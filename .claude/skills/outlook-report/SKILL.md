# 세계 전망 (outlook-report, skillVersion 1)

설계: `docs/design/세계전망_docvault_20261121.md`. 이 스킬의 목적은 **매번 같은 방식**이다 — 에이전트 지시문(`references/agents.md`), 노트 양식(`references/note-template.md`), 완성본 형식(`references/schema.md`), 기관 목록(`references/institutions.json`), 화면 틀(`server/assets/outlook-template.html`)을 고정한다. 지시문을 그때그때 고쳐 쓰지 않는다. 고칠 일이 생기면 이 파일들을 고치고 skillVersion을 올린다.

기계적인 일(원문 받기, 대조, 화면 만들기)은 저장소의 `npm run outlook:job -w server -- …`가 한다 — 나중에 서버가 완성본을 받을 때와 **같은 코드**다(`server/src/lib/outlook/`). 이 스킬이 하는 일은 **찾기·읽기·검증·묶기·쓰기**다.

## 원칙 (사용자 결정 2026-11-20~21 — 설계 "사용자 요구와 결정")

- **주제를 미리 정하지 않는다.** 기관이 스스로 앞세운 메시지를 기관이 쓴 순서대로 받아 적고, 묶고, 센다. 지시문에 특정 주제를 예로 들지 않는다.
- **어디를 볼지는 고정하고 링크는 매번 찾는다.** `institutions.json`의 발간 페이지(hubs)와 발간 달력을 먼저 보고, 그다음 주제 없는 열린 검색.
- **본문에 출처로서의 기관 이름을 쓰지 않는다.** 여러 곳이 같은 방향이면 단정, 갈리면 범위, 한 곳만 낸 숫자는 전망·추정으로. 출처는 각주 번호로만.
- **숫자는 원문 글에서 글자 그대로.** 웹 가져오기 도구(WebFetch)가 돌려주는 것은 요약이라 인용이 아니다 — 인용은 반드시 `outlook:job grab`으로 받은 원문 글에서 옮긴다. grab이 막힌 출처의 인용은 "원문 확인 못 함"으로 센다.
- **사이트를 우회하지 않는다.** 막히면 그 기관의 보도자료(근거 등급 "원문")나 그 글을 인용한 기사(근거 등급 "뉴스 경유")로 대신한다. 같은 기관이 다른 공개 주소에 올린 같은 글을 쓰는 것은 우회가 아니다(예: `institutions.json`의 McKinsey).
- **투자 권유가 아니다.** 화면 틀이 머리에 한 줄로 적는다. 매수·매도를 권하는 문장을 쓰지 않는다.

## 입력

사람이 부를 때(수동) 정한다. 빠진 것이 있으면 묻는다.

| 칸 | 작은 판 | 큰 판 |
|---|---|---|
| 판 이름 | "2026년 12월 첫째 판" | "2027년 세계 경제 전망" |
| 읽는 기간 | 직전 판의 `until` 다음 날 ~ 실행일 전날(날짜 단위 — 하루를 다 채운 날까지) | 전년 9월 1일 ~ 12월 31일 |
| 기준선 | 가장 최근 큰 판의 `out/report.json`과 그 `notes/` 폴더, 그리고 그 뒤에 나온 작은 판들의 작업 폴더(둘째 작은 판부터 — 숫자를 고친 것을 견줄 "가장 최근 값"이 거기 있다). 첫 큰 판 전에는 2026-11-20 시범의 `docs/data_ignored/전망보고서/v2/report/2027 세계 경제 전망 화이트페이퍼.md`와 `…/v2/notes/`(저장소 밖 개인 자료) | 없음 |
| 묶음 | 4개 — 기관마다 `group`을 `smallGroups`로 바꿔 묶고, 이름은 `smallGroupNames` | 6개 — `groups` |
| 묶음별 검색 할당 | 15회(첫 작은 판의 실측으로 고친다) | 25회(첫 큰 판 전에 고친다) |
| 시험인가 | 시험이면 `meta.test: true` — 화면에 "시험 운행" 표시 | |

판 id는 작은 판 `YYYY-MM-n`(예: `2026-12-1` — 그달 첫째 판), 큰 판 `YYYY-big`. 작업 폴더는 저장소 루트의 `.outlook-report/<판 id>`(gitignore — 커밋하지 않는다). **명령과 에이전트에게는 절대 경로로 준다**: `W="$PWD/.outlook-report/<판 id>"`(저장소 루트에서). 준비: `npm ci` 한 번, 그리고 PDF를 읽는 `pdftotext`(poppler-utils — 없으면 PDF 출처를 못 받는다).

낱말: **시범** = 2026-11-20 손으로 돌린 1회(기준선을 만든 것), **시험 운행** = 2026-11-21 이 스킬로 돌린 1회(판으로 치지 않는다 — 다음 판의 `since`에 영향이 없다), **첫 작은 판** = 2026년 12월 초에 돌릴 것.

```
W/
  sources/            grab이 받은 원문 글과 index.json
  notes/collect_<묶음>.md   verified_<묶음>.md
  synth/analysis.md
  out/report.json     리더가 쓰는 완성본
  data.json · verify-report.txt · report.txt · page.html · artifact.html   build가 만든다
```

## 단계와 모델

하위 에이전트는 **포그라운드로** 띄운다(파일을 읽고 쓰는 에이전트라서). 묶음별 에이전트는 한 번에 같이 띄운다. 모델은 Agent 도구의 `model`로 정한다 — **Haiku는 쓰지 않는다**(브리핑과 같은 사용자 결정). 지시문은 `references/agents.md`의 것을 `{…}` 자리만 채워 **그대로** 넘긴다(자리마다 넣을 값은 그 파일 머리의 표).

단계 번호는 설계 문서의 11단계를 따르지만, 실제로는 9(대조)를 8(검토)보다 먼저 돌린다 — 검토(독자)가 읽을 화면 글(`report.txt`)을 build가 만들기 때문이다. 검토를 반영한 뒤 9를 다시 돌린다.

| 단계 | 누가 | 모델 | 나오는 것 |
|---|---|---|---|
| 2~4. 찾기·고르기·읽기 | 묶음마다 F 한 명 | sonnet | `notes/collect_<묶음>.md` |
| 5. 검증 | 묶음마다 V 한 명(F와 다른 에이전트) | opus | `notes/verified_<묶음>.md` |
| 6. 분석 | A 한 명 | opus | `synth/analysis.md` |
| 7. 쓰기 | 리더(이 세션) | — | `out/report.json` |
| 9. 대조 | 코드 | — | `outlook:job fetch`, `outlook:job build` |
| 8. 검토 | R1 사실 대조·정합(opus) · R2 독자(sonnet) | | 지적 목록 |

### 2~4. 찾기·고르기·읽기 (F)

`references/agents.md`의 F 지시문(공통 규칙은 그 안의 `{COMMON_RULES}` 자리에 넣는다). 묶음마다 하나. `hubs`가 비어 있는 기관(시험 때 61곳 중 23곳)은 달력과 열린 검색으로 찾고, 발간 페이지 주소를 찾으면 노트의 추가 후보 칸에 적는다 — 사람이 목록에 넣는다. F는 원문을 `npm run outlook:job -w server -- grab $W <주소>`로 받아 그 파일을 읽고 노트를 쓴다(양식 `references/note-template.md`).

### 5. 검증 (V)

V 지시문(공통 규칙은 `{COMMON_RULES}` 자리에). F의 노트와 `W/sources/`의 원문 글을 맞춰 본다. 검증 기록의 합계(확인 · 맞음 · 고침 · 등급 낮춤 · 지움 · 미확인)를 노트 머리에 적게 한다 — 회고가 다시 세지 않아도 되게.

### 6. 분석 (A)

A 지시문(작은 판 / 큰 판, 공통 규칙은 `{COMMON_RULES}` 자리에). 검증본 전부와 기준선을 읽고 `synth/analysis.md`를 쓴다: 꼭지 후보와 무게(몇 곳 · 몇 부류 · 첫 메시지로 둔 곳), 숫자를 고친 기관 표(작은 판), 갈리는 곳, 편향 점검.

### 7. 쓰기 (리더)

`synth/analysis.md`의 순서로 `out/report.json`을 쓴다(형식 `references/schema.md`). 문체 규칙은 `references/agents.md`의 "쓰기 규칙". 숫자마다 `facts`를 붙이고, `facts`의 인용은 검증본에 적힌 인용(= grab한 원문 글에 있는 글)을 그대로 옮긴다.

### 9. 대조 (코드) → 8. 검토

```
npm run outlook:job -w server -- fetch $W     # 주 목록 가운데 아직 안 받은 원문을 받는다
npm run outlook:job -w server -- build $W     # 대조 → data.json · verify-report.txt · report.txt · page.html · artifact.html
```

- "고쳐야 받습니다"가 나오면 고쳐서 다시 돌린다. 근거가 틀렸으면 근거를 고치고, **근거를 댈 수 없는 숫자는 글에서 뺀다** — 대조를 통과시키려고 근거를 꾸미지 않는다.
- "뺀 것"이 0이 될 때까지 고친다. 고쳐서 다시 돌리는 것은 두 번까지 — 그래도 남으면 빠진 채로 두고 보고에 적는다.
- "원문 확인 못 함"은 그 출처를 서버도 못 받을 수 있다는 뜻이다. 비율을 보고에 적는다.
- 그다음 **검토**: R1(사실 대조·정합 — report.json과 검증본, 기준선)과 R2(독자 — `report.txt`만)를 한 번에 띄운다. 지적마다 근거를 직접 확인하고 **한 번** 반영한 뒤 build를 다시 돌린다. 고친 양이 절 하나 이상이면 R1을 고친 절만 대상으로 한 번 더 띄우고, 그 이상 되풀이하지 않는다.

### 10. 내놓기

- **수동**: `artifact.html`을 Artifact로 게시한다(아이콘 "chart"). 화면 틀은 고치지 않는다.
- **자동**: 아직 없다(세계전망 설계 2·3단계).
- 보고: 대조 결과(`n/n`, 원문 확인 못 함 비율), 에이전트 수와 모델, 검증 합계, 검토에서 반영한 것, 근거를 대지 못해 뺀 것, 링크.

## 알려진 함정 (2026-11-20 시범에서)

- **검색 한도는 한 실행에 함께 쓴다.** 시범에서 앞 묶음들이 200회를 다 써 뒤 묶음은 0회였다. F 지시문에 할당을 적고, F는 할당을 넘기지 않는다.
- 금융회사 연간 전망의 상당수가 **자산관리 고객용 안내서**다(결론이 "투자 유지"로 기운다). 연구 부서 전망과 구분해 노트에 적는다.
- **발표 시점이 출처 유형과 겹친다**(공공 9~10월, 금융 11월). 기간 안에서 먼저 나온 것과 나중 것의 차이를 시각 차이로 단정하지 않는다.
- 자동 접속을 막는 곳이 있다(시범 회고 `docs/data_ignored/전망보고서/v2/report/시범 회고.md`의 3절 "사이트별 접근 결과" — 저장소 밖). `institutions.json`의 `access` 칸에 옮겨 두었다.
- 같은 기관 안의 다른 조직(예: UBS 자산관리와 투자은행, BofA의 Merrill)은 숫자가 다를 수 있다. 노트에 어느 조직인지 적는다.

## 알려진 함정 (2026-11-21 시험 운행에서)

- **WebFetch는 요약을 돌려준다.** 그것을 인용으로 옮기면 build의 원문 대조에서 떨어진다. 인용은 grab한 글에서.
- **grab의 작업 폴더는 절대 경로로.** `npm … -w server`는 `server/` 안에서 돌아, 상대 경로를 주면 `server/` 아래에 엉뚱한 폴더가 생긴다(시험에서 한 번 생겼다).
- **분석(A)이 파일을 못 쓸 수 있다.** 환경에 따라 하위 에이전트의 보고서 파일 쓰기가 막힌다. 그러면 A가 답으로 돌려준 전문을 리더가 `synth/analysis.md`에 저장한다.
- **찾기(F)가 주제로 거르는 버릇.** 시험에서 F가 방위·위성·창업 보고서를 "거시 전망이 아니라서" 뺐다. F 지시문의 고르기 규칙에 금지를 적었다.
- **검증에서 고치는 비율이 높았다.** 시험에서 195건 중 67건(34%)을 고쳤다(시범 18%). 대부분은 메시지 순서·빠진 요점·숫자의 기준·원문과 해석의 구분이었고, 인용이 잘리거나 값을 잘못 옮긴 곳도 몇 군데 있었다(지운 10건에는 기간 밖 숫자·근거 없는 숫자가 들어 있다). 검증(V)을 빼지 않는다.
- **풀이 속 숫자도 대조된다.** "bp(0.01%p)"처럼 낱말을 풀며 쓴 숫자는 근거가 없어 문단이 빠진다. "100분의 1%포인트"처럼 쓴다.
