# 에이전트 지시문 (outlook-report)

리더는 아래 글을 `{…}` 자리만 채워 **그대로** 넘긴다. 공통 규칙은 F·V·A 지시문 안의 `{COMMON_RULES}` 자리에 넣는다(앞에 따로 붙이지 않는다).

| 자리 | 넣을 값 |
|---|---|
| `{TODAY}` | 실행일 `YYYY-MM-DD` |
| `{SINCE}` · `{UNTIL}` | 읽는 기간(SKILL.md "입력") |
| `{W}` | 작업 폴더 절대 경로 |
| `{REPO}` | 저장소 루트 절대 경로 |
| `{판 종류}` | "작은 판" 또는 "큰 판"(시험이면 뒤에 "(시험 운행)") |
| `{판 이름}` | 판 이름(예: "2026년 12월 첫째 판") |
| `{GROUP_ID}` · `{GROUP_NAME}` | 묶음 id와 이름 — 작은 판은 `smallGroups`의 값과 `smallGroupNames`, 큰 판은 `groups` |
| `{INSTITUTIONS_JSON}` | 그 묶음 기관들의 `name`·`hubs`·`calendar`·`access`·`lang`(JSON 배열) |
| `{QUOTA}` | 묶음별 검색 할당 |
| `{SELECT_RULE}` · `{ANALYSIS_TASK}` · `{BASELINE_LINE}` | 아래에 적힌 판별 글 |
| `{BASELINE_MD}` · `{BASELINE_NOTES}` | 기준선 파일과 그 노트 폴더(SKILL.md "입력") |
| `{LATER_EDITIONS}` | 기준선 뒤에 나온 작은 판들의 작업 폴더(`out/report.json`·`notes/`) 목록, 없으면 "없음" |
| `{COMMON_RULES}` | 아래 "공통 규칙"을 채운 글 |

## 공통 규칙

```
공통 규칙:
- 오늘은 {TODAY}. 대상은 {SINCE}부터 {UNTIL}까지 발표된 글이다. 이 기간 밖 글은 "기간 밖"으로만 적고 쓰지 않는다. 아직 안 나온 정기 발간물은 "예정"으로 적는다. 발표일은 원문에서 확인한다.
- 특정 주제를 찾지 않는다. 각 기관이 스스로 앞세운 메시지를 그 기관의 순서와 표현대로 옮긴다. 조사자가 중요하다고 생각하는 주제로 고르거나 다시 묶지 않는다.
- 원문은 반드시 이 명령으로 받아 그 파일을 읽는다: npm run outlook:job -w server -- grab {W} <주소>  (저장소 루트 {REPO}에서. 받은 파일 경로가 찍힌다)
  {W}는 적힌 절대 경로 그대로 쓴다 — 이 명령은 server/ 안에서 돌아서, 상대 경로를 주면 server/ 아래에 엉뚱한 폴더가 생긴다.
  웹 가져오기 도구(WebFetch)는 페이지를 요약해 돌려주므로 인용의 근거가 될 수 없다 — 목록 페이지를 훑을 때만 쓴다.
- 인용은 받은 원문 파일에서 글자 그대로 옮긴다(500자 안, 숫자가 든 문장). 번역하지 않는다.
- 근거 등급은 이 세 단어만: 원문(기관 원문을 grab으로 받아 확인) / 뉴스 경유(원문을 못 받고 그것을 인용한 기사를 grab으로 받아 확인) / 미확인(검색 결과 요약·집계 사이트에만 있음 — 글에 쓰지 않는다).
- 사이트가 막으면 우회하지 않는다(브라우저 흉내·다른 사용자 에이전트 금지). 같은 기관의 보도자료·요약 페이지(등급 원문), 그다음 신뢰할 만한 언론 보도(등급 뉴스 경유)를 쓴다. 같은 기관이 다른 공개 주소에 올린 같은 글은 우회가 아니다.
- 기억으로 숫자나 사실을 채우지 않는다. 읽지 못한 것은 읽지 못했다고 적는다.
- 원문에 있는 말과 조사자의 해석을 섞지 않는다. 해석은 줄 앞에 "해석:"을 붙인다.
- 숫자에는 기준을 붙인다: 연도 대비/4분기 대비, 연말/연평균, 1인당/전체, PPP/시장환율, 근원/전체, 자체 전망/컨센서스. 같은 기관 안의 다른 조직(자산관리 부문, 연구 부서)이면 어느 조직인지 적는다.
- 노트는 한국어로 쓴다.
```

## F — 찾기·고르기·읽기 (묶음마다, sonnet)

```
{판 종류} 세계 전망 — 묶음 "{GROUP_NAME}".

대상 기관(이름 · 발간 페이지 · 발간 달력 · 접근 메모): {INSTITUTIONS_JSON}
검색 할당: 웹 검색 {QUOTA}회까지. 넘기지 않는다. 남은 횟수를 노트 검색 기록에 적는다.

순서:
1. 기관마다 발간 페이지(hubs)를 먼저 연다(WebFetch로 훑어도 된다). 기간 안에 새로 올라온 글을 모은다.
2. 발간 달력에서 이번 기간에 나올 때가 된 자료를 찾는다. 안 보이면 "아직 안 나옴" 또는 "못 찾음".
3. 남은 할당으로 주제를 정하지 않은 열린 검색을 한다(영어와 그 기관들의 언어). 목록 밖 기관의 글이 걸리면 "추가 후보"에만 적는다.
4. 고른다. {SELECT_RULE}
5. 고른 글을 grab으로 받아 읽고 노트를 쓴다.

{COMMON_RULES}
노트 양식: {REPO}/.claude/skills/outlook-report/references/note-template.md
저장: {W}/notes/collect_{GROUP_ID}.md
마지막에 돌려줄 것: 노트 경로, 기관별 상태 한 줄씩, 쓴 검색 수, 추가 후보.
```

`{SELECT_RULE}`:
- 작은 판: `읽을 기간에 나온 글 가운데 담을 가치가 있는 것만 — 전망 숫자(성장률·물가·금리·유가·환율·주가 지수 등)를 새로 냈거나 고친 글, 새로 나온 주제별 화이트페이퍼·보고서, 다수와 다른 시각을 낸 글. 지난 판과 같은 말을 되풀이하는 주간 시황은 뺀다. 한 기관에서 여럿이어도 된다(3개까지). "거시 전망이 아니라서", "우리 주제가 아니라서"처럼 주제로 빼지 않는다 — 방위·위성·창업처럼 거시와 멀어 보이는 주제 보고서도 새로 나온 것이면 담는다.`
- 큰 판: `기관마다 대표 보고서 하나. 범위가 넓은 것이 먼저다 — 경제·시장 전체 > 여러 산업 > 한 주제. 같은 급이면 ① 세계 > 지역 > 한 나라 ② 그해 전체 전망 > 분기 갱신 ③ 더 최근. 고른 이유를 적는다.`

## V — 검증 (묶음마다, opus — F와 다른 에이전트)

```
세계 전망 수집 노트 검증 — 묶음 "{GROUP_NAME}".

읽을 것: {W}/notes/collect_{GROUP_ID}.md (다른 에이전트가 쓴 노트. 당신은 그 과정을 모른다)
원문 글: {W}/sources/ (index.json에 주소 → 파일). 노트가 가리킨 원문이 없으면 grab으로 받는다.
{COMMON_RULES}
할 일:
1. 노트의 글마다 원문 글을 열어 발표일이 기간 안인지, 메시지가 원문의 순서·표현과 같은지, 숫자와 기준이 맞는지 하나씩 확인한다. 인용은 원문 파일에 글자 그대로 있어야 한다(띄어쓰기만 무시) — 없으면 원문에서 맞는 문장으로 바꾸거나 지운다.
2. 등급이 실제보다 높게 적힌 것은 낮추고, 틀린 숫자는 고치고, 근거를 찾을 수 없는 것은 지운다.
3. 고르기 규칙이 지켜졌는지, 기간 밖 글이 섞였는지, 원문과 해석이 섞였는지 본다.
4. 검증본을 {W}/notes/verified_{GROUP_ID}.md 에 쓴다: 맨 위에 "결과 요약: 확인 n · 맞음 n · 고침 n · 등급 낮춤 n · 지움 n · 미확인으로 남김 n" 한 줄, 그 아래 "검증 기록" 표(| 항목 | 노트의 값 | 확인 결과 | 조치 |), 그 아래 고친 노트 전체.
돌려줄 것: 검증본 경로, 결과 요약 한 줄, 규칙 위반 목록.
```

## A — 분석 (opus)

```
세계 전망 분석 — {판 이름}.

읽을 것: {W}/notes/verified_*.md 전부{BASELINE_LINE}
{COMMON_RULES}
{ANALYSIS_TASK}
저장: {W}/synth/analysis.md (한국어)
돌려줄 것: 꼭지 순서와 무게 한 줄씩, 편향 점검 요약 세 줄.
```

`{BASELINE_LINE}`(작은 판만): `, 기준선 {BASELINE_MD}와 그 근거 노트 {BASELINE_NOTES}/verified_*.md, 그 뒤 작은 판들 {LATER_EDITIONS}`

`{ANALYSIS_TASK}`:
- 작은 판:
  ```
  1. 숫자를 고친 것: 같은 기관·같은 지표·같은 기준의 이전 값을 기준선(과 그 뒤 판들)의 근거 노트에서 찾아 표로 — | 기관 | 지표(기준) | 이전 값(출처) | 새 값(출처) | 방향 |. 기준이 다르면 고친 것으로 보지 않고 따로 적는다.
  2. 새로 떠오른 것: 기준선에 없던 메시지가 이번 노트에서 몇 곳에서 나왔나. 메시지를 아래에서 위로 묶고, 묶음마다 몇 곳 · 몇 부류에서 · 첫 메시지로 둔 곳이 몇인지 센다.
  3. 주제별 화이트페이퍼에서 보이는 산업 흐름(새 보고서마다 핵심 주장 · 근거 숫자).
  4. 갈리는 곳: 같은 지표·같은 기준에서 기관끼리 정면으로 갈리는 숫자와 시각.
  5. 꼭지 순서 제안: 무게 순. 기준선에 없던 주제가 여러 곳에서 나왔으면 그것이 첫 꼭지다. 한 곳만 말한 것은 "한 곳만"으로 표시.
  6. 편향 점검: 지역 · 부류 · 발표 시점 · 접근(원문/뉴스 경유/못 받음) 치우침을 센다.
  ```
- 큰 판:
  ```
  1. 주제 지도: 기관마다 앞세운 메시지를 아래에서 위로 묶는다. 묶음마다 몇 곳이 말했나 · 몇 부류에서 나왔나 · 첫 메시지로 둔 곳이 몇인가. 무게 순으로 놓고, 판단으로 순서를 바꾼 곳은 이유를 적는다.
  2. 주제마다 기관(부류·지역), 대표 인용, 숫자(기준이 같은 것끼리만 표로), 정면으로 갈리는 지점.
  3. 다수가 말하지 않은 것, 한두 곳만 말한 것.
  4. 편향 점검: 지역 · 부류 · 발표 시점 · 접근 치우침, 정식 전망과 대용 자료(예고편·요약·보도)의 비율.
  ```

## 쓰기 규칙 (리더)

- 결론이 앞에 오고 문장이 이어지는 사람 분석가의 글. 문단 길이를 고르게 맞추지 않는다.
- 본문에 출처로서의 기관 이름을 쓰지 않는다. 그 기관 자체가 대상일 때(연준의 금리 결정, 일본은행 정책금리)만 쓴다.
- 여러 곳이 같은 방향이면 단정한다. 갈리면 "76–100달러로 갈린다[4][5]"처럼 범위와 각주. 한 곳만 낸 숫자는 "…로 추정된다[n]", 한 곳만 그린 시나리오는 "한 전망은 …를 제시한다[n]".
- 주장의 세기는 근거를 넘지 않는다. 몇 곳이 말했는지는 "대다수 전망", "적지 않은 전망"으로 옮기고, 센 값은 꼭 필요한 곳에만. 그 진단을 **직접** 내놓은 곳만 센다 — 이웃한 주제를 다룬 곳까지 "여러 곳이 같은 말을 했다"로 묶지 않는다.
- (작은 판) 기준선과 그 뒤 작은 판들에 이미 있는 숫자·글을 "달라진 것"으로 쓰지 않는다. 쓰기 전에 그 판들에서 그 숫자를 찾아본다.
- 같은 전망 안의 숫자를 골라 쓰지 않는다 — 2026년 말 5.00%를 쓰면 같은 문장의 2027년 말 4.75%도 쓴다. 원문의 단서("at least in part", "효과는 작다")와 글의 성격(저자 견해 블로그 등)은 함께 옮긴다.
- 측정 방법이 다른 두 값을 "한 걸음 더 나간다"처럼 강도 차이로 잇지 않는다. 방법이 다르다고 적는다.
- 사실 사이에 원문에 없는 인과("중동 위기로 …")를 끼워 넣지 않는다.
- 처음 나오는 전문용어는 그 자리에서 풀어 준다.
- 쓰지 않는 버릇: 셋씩 나열, 대칭 구조, 모든 절에 같은 틀, 굵은 글씨 남발, "핵심은 ~다", "~라는 점이다", "주목할 만하다", "눈여겨볼", 수사 의문문.
- 물결표와 달러 기호를 쓰지 않는다(금액은 "달러", 범위는 "–"). build가 막는다.
- 작은 판 구성: 요약(두세 문단) · 달라진 것 · 새로 떠오른 것 · 다음에 볼 것 · 맺음 한 줄(편향 점검). 절 제목은 자연스러운 소제목. 큰 판 구성: 요약 · 분석(6단계)에서 정한 주제 순서의 절 · 앞으로 볼 지표 · 이 보고서에 대하여.
- 도표(`chart`)는 같은 기준의 숫자만. 기준이 섞이면 표(`table`)로.

## R — 검토 (한 번에 띄운다)

### R1 사실 대조 (opus)

```
세계 전망 완성본의 사실 대조. 고치지 말고 찾기만 한다.
읽을 것: {W}/out/report.json(완성본 — 형식은 {REPO}/.claude/skills/outlook-report/references/schema.md), {W}/notes/verified_*.md(근거 노트), {W}/synth/analysis.md{BASELINE_LINE}
찾을 것: 본문 문장이 근거 노트와 다른 곳(숫자·기준·방향·기간), 한 곳만 낸 숫자를 합의처럼 단정한 곳, 주장의 세기가 근거를 넘는 곳, 기준이 다른 숫자를 맞댄 곳, 근거 노트에 없는 사실, 출처로서의 기관 이름이 본문에 남은 곳. 정합도 본다: 문서 안에서 앞뒤가 다른 곳, (작은 판) 기준선에 이미 있는 숫자를 "달라진 것"으로 쓴 곳, 기준선과 같은 사실을 다르게 말한 곳.
지적마다 ① report.json의 위치(절 id · 블록 번호) ② 무엇이 틀렸나 ③ 근거(노트 파일:줄) ④ 확신(확인함/추정). 없으면 무엇을 대조했는지 적고 "없음".
```

### R2 독자 (sonnet)

```
아래 글을 처음 읽는 사람(경제·투자에 관심 있는 비전문가)의 눈으로 읽는다. 고치지 말고 찾기만 한다.
읽을 것: {W}/report.txt (화면에 보이는 글만)
찾을 것: 설명 없이 처음 나오는 용어, 앞뒤가 다른 숫자, 두 가지로 읽히는 문장, 결론이 흐린 절, 같은 이야기의 반복, 기계적으로 읽히는 문장(셋씩 나열·대칭 구조·같은 틀 반복).
지적마다 ① 위치(절 제목 + 첫 몇 글자) ② 무엇이 문제인가 ③ 어떻게 읽혔나. 마지막에 "다른 사람에게 보여 줄 만한가"를 한 줄로.
```
