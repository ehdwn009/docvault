# 수출입 동향 정리본 (trade-report, skillVersion 3)

설계: `docs/design/수출입동향_docvault_20261120.md`("4단계 — 정리본"). 이 스킬의 목적은 **매번 같은 방식**이다 — 에이전트 지시문(`references/agents.md`)과 결과 형식(`references/schema.md`)과 화면 틀(`server/assets/trade-template.html`)을 고정해, 달이 바뀌어도 깊이와 모양이 흔들리지 않게 한다. 지시문을 그때그때 고쳐 쓰지 않는다. 고칠 일이 생기면 이 파일들을 고치고 skillVersion을 올린다.

기계적인 일(PDF 받기, 쪽 텍스트, 원문 대조, 서버와 주고받기)은 저장소의 `npm run trade:fetch`·`npm run trade:job`이 서버와 **같은 코드**로 한다. 이 스킬이 하는 일은 **읽기·잇기·쓰기·읽혀 보기**다.

## 원칙 (사용자 결정 2026-11-20)

- **읽는 사람은 원문 없이 이 정리본만 읽는다.** 그 달에 무슨 일이 있었는지, 왜 그랬는지, 다음에 무엇을 볼지를 이것 하나로 알 수 있어야 한다. 데이터 분석가이자 시장의 흐름을 읽으려는 사람의 마음가짐으로 쓴다.
- **정리된 정보를 준다.** 어느 쪽에 무엇이 있는지, 보도자료의 낱말이 지난달과 어떻게 달라졌는지는 쓰지 않는다. 지난달과 달라진 것은 숫자와 흐름으로, 그 주제의 본문 안에서 말한다.
- **화면에는 근거를 보이지 않고, 대조는 뒤에서 그대로 한다.** 쪽 번호·원문 인용·계산식은 화면에 없다. 하지만 글에 나온 숫자마다 근거(`facts`)를 붙이고, `trade:job build`와 서버가 같은 함수로 대조한다 — 인용은 그 쪽에 글자 그대로, 계산식은 다시 계산, 품목·지역 표와 그래프는 대조를 통과한 표 줄에서 서버가 만든다.
- **해설 문장을 다 읽고, 떨어진 쪽을 잇는다.** 요약 쪽만 보고 쓰지 않는다. 품목·지역 해설, 각주, 표, 장관 평가까지 읽고, 따로 적힌 것을 함께 봐야 보이는 것(유가 → 석유제품 단가 → 에너지 수입 → 중동 적자)을 찾는다.
- **장황하지 않게, 단정은 근거만큼만.** 표와 그래프는 좋다. 폰 화면으로 10장 안팎.
- **쓰고 나서 아무것도 모르는 독자 세 명에게 읽힌다.** 피드백을 한 번 반영한다.

## 두 모드

| | 자동 (서버가 예약 작업을 켬) | 수동 (사람이 부름) |
|---|---|---|
| 시작 | briefing-subscription 스킬이 받은 지시서의 `kind`가 `"trade"`일 때 이 스킬로 넘어온다. job id는 그 지시서의 `jobId`(= `<routine-fire-payload>`의 `BRIEFING_JOB_ID=` 줄) | "이번 달 수출입 동향 정리해 줘", "2026-09 호로" |
| 원문 | `npm run trade:job -w server -- pull <jobId> $W` — 서버가 쪽별 텍스트를 준다(이번 호·전월 호). 산업통상부 사이트에 접속하지 않는다 | `npm run trade:fetch -w server -- <YYYY-MM\|latest> $W` 뒤 `npm run trade:job -w server -- pages $W` (pdftotext 필요) |
| 내놓기 | `npm run trade:job -w server -- send <jobId> $W` → 서버가 다시 대조해 저장하고 알린다 | build가 만든 `page.html`을 페이지로 게시해 링크를 준다 |
| 서버 주소·열쇠 | `DOCVAULT_URL`은 환경 변수, 연결 열쇠는 네트워크 시크릿이 붙인다(briefing-subscription과 같은 규칙 — 값은 어떤 파일·출력에도 적지 않는다). 401이면 우회하지 말고 멈추고 보고 | 쓰지 않는다 |

**자동 모드에서 멈추는 경우**: `pull`·`send`가 409(`TRADE_JOB_CLOSED` — 마감이 지났거나 이미 저장됨)·404를 주면 거기서 멈추고 보고한다. 지시서의 `deadline`(unix ms) **30분 전**이 되면 독자 검수(D)를 건너뛰고 바로 보낸다 — 빈손보다 대조를 통과한 결과가 낫다.

예약 시각을 따로 두지 않는 이유: 보도는 1일 11:00이지만 게시판에 오르는 시각을 모른다. 서버가 1일 11:10·13:00·18:00, 2~10일 10:00에 확인하다 **찾는 순간** 이 스킬을 켜고, 못 찾으면 서버가 관리자에게 알린다.

## 단계

작업 폴더는 저장소 루트의 `.trade-report/<YYYY-MM>`(gitignore — 커밋하지 않는다). **명령과 에이전트에게는 절대 경로로 준다**: `W="$PWD/.trade-report/<YYYY-MM>"`(저장소 루트에서). `npm … -w server`는 `server/` 안에서 돌기 때문에 상대 경로를 주면 `server/.trade-report/…`에 생겨 에이전트가 찾지 못한다. 준비: `npm ci -w server` 한 번.

### 1. 원문 받기 (코드)

```
# 자동
npm run trade:job -w server -- pull <jobId> "$PWD/.trade-report/<지시서의 period>"
# 수동 — 받은 뒤 출력의 cur.period로 폴더 이름을 정한다
npm run trade:fetch -w server -- latest "$PWD/.trade-report/tmp"      # 또는 2026-09
npm run trade:job -w server -- pages "$PWD/.trade-report/<YYYY-MM>"
```
→ `pages/cur/01.txt…`·`all.txt`, `pages/prev/…`(전월 호가 없으면 "전월 호 없음" — 지난달과의 비교는 이번 호 표에 실린 값으로만 쓴다). 쪽 번호는 PDF 쪽(1부터)이고 하단 인쇄 쪽번호와 같다(실측).

### 2. 조사 (에이전트 A·B·C 동시)

`references/agents.md`의 조사 공통 머리 + A / B / C 지시문을 `{WORK}`만 바꿔 **그대로** 세 에이전트에게 한 번에 넘긴다. 결과: `out/a.json`·`out/b.json`·`out/c.json`(발견 목록 — 사실·해석 + 근거), `out/tables.json`(숫자 표 줄).

### 3. 쓰기 (리더 = 이 세션)

`references/agents.md`의 "쓰기" 규칙대로 `out/report.json`을 쓴다(형식 `references/schema.md`, 완성 예 `assets/example-data.json`).

1. 세 발견 목록을 주제별로 모아 읽는다. `weight: 핵심`부터, 그리고 서로 다른 에이전트가 따로 찾은 것 중 **함께 봐야 뜻이 생기는 것**을 고른다.
2. 숫자 칸 4개(수출 · 수입 · 무역수지 · 하루 평균 수출)와 결론 3줄을 먼저 쓴다. 결론은 "얼마나 컸나 / 무엇이 끌었나 / 숫자를 어떻게 읽어야 하나"가 기본 뼈대다.
3. 절을 쓴다. 문단·항목마다 쓴 숫자의 근거 id를 `facts`에 넣고, 근거 본문은 에이전트의 `facts`에서 옮긴다. 근거 id는 정리본 전체에서 하나뿐이어야 한다 — 에이전트의 발견마다 `f1`·`f2`로 새로 시작하므로, 뜻이 드러나는 고유한 이름(`exp`, `semiShare` …)으로 바꾸고 `uses`도 함께 고친다. 직접 계산한 값은 `calc`로 넣는다(서버가 다시 계산한다).
4. 품목 표·지역 표의 한마디(`notes`)는 B(품목)와 C(지역)가 `notes`에 적어 준 후보에서 고른다. 표의 숫자는 적지 않는다(서버가 표 줄에서 만든다).

### 4. 대조 (코드) → 독자 검수

```
npm run trade:job -w server -- build $W
```
→ `data.json`, `verify-report.txt`, `report.txt`(화면에 보이는 글만 — 독자가 읽을 것), `page.html`(완성 화면).

- "고쳐야 받습니다"(숫자 칸·결론·절 제목의 숫자에 근거가 없음, 숫자 표가 출처 줄과 다름, 남은 절이 3개 미만, 빠진 것이 30% 초과)가 나오면 고쳐서 다시 돌린다. 근거가 틀렸으면 근거를 고치고, **근거를 댈 수 없는 숫자는 글에서 뺀다** — 대조를 통과시키려고 근거를 꾸미지 않는다.
- "뺀 것"이 있으면 그 문단이 화면에서 빠진 것이다. 0개가 될 때까지 고친다. 고쳐서 다시 돌리는 것은 위의 "고쳐야 받습니다"까지 합쳐 두 번까지 — 그래도 남으면 그 문단은 빠진 채로 보내고 보고에 적는다.
- 그다음 **독자 검수**: `references/agents.md`의 D 공통 머리 + D1 / D2 / D3을 그대로, `report.txt`만 주고 한 번에 띄운다. 피드백을 "쓰기" 규칙에 비춰 **한 번** 반영하고 build를 다시 돌린다.

### 5. 내놓기

- **자동**: `npm run trade:job -w server -- send <jobId> $W`. 200 `{ fileId, checked, passed, dropped, already }`면 끝. 422 `TRADE_JOB_REJECTED`(서버 대조에서 거절 — `fatal`에 이유)면 고쳐서 build부터 다시, **합쳐 2번까지**(지시서 `limits.resendMax`). 400은 형식(메시지가 `<경로>: <이유>`), 413은 2MB 초과.
- **수동**: `page.html`을 Artifact로 게시한다. 화면 틀은 고치지 않는다.
- 보고: 대조 결과(`n/n`), 결론 3줄, 독자 세 명의 점수와 반영한 것, 근거를 대지 못해 뺀 내용이 있으면 그것. 수동이면 링크도.

## 알려진 함정 (실측)

- 제목 띄어쓰기가 흔들린다(2026년 8월호 「수출입동향」). 같은 달 「정보통신산업(ICT) 수출입 동향」이 따로 있다 — 판정은 서버·`trade:fetch`가 한다.
- 1월 1일 호는 「연간 및 12월」(48쪽 안팎)이라 표 모양이 다르다. 숫자 표는 찾은 줄만, 못 찾은 것은 보고(그 품목·지역은 표에서 빠진다).
- 지역별 품목 숫자는 그달 1~25일 기준(16쪽 안내문) — 월 전체와 나란히 놓지 않는다.
- 품목 표의 '역대순위'는 **같은 달끼리** 순위다(2026년 10월 반도체: 표 1위, 전 기간 2위).
- 지난달 숫자는 이번 호에서 정정된다(9월→10월호 겹치는 396칸 중 약 100칸). 전월 값은 **이번 호 표의 정정값**을 쓴다.
- 최근 1년은 분기 마지막 달에 수출이 몰리고 다음 달에 줄어드는 일이 반복됐다(2025년 12월→2026년 1월, 3→4월, 6→7월, 9→10월). 한 달 전보다 줄었다고 바로 "꺾였다"고 쓰지 않는다.
- 무게(톤) 기준 물량 통계에는 반도체가 거의 잡히지 않는다 — 전체 물량이 줄었다고 "덜 팔았다"고 쓰지 않는다.
- 그래프는 이미지라 텍스트로 안 나온다(27쪽 등) — 같은 숫자가 있는 표를 인용한다.
- 표의 줄을 인용할 때 pdftotext가 품목 이름과 숫자를 다른 줄로 가르는 일이 있다 — 숫자 줄을 인용한다.
