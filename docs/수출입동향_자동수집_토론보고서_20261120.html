매달 1일, 수출입 동향이 알아서 들어오게

사용자 질문: "산업통상부 사이트에서 매번 수출입동향을 자동으로 가져오고, 가져온 자료를 어떻게 정리해서 보여주면 좋을지 에이전트들과 의논해 와라." 수집·데이터·화면 담당 세 명이 1라운드 안을 내고, 비판 담당이 2라운드에서 검토해 합의안을 만들었습니다. 수치는 모두 오늘 컨테이너에서 사이트에 직접 접속해 받은 파일로 확인한 값입니다.

결론: 가져오기는 쉽고, 어려운 건 숫자다. 숫자는 코드가, 글은 AI가 쓴다 (4/4)
  • 자동으로 가져오는 건 확실히 됩니다. 로그인 없이 목록, 상세, 첨부 PDF가 모두 받아집니다. 2015년 12월부터 2026년 10월까지 131개월이 빈틈 없이 같은 게시판에 있고, 제목 판정 규칙으로 131건을 모두 정확히 골라냈습니다.
  • RSS가 아니라 목록 검색으로 확인합니다. RSS는 10건, 약 3일치뿐이라 1일 글이 금방 밀려납니다. 「수출입 동향」으로 검색하면 띄어쓰기 없이 올라온 8월호 「수출입동향」이 빠지므로, "수출입"으로 넓게 검색한 뒤 서버가 걸러냅니다.
  • 숫자는 PDF 뒤쪽 붙임 표에서 코드로 뽑습니다. 기존 수출입 대시보드 스킬의 파서로 최근 월간호 11개를 돌려 보니, 11개 모두에서 13개월치 수출·수입·수지와 품목·지역 추이가 빠짐없이 나왔고 수지 검산(수출 − 수입)도 다 맞았습니다. 연간호(1월 1일자)만 형식이 달라 깨집니다.
  • AI에게 숫자를 만들게 하지 않습니다. 서버 검산은 합계가 안 맞는 건 잡지만, 품목 줄을 바꿔 적거나 달을 한 칸 밀어 적은 실수는 못 잡습니다. AI는 "왜 늘었나" 같은 해설만 쓰고, 그 해설에 원문에 없는 숫자가 있으면 지웁니다. 지금 브리핑에 있는 verify.ts를 그대로 씁니다.
  • Loft에서는 세 겹으로 봅니다. 홈 카드는 입구, 월 화면은 시간 축(13개월 추이·품목·지역·지난달과 달라진 것), 원문 PDF는 근거입니다. 1단계는 알림 + 원문 PDF 폴더만으로 작게 시작합니다.
  • 하지 않습니다. RSS에만 기대기, 구형 HWP 변환(1건 138초 + AGPL 라이선스), 1997~2015년 소급(대부분 HWP이고 2016년에 일괄 이관됨), Claude 예약 작업(구독)으로 매달 대시보드 만들기(1단계부터 예약 작업이 필요해지고 다크모드도 안 맞음), 표 3개짜리 데이터 창고(한 달 1건에는 과잉).

정해 주실 것은 맨 아래 5가지입니다. 가장 중요한 건 1번 "숫자를 어디까지 볼지"이고, 추천은 2단계(홈 카드 + 간단한 월 화면)까지입니다.

1단계 · 도착과 보관

  • 기존 1분 스케줄러에 점검 단계 추가
  • 목록 파싱 + 제목 판정 + PDF 받기(전용 크기 상수, 6월호가 2.44MB라 브리핑의 2MB 상한을 넘음)

2단계 · 숫자 한 장

작업량 중간 · 추천 목표 지점

얻는 것: 홈 카드(수출·수입·수지·증감률, 13개월 막대, 1위 품목)와 월 화면(‹ › 이동, 품목·지역 표, 고쳐진 숫자), 용어 풀이 ⓘ. 알림에 숫자 한 줄이 붙습니다.

  • 검산: 수지 항등식, 품목 합 < 총액, 1쪽 헤드라인 ±0.5, 전 호 대비 1% 넘는 정정 목록

  • 검산이 실패하면 "숫자 확인 필요" 표시를 달고 원문은 그대로 게시

3단계 · 해설과 질문

작업량 중간 · 회당 API 1회

얻는 것: 「지난달과 달라진 것」(증감 방향이 뒤집힌 품목), "왜?" 한두 줄(추석 이동, 기저효과), 그 달 자료로 AI에게 묻기.

  • 방향 전환 탐지는 코드로. 예: 자동차 ▼5.5% → ▲18.1%, 선박 ▲29.9% → ▼43.6%

  • 일평균 수출: 수출액을 일한 날 수로 나눈 값입니다. 올해는 추석이 9월로 옮겨 가 10월에 일한 날이 22일(작년 20일)이었습니다. 그래서 총액 증가율 93.7%보다 일평균 증가율 76%가 실제 체력에 가깝습니다.
  • 기저효과: 비교 대상인 작년 같은 달이 유난히 커서 올해 증감률이 작아 보이는 현상입니다. 선박 ▼43.6%는 작년 10월 해양플랜트 한 건(24.7억 달러) 때문입니다.
  • △ 표기: 원문에서 감소를 뜻합니다. 앱에서는 ▼와 "감소"로 바꿔 보여 줍니다.

위험과 운영

위험대응
사이트 개편·게시판 ID 변경부처명이 이미 한 번 바뀜(motie → motir). 주소는 constants.ts 한 곳에 둡니다. 목록이 200인데 글이 0개이거나 404면 "게시판 모양이 바뀜" 알림. 파서가 깨져도 1단계(알림 + 원문)는 살아 있게 단계를 분리합니다.
양식 변경15대 → 20대 품목 개편이 이미 한 번 있었고, 파서는 위치가 아니라 이름으로 찾아서 흡수했습니다. 검산이 실패하면 숫자에 "확인 필요"를 표시합니다.
1GB 램 서버pdftotext는 잠깐 돌고 끝나는 프로그램이라 부담이 작고, 이미지는 수십 MB 늘 것으로 봅니다(추측, 미측정). 2단계에서만 넣습니다.
사이트 부담평소 월 10여 회 요청. 소급할 때는 요청 사이를 2~5초 띄우고, User-Agent에는 개인정보 없이 일반 이름을 씁니다.
브리핑과 시간 엇갈림아침 브리핑(06:30)은 발표(11:00)보다 이르므로 1일 아침 브리핑에는 넣을 수 없습니다. 2일 브리핑에 한 줄 넣는 건 가능합니다(추후 선택).
