# 뉴스 브리핑 구독 생성 방식 — 1회 시험 안내 (2026-10-27)

설계: [docs/design/뉴스브리핑_docvault_20261001.md](design/뉴스브리핑_docvault_20261001.md) "구독 생성 방식 — 시험". 앱 코드는 바꾸지 않고, **claude.ai 예약 작업(클라우드 세션)이 저장소의 스킬로 브리핑 회차 하나를 만들어 낼 수 있는지**를 손으로 1회 돌려 본다. 모델 구성 A(전부 Opus)와 B(분류·선별은 Sonnet)를 각각 한 번씩.

이 시험이 쓰는 것은 **Claude 구독 사용량**이다. 평소 Claude를 많이 쓰는 날은 피한다. API 비용은 들지 않는다.

## 0. 이 시험으로 알게 되는 것

| 기준 | 합격 | 어디서 보나 |
|---|---|---|
| 걸린 시간 | 75분 이내 | 세션 시작~`result.json` 커밋 시각 |
| 구독 사용량 | 1회 ≈ 주간 한도 3% 이하 | claude.ai 설정 → 사용량, 실행 전후 비교 (두 구성 각각) |
| 정확도 | 무작위 10건 원문 대조, 틀린 사실 0건 | `result.json` 기사 10건의 `url`을 열어 요약과 대조 |
| 체감 품질 | 같은 시간대 API 회차와 같거나 나음 | 두 JSON을 나란히 — 비교는 Claude Code 세션에 맡겨도 된다 |

## 1. 준비 — docvault 쪽 (5분)

1. 저장소 브랜치 `claude/keen-hawking-ssl55j`(PR [ehdwn009/docvault#15](https://github.com/ehdwn009/docvault/pull/15))가 스킬·CLI를 담고 있다. 시험은 이 브랜치에서 한다. 아직 main에 합치지 않아도 된다. **실전(6절)은 main에 올려 배포한 뒤**에 한다 — 서버 쪽(4단계)이 main에서 돌아야 지시서를 내주고 완성본을 받을 수 있다.
2. (선택) 실제 수집 목록으로 시험하려면 앱에서 `뉴스 브리핑/수집 목록.json`을 열어 내용을 복사해 저장소에 `.briefing-job/sources.json`으로 둘 수 있다 — 세션에게 "수집 목록은 `.briefing-job/sources.json`"이라고 말하면 된다. 없으면 코드의 기본 목록(27곳 + 꺼진 후보)으로 돈다.
3. 비교 대상 API 회차: 시험을 돌리는 날 아침 회차(또는 [브리핑 만들기] 한 번)의 JSON. 회차 화면 ⋯ → "코드로 보기"에서 복사하거나 [다운로드].

## 2. 준비 — claude.ai 쪽 (10분, 처음 한 번)

Claude Code on the web(claude.ai/code) → 환경(Environment) 설정:

1. **저장소**: `ehdwn009/docvault` 연결, 기본 브랜치는 시험 브랜치.
2. **네트워크 (Network access)**: `Custom`으로 두고 아래를 넣는다. 세션이 밖으로 나가는 요청은 이 목록을 거친다 — 없는 곳은 403이 난다.
   - `registry.npmjs.org` (의존성 설치)
   - 수집 목록 언론사 도메인 전부 — 세션에서 `npm run briefing:job -w server -- instruction .briefing-job` 뒤 `.briefing-job/instruction.json`의 `allowedDomains`가 그 목록이다. 처음엔 `Full`(모든 도메인 허용)로 시작해 동작을 확인한 뒤 좁혀도 된다.
   - 실전 단계(6절)에서는 docvault 도메인(`https://내이름.duckdns.org`)도 — **이번 시험에는 필요 없다.**
3. **비밀값**: 이번 시험에는 **없다**(docvault에 보내지 않는다). 실전 단계(6절)에서 열쇠는 네트워크 시크릿에, `DOCVAULT_URL`은 환경 변수에 넣는다.
4. **권한 설정(권장)**: 저장소에 `.claude/settings.json`을 아래 내용으로 두면 세션이 명령마다 멈춰 사람을 기다리지 않는다. (이 파일은 Claude Code 자체 설정이라 이 세션이 만들지 않았다 — 직접 만들어 커밋한다.)

```json
{
  "permissions": {
    "allow": [
      "Bash(npm ci:*)",
      "Bash(npm run briefing:job:*)",
      "Bash(curl -sS:*)",
      "Bash(git add:*)",
      "Bash(git commit:*)",
      "Bash(git push:*)",
      "Bash(git checkout:*)",
      "Bash(mkdir:*)",
      "Bash(cat:*)",
      "Bash(ls:*)",
      "Bash(wc:*)"
    ]
  }
}
```

## 3. 실행 (구성마다 한 번)

claude.ai/code에서 그 환경으로 **새 세션**을 열고 아래를 붙여 넣는다. 예약 작업(routine)을 만들어 "지금 실행"해도 같다 — 이번엔 손으로 돌려서 시작·끝 시각을 직접 적는 편이 비교에 낫다.

**구성 A**
```
BRIEFING_JOB_MODE=test 로 briefing-subscription 스킬을 실행해.
지시서는 npm run briefing:job -w server -- instruction .briefing-job --hours 24 --slot morning --config A 로 만들어.
결과는 브랜치 claude/briefing-test-<오늘날짜>-A 에 커밋·push 해.
시작 시각과 끝 시각(UTC)을 마지막에 알려 줘.
```

**구성 B** — 위에서 `--config B`, 브랜치 `…-B`. 스킬이 B를 읽으면 분류·선별 하위 에이전트를 Sonnet으로 돌린다.

### 두 번째 시험 (2026-10-30 추가 — 스킬 v2: 웹 검색 재료·후보 출처 점검·전수 검수)

1회 시험(구성 A)에서 시간(12분)·사용량(주간 약 1%)은 넉넉히 통과했지만, 클라우드에서 연합뉴스·동아일보·BBC·NYT가 막혀(403) 국내 기사가 얇았다. 스킬 v2는 막힌 기사를 웹 검색으로 채우고(구독이라 전부), 꺼 둔 후보 출처 중 열리는 곳을 재고, 핵심·주요를 전부 검수한다. API 회차와 **같은 시간 범위**로 돌려야 비교가 된다 — 그날 아침 API 회차의 범위(보통 전날 06:30 ~ 당일 06:30)를 넣는다. 범위가 오래될수록 피드에서 기사가 빠지므로, **그날 오전 중**에 돌리는 것이 좋다.

```
BRIEFING_JOB_MODE=test 로 briefing-subscription 스킬을 실행해.
지시서는 npm run briefing:job -w server -- instruction .briefing-job --since <전날>T06:30+09:00 --until <오늘>T06:30+09:00 --slot morning --config B --all-candidates 로 만들어.
결과는 브랜치 claude/briefing-test-<오늘날짜>-B 에 커밋·push 해.
시작 시각과 끝 시각(UTC)을 마지막에 알려 줘.
```

`<전날>`·`<오늘>`은 날짜로 바꾼다(예: `2026-10-30T06:30+09:00`). 실행 전후 사용량 %는 1회 때처럼 적는다. 웹 검색과 전수 검수가 늘어 1회보다 오래 걸리고 사용량도 더 쓸 것이다 — 그 차이가 이번에 재는 것이다.

실행 **직전·직후**에 claude.ai 설정 → 사용량 화면의 주간 % 를 적어 둔다 (A 전·후, B 전·후 — 네 숫자).

중간에 세션이 권한을 물으면 허용한다(위 settings.json을 넣었으면 거의 묻지 않는다). 90분 넘게 끝나지 않으면 그 자체가 결과다 — 세션을 멈추고 어디까지 됐는지(`.briefing-job/`에 어떤 파일이 생겼는지) 적어 둔다.

## 4. 결과 넘기기

끝나면 브랜치 두 개(`claude/briefing-test-<날짜>-A`, `-B`)에 `.briefing-job/result.json`·`verify-report.txt`·`instruction.json`이 올라와 있다. 아래를 Claude Code 세션(이 PR을 만든 세션이든 새 세션이든)에 알려 주면 비교·판정을 맡길 수 있다.

- 두 브랜치 이름
- 네 개의 사용량 % (A 전/후, B 전/후)
- 두 실행의 시작·끝 시각
- 비교 대상 API 회차 JSON (파일 또는 붙여 넣기)

판정은 설계 문서의 합격 기준으로 한다. 두 번째 시험까지 통과해 **4단계(서버)와 5단계(설정 화면)가 2026-10-30 완료**됐다. 남은 것은 6절의 실전 설정이다 — 이제 API가 아니라 설정 화면에서 한다. 이후 시험에서 불합격이 나오면 어디가 모자랐는지 보고 스킬·손잡이를 고쳐 한 번 더 돌리거나 멈춘다.

## 5. 세션 안에서 무슨 일이 일어나나 (참고)

| 단계 | 누가 | 무엇 |
|---|---|---|
| 수집 | 코드 (`briefing:job collect`) | 수집 목록의 RSS·Google 검색을 받아 후보 수백 건 → `candidates.json`, 분류할 것 `classify-NN.txt` |
| 분류 | 에이전트 | 언론사 피드 기사마다 세부 분야 → `classified.json` |
| 입력 자르기 | 코드 (`group`) | 분야마다 최대 60건, 서버와 같은 규칙 → `select/<분야>.txt` |
| 선별 | 에이전트 | 같은 사건 묶기·중요도·분야 넘는 합치기 → `selected.json` |
| 원문 읽기 | 코드 (`read`) | 핵심·주요 기사의 본문을 받아 재료로 → `materials.json`, 요약 입력 `summarize/*.txt` |
| 요약·검수 | 에이전트 | 서버와 같은 지시문으로 리드·왜·칸·5W·영향·해설·글머리표 → `written.json`, 검수 에이전트가 10건 대조 |
| 웹 검색 재료 (v2) | 에이전트 + 코드 (`webfill`) | 막힌 기사·재료 1곳인 핵심을 허용 도메인 안에서 검색 → `webfill.json`, 코드가 도메인·날짜·제목 겹침 검사 후 W 재료로 |
| 검증·조립 재료 | 코드 (`verify`) | 서버의 `finalizeItem`·`finalizeBullets`로 숫자 대조·근거 기호·칸 규칙 검사, 건강 숫자 → `result.json` |

서버로 보내는 것은 `result.json`뿐이고, 원문 재료(`materials.json`)는 커밋하지 않는다.

## 6. 실전 설정 (설정 화면에서 — 2026-10-30부터)

서버(4단계)와 설정 화면(5단계, SCR-147)이 2026-10-30에 끝났다. 실전 연결은 **설정 → 뉴스 브리핑 → 생성 방식**에서 전부 한다. 콘솔에 `fetch`를 붙여 넣던 옛 방법은 이 절 맨 뒤 "부록"에만 남겼다 — 화면이 안 열리는 비상시용이다.

전제 셋.
- 이 브랜치가 **main에 올라가 배포**되어 있다 — 스킬·서버·화면이 전부 main에서 돈다. 왜: 세션은 저장소의 main을 받아 스킬을 읽고, 서버는 main 이미지로 돈다. 한쪽만 새 버전이면 지시서와 스킬이 어긋난다.
- docvault가 **https** 주소로 열려 있다. 왜: 열쇠가 평문(http)으로 나가면 중간에서 읽힌다. 스킬도 `DOCVAULT_URL`이 https가 아니면 스스로 멈춘다.
- 열쇠·토큰 **실제 값은 어디에도 적어 두지 않는다**(이 문서·메모·커밋 전부). 화면의 [복사] 단추로 바로 옮긴다.

### 들어가기

관리자로 로그인 → 설정(⚙) → **뉴스 브리핑** → 아래쪽 **생성 방식**. 라디오가 둘이다 — "앱이 직접 만들기 (API)"와 "구독으로 받기 (Claude 예약 작업)". **"구독으로 받기"를 누른다.**

아직 열쇠도 트리거도 없으니 방식은 바뀌지 않는다. 대신 라디오 아래에 노란 줄 「아래 열쇠와 트리거를 준비하면 바꿀 수 있어요. 그동안은 앱이 직접 만들어요」가 뜨고, 그 밑에 상자가 펼쳐진다 — 정상이다. 상자 안 **「설정 체크리스트 펼치기」**를 누르면 여섯 단계가 나온다. 아래 ①~⑥이 그 여섯 단계를 하나씩 푼 것이다.

왜 순서가 있나 — 열쇠(①)는 claude.ai 환경(②)에 넣어야 하고, 예약 작업(④)은 그 환경 안에 만들며, 트리거 주소·토큰(⑤)은 예약 작업을 만들어야 생긴다. 앞 단계 없이 뒷 단계를 할 수 없다.

### ① 연결 열쇠 발급

「연결 열쇠 (예약 작업이 docvault에 들어올 때)」 아래 **[발급]**을 누른다. 그 자리에 노란 상자가 생기고 `dvt_`로 시작하는 열쇠 원문과 [복사]·[닫기]가 보인다.

**[복사]를 누르고 바로 ②로 간다.** [닫기]를 누르거나 라디오를 바꾸면 다시 볼 수 없다 — 서버는 열쇠의 해시(지문)만 남기고 원문은 버린다. 왜: 서버에 원문이 없으면 DB가 통째로 새도 열쇠는 새지 않는다.

닫아 버렸으면 [다시 발급]. 이전 열쇠는 그 자리에서 죽는다. 확인창이 「열쇠가 샌 것 같을 때만 하세요 — 새면 남이 가짜 회차를 보낼 수 있어요. 지금 열쇠는 바로 쓸 수 없게 되고, claude.ai 환경의 DOCVAULT_TOKEN도 새 값으로 바꿔야 해요.」라고 묻는다 — 열쇠를 가진 사람은 docvault에 완성본을 넣을 수 있어서다. 닫은 뒤에는 「`dvt_8f3k…` · 발급 10/30 12:00 · 아직 사용 안 함」만 남고, ⑥을 통과하면 「마지막 사용 10/30 14:12」로 바뀐다.

이 열쇠로는 `/api/v1/briefing/jobs/…` 세 주소(지시서·진행 보고·완성본)만 열린다. 다른 API에는 통하지 않는다.

### ② claude.ai 환경 — 열쇠는 네트워크 시크릿에, 주소는 환경 변수에

claude.ai → 설정 → Claude Code → 환경. 2절의 시험용 환경을 그대로 쓰되 **기본 브랜치를 main**으로 바꾼다. 넣을 것은 둘인데 **자리가 다르다** — 첫 실전(2026-10-30)에서 확인한 사실: "시크릿 추가" 창에는 환경변수 유형이 없고(Bearer·Basic·OAuth… 뿐), "환경 변수" 화면에는 "이 환경을 쓰는 모든 사람이 값을 볼 수 있으니 시크릿은 넣지 마세요"라고 적혀 있다.

**(1) 네트워크 시크릿 — 열쇠.** 환경 편집 → 네트워크 시크릿 → [시크릿 추가]:

| 칸 | 값 |
|---|---|
| 시크릿 유형 | `Bearer` |
| 허용된 웹사이트 | docvault 호스트(예 `mydocvault.duckdns.org`, `https://` 없이) — 화면 체크리스트 ②의 [복사] |
| 경로 접두사 | `/api/v1/briefing/jobs/` — 화면 체크리스트 ②의 [복사] |
| 사용자 지정 헤더 | 이름 `Authorization` · 접두사 `Bearer` · 값 = ①에서 복사한 열쇠 |

왜 이게 더 좋은가 — 프록시가 그 주소로 나가는 요청에만 헤더를 붙여 주고, 세션(Claude)은 열쇠 값을 아예 보지 못한다. 경로 접두사를 두는 이유는 서버도 그 접두어에서만 열쇠를 받기 때문이다 — 다른 주소로는 새어 나갈 일 자체가 없다.

**(2) 환경 변수 — 주소.** 환경 편집 → 환경 변수에 한 줄(체크리스트 ②의 [한 줄 복사]):

```
DOCVAULT_URL=https://mydocvault.duckdns.org
```

끝에 `/`가 없다. 열쇠는 여기에 넣지 않는다. 스킬은 `DOCVAULT_URL`만 읽고, 헤더는 붙이지 않은 채 요청을 보낸다(프록시가 붙인다). 이름이 다르면 ⑥에서 「아직 연결 기록 없음」, 시크릿이 안 붙으면 세션이 401을 받고 멈춘다 — 둘 다 ⑥에서 드러난다.

### ③ 네트워크 허용 목록

같은 환경의 **Network access**를 `Custom`으로 두고, 2-2의 목록(`registry.npmjs.org` 등)에 더해 둘을 넣는다.
- 체크리스트 ③의 **[허용 목록 n줄 복사]** 값 — docvault 도메인 한 줄 + 언론사 도메인마다 **두 줄**(`hankyung.com`과 `*.hankyung.com`). 그대로 붙여 넣는다.

왜 두 줄인가 — 첫 실전(2026-10-31 아침판)에서 배운 것. 맨몸 도메인(`hankyung.com`)만 넣으면 claude.ai 허용 목록은 `www.hankyung.com`·`rss.hankyung.com` 같은 하위 도메인을 열어 주지 않는다. 그날 피드 67곳 중 26곳이 "주소를 찾을 수 없음"으로 막혀 190건 중 요약은 6건뿐인 얇은 회차가 왔다. 별표(`*.`) 줄이 하위 도메인을, 맨몸 줄이 도메인 자체를 연다.

왜 이 목록이 필요한가: 세션이 밖으로 나가는 요청은 이 목록을 거친다. docvault 도메인이 없으면 지시서를 받을 수 없고, 언론사 도메인이 없으면 피드와 원문을 읽을 수 없다. 수집 목록을 고치면 목록도 바뀌니 그때 다시 복사해 맞춘다.

### ④ 예약 작업 만들기

claude.ai/code → 그 환경에서 예약 작업(scheduled task)을 하나 만든다.
- 저장소: docvault.
- **일정(시각)은 비워 둔다.** 왜: 켜는 것은 docvault 서버다(회차 90분 전). 시각을 걸어 두면 서버가 켠 것과 겹쳐 두 번 돌고 사용량만 쓴다.
- 지시문: 체크리스트 ④의 **[지시문 복사]** 한 줄을 그대로 붙인다. 지금 서버가 내주는 문장은 이것이다.

```
routine-fire-payload 블록에 적힌 BRIEFING_JOB_ID로 briefing-subscription 스킬을 실전 모드로 실행해. DOCVAULT_URL은 환경 변수에 있고, docvault 연결 열쇠는 네트워크 시크릿이 붙여 줘.
```

왜 이렇게 쓰나 — 서버가 예약 작업을 켤 때 "BRIEFING_JOB_ID=<uuid> — …"라는 글을 보내는데, claude.ai는 이 글을 세션 첫 메시지 안에 `<routine-fire-payload>` 블록으로 감싸 넣는다("신뢰하지 않는 데이터" 취급). 그래서 예약 작업에 **저장된** 지시문이 "그 블록에서 id를 읽어라"고 말해 줘야 세션이 어느 회차를 만들지 안다. `BRIEFING_JOB_ID`는 비밀값이 **아니다** — 켜질 때마다 바뀌어 메시지로 온다. [연결 확인](⑥)도 같은 길로 `BRIEFING_JOB_ID=ping-<uuid> — docvault 연결 확인입니다. …`가 온다.

만들면 **트리거 주소(fire URL)와 트리거 토큰**이 보인다. 주소는 `https://api.anthropic.com/v1/claude_code/routines/<id>/fire` 꼴이어야 한다 — docvault는 **이 모양만 받는다**. 왜: 아무 주소나 받으면 서버가 토큰을 아무 데나 보내는 구멍이 된다.

### ⑤ 트리거 주소·토큰을 docvault에

「예약 작업 트리거 (docvault가 예약 작업을 켤 때)」의 두 칸에 ④의 주소와 토큰을 넣고 **[저장]**. 토스트 「트리거를 저장했어요 — [연결 확인]으로 시험해 보세요」가 뜨고 「설정됨 ✓」로 바뀐다.

- 값은 암호화되어 저장되고 **다시 보이지 않는다.** 바꾸려면 새 값을 넣고 [바꾸기], 없애려면 [지우기](생성 방식은 "앱이 직접 만들기"로 돌아간다).
- 주소 모양이 틀리면 「주소: …」로 거절한다.
- 언젠가 「트리거를 읽을 수 없어요(서버 비밀키가 바뀜) — 다시 넣어 주세요」가 보이면 서버의 `JWT_SECRET`이 바뀐 것이다 — ④의 값을 다시 넣는다.
- **방식은 여기서 바뀌지 않는다.** 저장만 한 것이다. 바꾸는 건 ⑥ 뒤에 사람이 단추로 한다.

### ⑥ 연결 확인 → [구독으로 바꾸기]

**[연결 확인]**을 누른다(트리거를 저장해야 눌린다). 서버가 예약 작업을 한 번 켜고, 세션이 지시서를 받아 가는지만 본다 — 회차는 만들지 않는다. 단추가 「확인하는 중…」으로 바뀌고 화면이 5초마다 결과를 다시 읽는다(6분 뒤 멈춘다).

| 보이는 글 | 뜻 | 어디를 보나 |
|---|---|---|
| 켰어요 — 세션을 기다리는 중 (14:10) | 켰고, 아직 안 왔다 | 1~3분 기다린다(세션 기동) |
| **연결 확인됨 (14:12)** | 세션이 열쇠로 지시서를 받아 갔다 | 통과 |
| 아직 연결 기록 없음 — 세션이 docvault를 부르지 않았어요 (네트워크 허용 목록·환경변수를 확인) | 5분 동안 요청이 없었다 | ③ docvault 도메인, ② 비밀값 이름, ④ 지시문 |
| 연결 열쇠가 맞지 않습니다 (14:11) | 틀린 열쇠로 요청이 왔다 | 네트워크 시크릿의 헤더 값이 ①의 열쇠인지(다시 발급했으면 이전 값은 죽었다) |
| 예약 작업을 켜지 못했어요 — 트리거 주소·토큰을 확인하세요 (14:10) | 켜지 못했다 | ⑤의 주소·토큰 |

「연결 확인됨」이 나오면 라디오 아래 노란 줄이 「열쇠와 트리거가 준비됐어요 — [연결 확인]이 "연결 확인됨"이면 바꾸세요」로 바뀌어 있다. 그 옆 **[구독으로 바꾸기]**를 누른다. 이제 방식이 구독이다.

왜 자동으로 안 바꾸나 — 트리거를 저장했다고 바로 바꾸면, 연결이 안 되는 상태로 아침 회차가 「도착 안 함」이 된다. 왕복을 눈으로 확인한 사람이 바꾸는 게 맞다.

바꾼 뒤 확인할 것:
- **자동 생성 스위치**와 회차 세 줄은 두 방식이 함께 쓴다 — 스위치가 켜져 있어야 서버가 예약 작업을 켠다. 구독 모드에서는 AI 키가 없어도 켜진다. 스위치 설명이 「아래에서 켠 회차의 90분 전에 claude.ai 예약 작업을 켜고, 회차 시각 30분 뒤까지 완성본을 기다려요. 안 오면 패널에 알리고 [지금 만들기]로 만들 수 있어요」로 바뀐다.
- 상자 아래 「예약 작업은 회차 90분 전에 켜지고, 마감은 회차 30분 뒤예요 — 아침 06:30 → 05:00 켜기 · …」에서 켜지는 시각을 본다.
- 비용 줄 뒤에 「(구독 회차는 $0으로, 비용에 쌓이지 않아요)」가 붙는다.
- 되돌리려면 라디오 "앱이 직접 만들기". 예약 작업이 도는 중이면 한 번 묻고(「앱이 직접 만들기로 바꿀까요?」), 그 실행은 취소로 기록된다. claude.ai의 세션은 스스로 멈추지 않으니 거기서도 꺼 둔다. 열쇠·트리거는 남아 있어 다시 구독으로 바꾸면 바로 이어서 쓴다.

### 첫 실전 회차에서 볼 것

- **패널 진행 카드**: 켜지는 시각(아침 06:30이면 05:00)에 「예약 작업을 켰어요 — 세션을 기다리는 중」 → 세션이 지시서를 받아 가면 단계 이름(수집 · 분류 · 선별 · 원문 읽기 · 웹 검색 · 요약 · 보기 쓰기 · 검수)과 「요약 12/40」 같은 숫자, 걸린 시간 → 작은 줄 「구독 작업 중 · 05:00 시작 · 마감 07:00 · 마감까지 안 오면 알려 드려요. 멈추려면 claude.ai의 예약 작업에서」. 진행 기록은 세션이 보낸 한 줄들이다. 화면은 15초마다 새로 읽는다. **[중지]는 없다** — docvault가 claude.ai 세션을 멈출 수 없다. 기다리기 싫으면 오른쪽 끝 **[직접 만들기로 대체]**(한 번 묻고, 이 회차만 API 비용으로 앱이 만든다; AI 키가 없으면 잠겨 있다).
- **끝나면**: 토스트 「아침판 137건을 만들었어요 [열기]」와 실행 기록 「구독 · 아침판 137건 · 구독 생성 · $0 · 52분 · 검사에서 3건 뺌 · 10/30 06:40」. 52분은 지시서를 받아 간 때부터다.
- **마감(07:00)까지 안 오면**: 띠 「아침판이 도착하지 않았어요 (마감 07:00) [지금 만들기]」와 실행 기록 「구독 · 아침판 도착 안 함 — … · 10/30 07:00」. [지금 만들기]는 API로 그 회차를 만든다(이 회차만 비용).
- **며칠 뒤**: 설정 상자 아래 「최근 n회: 성공 n · 도착 안 함 n · 실패 n · 평균 n분」과 힌트 — 「마감에 자주 몰려요. 수집 목록의 출처나 켜 둔 분야를 줄여 보세요」 또는 「넉넉히 끝나요. 회차 시각을 30분 늦추면 더 최근 기사까지 담을 수 있어요」.
- 끝난 회차의 JSON(`edition.generator`)에 `{ mode: "subscription", skillVersion: "4" }`가 찍혔는지.

### 부록 — 화면 없이 API로 (비상용)

설정 화면이 안 열릴 때만 쓴다. 관리자 전용 API(API-134·141·143·144)는 로그인 쿠키로 들어가므로, **docvault에 로그인한 브라우저 탭 → 개발자 도구(F12) → 콘솔**에 `fetch`를 붙여 넣으면 쿠키가 알아서 따라간다. `<…>`는 자리표시자다 — 실제 값은 적어 두지 않는다. 화면이 하는 일과 1:1로 대응한다.

① 연결 열쇠 발급 (화면 [발급]) — `token`은 이 응답에 한 번만:

```js
await (await fetch('/api/v1/briefing/token', { method: 'POST' })).json()
// → { token: "dvt_…", prefix: "dvt_xxxx", createdAt: 1793… }
```

②·③ 체크리스트 재료 (화면의 복사 단추들) — `checklist.docvaultUrl`·`envNames`·`taskPrompt`와 `allowedDomains`:

```js
await (await fetch('/api/v1/briefing/subscription')).json()
// → { mode, tokenPrefix, triggerSet, triggerBroken, lastPingAt, lastPingResult, triggerTimes, recent,
//     allowedDomains: [ … ], checklist: { docvaultUrl, envNames: ["DOCVAULT_URL"], secret: { host, pathPrefix, header, prefix }, taskPrompt: "…" } }
```

⑤ 트리거 저장 (화면 [저장]) — 값은 다시 내려오지 않고 `triggerSet: true`만 보인다. 지우려면 `{ trigger: null }`(방식은 `api`로 돌아간다):

```js
await (await fetch('/api/v1/briefing/settings', {
  method: 'PUT', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ trigger: { url: 'https://api.anthropic.com/v1/claude_code/routines/<id>/fire', token: '<트리거 토큰>' } }),
})).json()
// → { …, triggerSet: true }
```

⑥ 연결 확인 (화면 [연결 확인]) — 1~3분 뒤 ②의 API를 다시 읽어 `lastPingResult`를 본다(`ok` / `fired` / `no_request` / `token_invalid` / `trigger_failed` — 뜻은 위 ⑥의 표와 같다):

```js
await (await fetch('/api/v1/briefing/subscription/ping', { method: 'POST' })).json()
// → 202 { jobId: "ping-…" }   (트리거가 없으면 409 BRIEFING_TRIGGER_NOT_SET, 켜지 못하면 502 BRIEFING_TRIGGER_FAILED)
```

⑥ 구독으로 바꾸기 (화면 [구독으로 바꾸기]) — 열쇠나 트리거가 없으면 409 `BRIEFING_TRIGGER_NOT_SET`. 되돌리기는 `{ mode: 'api' }`:

```js
await (await fetch('/api/v1/briefing/settings', {
  method: 'PUT', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ mode: 'subscription' }),
})).json()
// → { mode: "subscription", autoEnabled, schedule, nextAutoAt, … }
```
