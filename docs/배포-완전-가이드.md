# docvault 배포 완전 가이드 (초보자용)

이 문서는 **아무것도 모른다고 가정하고** 처음부터 끝까지 안내합니다. 셋 중 원하는 방법을 골라 그 장(章)만 따라 하면 됩니다.

| | 방법 1: 내 PC | 방법 2: 무료 VPS | 방법 3: + Cloudflare Tunnel |
|---|---|---|---|
| 뭐가 되나 | 집 와이파이 안에서 PC·폰으로 사용 | 24시간 켜져 있는 내 서버 | 밖에서도(LTE) HTTPS 주소로 접속 |
| 비용 | 무료 | 무료 (Oracle 무료 티어) | 무료 (도메인만 연 1~2만원, 선택) |
| 난이도 | ★ | ★★ | ★★ |
| 소요 시간 | 20분 | 40분 | 20분 |
| 이런 사람 | 일단 써보고 싶다 | PC를 24시간 켜두기 싫다 | 폰으로 어디서든 보고 싶다 |

> 추천 경로: **방법 1로 먼저 맛보기 → 방법 2로 이사 → 방법 3으로 외부 개방.**
> 이사는 `data/` 폴더 하나만 옮기면 되니 부담 없이 1부터 시작하세요.

---

## 시작 전에: 개념 3개만 알고 가기

**서버**란 그냥 "이 프로그램을 계속 켜두는 컴퓨터"입니다. 내 PC도 서버가 될 수 있고, 남의 데이터센터 컴퓨터(VPS)를 빌릴 수도 있습니다.

**Docker**는 "프로그램 + 실행 환경"을 통째로 상자(컨테이너)에 담아 실행하는 도구입니다. docvault는 Docker로 포장돼 있어서, Docker만 깔려 있으면 어떤 컴퓨터에서든 명령 한 줄로 똑같이 돕니다. Node.js 설치 같은 건 필요 없습니다.

**data/ 폴더**에 여러분의 모든 데이터(문서, 계정, 설정)가 들어 있습니다. 이 폴더만 복사하면 백업이고, 다른 컴퓨터로 옮기면 이사입니다. 나머지는 전부 다시 만들 수 있는 것들입니다.

# 방법 1. 내 Windows PC에서 돌리기

## 1-1. Docker Desktop 설치

이미 설치돼 있는지 먼저 확인: **PowerShell**을 열고(시작 버튼 우클릭 → "터미널" 또는 "Windows PowerShell") 아래 입력.

```powershell
docker --version
```

버전이 나오면 설치돼 있는 것 → 1-2로. `인식할 수 없는...` 오류가 나면:

1. https://www.docker.com/products/docker-desktop/ 접속 → **Download for Windows** 클릭
2. 받은 `Docker Desktop Installer.exe` 실행 → 옵션은 기본값 그대로(WSL 2 체크 유지) → 설치
3. **재부팅** (필수인 경우가 많음)
4. 재부팅 후 Docker Desktop 실행 → 약관 동의 → 회원가입은 **Skip 해도 됨**
5. "WSL 2 installation is incomplete" 오류가 뜨면: 안내된 링크에서 `wsl_update_x64.msi` 설치 후 Docker Desktop 재시작
6. 왼쪽 아래 고래 아이콘이 **초록색**이 되면 준비 완료

## 1-2. 코드 준비

이미 이 저장소가 PC에 있다면(`c:\Github\docvault`) 건너뛰세요. 새 PC라면:

```powershell
# git이 없다면 https://git-scm.com/download/win 에서 설치 후
cd C:\
git clone https://github.com/ehdwn009/docvault.git
cd docvault
```

## 1-3. 비밀 키 설정 (.env 파일)

`.env`는 "이 서버만의 비밀 설정" 파일입니다. **JWT_SECRET**은 로그인 세션을 암호화하는 열쇠라 반드시 길고 무작위여야 합니다.

> **이미 `.env` 파일이 있다면 이 단계는 건너뛰세요.** JWT_SECRET에 긴 무작위 값이 들어 있으면 그대로 쓰면 됩니다.
> 참고로 `ADMIN_INITIAL_PASSWORD`는 **DB가 처음 만들어질 때 딱 한 번** admin 계정에 적용되는 값입니다. 이미 한 번이라도 실행해서 `data/` 폴더가 생겼다면 이 값을 바꿔도 효과가 없고, 비밀번호는 앱 안의 설정 화면에서 바꿉니다.

PowerShell에서 (docvault 폴더 안에서):

```powershell
cd C:\Github\docvault    # 자기 경로에 맞게

# 무작위 열쇠를 만들어 .env 파일 생성 (한 줄씩 실행)
$secret = -join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })
Set-Content .env "JWT_SECRET=$secret`nADMIN_INITIAL_PASSWORD=여기에초기비밀번호" -Encoding utf8
```

`여기에초기비밀번호` 부분을 원하는 비밀번호(8자 이상)로 바꿔서 실행하세요. 메모장으로 `.env`를 열어 확인해도 됩니다.

## 1-4. 실행

```powershell
docker compose up -d --build
```

- 처음엔 이미지를 만드느라 2~5분 걸립니다. 두 번째부터는 몇 초.
- `-d`는 "백그라운드로 켜둬라"라는 뜻입니다. 창을 닫아도 계속 돕니다.

확인:

```powershell
docker compose ps        # STATUS가 Up (healthy)면 성공
```

## 1-5. 접속해서 첫 설정

1. 브라우저에서 http://localhost:3000 접속
2. 아이디 `admin` / 비밀번호는 1-3에서 정한 것으로 로그인
3. 좌측 레일 ⚙(설정) → **비밀번호 변경** (초기 비밀번호는 반드시 바꾸세요)
4. 파일을 하나 올려보고, 새로고침해도 남아 있으면 정상

가족·지인 계정은 레일의 🛠(관리자) → 사용자 탭에서 발급합니다.

## 1-6. 같은 와이파이의 폰에서 접속하기

먼저 PC의 내부 IP를 알아냅니다:

```powershell
ipconfig
```

"무선 LAN 어댑터 Wi-Fi" 항목의 **IPv4 주소**(예: `192.168.0.23`)를 찾으세요.

다음으로 Windows 방화벽이 폰의 접속을 막지 않게 허용합니다 (**관리자 권한 PowerShell**에서):

```powershell
New-NetFirewallRule -DisplayName "docvault" -Direction Inbound -LocalPort 3000 -Protocol TCP -Action Allow
```

이제 폰 브라우저에서 `http://192.168.0.23:3000` (자기 IP로) 접속 → 로그인 → 브라우저 메뉴에서 **"홈 화면에 추가"** 하면 앱처럼 설치됩니다.

> 폰에서 안 열리면: ① PC와 폰이 같은 와이파이인지 ② 방화벽 규칙을 관리자 권한으로 만들었는지 ③ 공유기의 "AP 격리" 설정이 꺼져 있는지 확인.

## 1-7. PC를 켤 때 자동으로 시작되게

1. Docker Desktop → 우상단 ⚙ Settings → General → **Start Docker Desktop when you sign in** 체크
2. 컨테이너는 `restart: unless-stopped`로 설정돼 있어 Docker가 켜지면 자동으로 따라 켜집니다

## 1-8. 자주 쓰는 명령 모음

```powershell
docker compose ps              # 상태 보기
docker compose logs app        # 로그 보기 (문제 생겼을 때 1순위)
docker compose restart         # 재시작
docker compose down            # 끄기 (데이터는 남음)
docker compose up -d           # 다시 켜기
git pull; docker compose up -d --build    # 새 버전으로 업데이트
```

# 방법 2. 무료 VPS에서 24시간 돌리기 (Oracle Cloud)

내 PC를 계속 켜두지 않아도 되는 방법입니다. Oracle Cloud의 "Always Free" 등급은 **기간 제한 없이 무료**입니다 (가입에 본인 확인용 카드가 필요하지만, Free 등급만 쓰면 결제되지 않습니다).

> Oracle 가입이 거절되거나 번거로우면 대안: 구글 클라우드(GCP) e2-micro 무료 등급, 또는 월 5천원 안팎의 유료 VPS(Vultr, DigitalOcean 등). 서버만 있으면 2-4부터는 전부 동일합니다.

## 2-1. Oracle Cloud 가입

1. https://signup.cloud.oracle.com 접속
2. 국가 Korea, 이름·이메일 입력 → 메일 인증
3. Account Name(아무거나), 비밀번호 설정
4. Home Region은 **South Korea Central (Seoul)** 선택 ← 나중에 못 바꿉니다
5. 휴대폰 인증 → 카드 등록 (확인용 소액 승인 후 취소됨) → 가입 완료
6. 콘솔(https://cloud.oracle.com) 로그인

## 2-2. 가상 머신(인스턴스) 만들기

1. 콘솔 좌상단 ☰ 메뉴 → **Compute → Instances** → **Create instance**
2. Name: `docvault`
3. **Image and shape** 섹션의 Edit:
   - Image: **Canonical Ubuntu 22.04** (Change image에서 선택)
   - Shape: **Ampere → VM.Standard.A1.Flex**, OCPU 1개·메모리 6GB 정도로 설정
     (A1이 "Out of capacity" 오류로 안 만들어지면: VM.Standard.E2.1.Micro 선택 — 조금 느리지만 충분합니다)
4. **Add SSH keys**: "Generate a key pair for me" 선택 → **Save private key** 눌러 키 파일 다운로드
   (예: `ssh-key-2026-08-13.key` — 이 파일이 서버 열쇠입니다. 잃어버리면 접속 불가!)
5. **Create** 클릭 → 1~2분 후 상태가 초록색 **Running**이 되면 완성
6. 화면에 표시된 **Public IP address**를 메모 (예: `152.67.xx.xx`)

## 2-3. Windows에서 서버에 접속 (SSH)

PowerShell에서 (키 파일 경로와 IP는 자기 것으로):

```powershell
# 키 파일 권한 정리 (최초 1회 — 안 하면 접속 거부될 수 있음)
icacls "C:\Users\내이름\Downloads\ssh-key-2026-08-13.key" /inheritance:r /grant:r "$env:USERNAME:R"

# 접속
ssh -i "C:\Users\내이름\Downloads\ssh-key-2026-08-13.key" ubuntu@152.67.xx.xx
```

처음 접속 시 `Are you sure you want to continue connecting?` → `yes` 입력. 프롬프트가 `ubuntu@docvault:~$`로 바뀌면 **이제부터는 서버 안**입니다. 아래 명령들은 모두 이 서버 안에서 입력합니다.

## 2-4. 서버에 Docker 설치

```bash
# 시스템 최신화
sudo apt update && sudo apt upgrade -y

# Docker 공식 설치 스크립트
curl -fsSL https://get.docker.com | sudo sh

# sudo 없이 docker 명령을 쓸 수 있게
sudo usermod -aG docker ubuntu

# 그룹 적용을 위해 한 번 나갔다 다시 접속
exit
```

다시 `ssh -i ... ubuntu@IP`로 접속한 뒤 `docker --version`이 나오면 성공.

## 2-5. docvault 설치·실행

```bash
git clone https://github.com/ehdwn009/docvault.git
cd docvault

# 비밀 키 생성 + .env 작성
echo "JWT_SECRET=$(openssl rand -hex 32)" > .env
echo "ADMIN_INITIAL_PASSWORD=여기에초기비밀번호" >> .env

# 빌드 + 실행 (첫 빌드 몇 분 소요)
docker compose up -d --build

# 확인 — {"status":"ok",...} 가 나오면 성공
curl http://localhost:3000/api/v1/health
```

## 2-6. 접속은 어떻게? — 포트를 열지 말고 터널을 쓰세요

서버 안에서는 떠 있지만, 밖에서 `http://152.67.xx.xx:3000`으로 바로 접속은 **안 됩니다** (Oracle 방화벽이 기본 차단). 여기서 갈림길:

- **권장: 방법 3(Cloudflare Tunnel)으로 진행** — 포트를 하나도 열지 않고 HTTPS 주소가 생깁니다. 보안도 이쪽이 훨씬 낫습니다. 바로 [방법 3](#방법-3-cloudflare-tunnel로-어디서나-https-접속)으로 가세요.
- 비권장(테스트용): 포트 3000을 직접 열기 — Oracle 콘솔 VCN의 Security List에 Ingress Rule(TCP 3000) 추가 + 서버에서 `sudo iptables -I INPUT -p tcp --dport 3000 -j ACCEPT`. 다만 **HTTP 평문 + 전 세계에 노출**이므로 임시 확인용으로만.

## 2-7. 업데이트·관리

```bash
cd ~/docvault
git pull && docker compose up -d --build   # 업데이트 (데이터 유지됨)
docker compose logs app                    # 로그
./scripts/backup.sh                        # 수동 백업 → backups/ 폴더

# 매일 새벽 4시 자동 백업: crontab -e 실행 후 아래 한 줄 추가
0 4 * * * cd /home/ubuntu/docvault && ./scripts/backup.sh >> backup.log 2>&1
```

# 방법 3. Cloudflare Tunnel로 어디서나 HTTPS 접속

터널은 "서버가 Cloudflare 쪽으로 먼저 전화를 걸어 연결을 유지하는" 방식입니다. 그래서 **포트 개방, 공유기 설정, 고정 IP, 인증서 발급이 전부 필요 없고**, 주소는 자동으로 HTTPS가 됩니다. 방법 1(집 PC)에도, 방법 2(VPS)에도 똑같이 얹을 수 있습니다.

## 3-0. 도메인 준비 (둘 중 하나)

터널에 고정 주소를 붙이려면 내 도메인이 Cloudflare에 연결돼 있어야 합니다.

- **A. 도메인 구입** (권장, 연 1~2만원): Cloudflare에서 직접 사는 게 제일 깔끔합니다 — 아래 3-1 가입 후 대시보드의 **Domain Registration → Register Domain**에서 검색·구매하면 연결까지 자동입니다. (가비아 등에서 이미 산 도메인이 있다면: Cloudflare 대시보드 → Add a domain → 안내에 따라 도메인 업체 사이트에서 **네임서버 2개를 Cloudflare 것으로 교체** → 몇 시간 내 활성화)
- **B. 도메인 없이 임시 테스트**: 서버에서 `docker run --rm cloudflare/cloudflared:latest tunnel --url http://호스트IP:3000` 실행하면 `https://랜덤단어.trycloudflare.com` 임시 주소가 나옵니다. **껐다 켜면 주소가 바뀌므로** 맛보기 전용입니다.

## 3-1. Cloudflare 가입 + 터널 만들기

1. https://dash.cloudflare.com/sign-up 에서 가입 (무료 플랜)
2. https://one.dash.cloudflare.com 접속 (Zero Trust — 처음이면 팀 이름 아무거나 정하고 Free 플랜 선택)
3. 좌측 **Networks → Tunnels** → **Create a tunnel**
4. **Cloudflared** 방식 선택 → 터널 이름 `docvault` → Save
5. 설치 안내 화면이 나오는데 **명령은 복사하지 말고**, 명령 안에 있는 긴 **토큰**(`eyJ`로 시작하는 문자열)만 복사하세요
   (Docker 탭을 누르면 `--token eyJ...` 부분이 잘 보입니다)

## 3-2. 주소(Public Hostname) 연결

같은 화면에서 **Next** → Public Hostname 설정:

| 항목 | 값 |
|---|---|
| Subdomain | `docs` (원하는 것) |
| Domain | 내 도메인 선택 |
| Type | **HTTP** |
| URL | `app:3000` |

> URL을 `app:3000`으로 쓰는 이유: 터널 컨테이너가 docvault 앱과 같은 Docker 네트워크에 살아서, 앱을 `app`이라는 이름으로 부릅니다. localhost가 아닙니다!

**Save tunnel**로 완료.

## 3-3. 서버에 토큰 넣고 터널 켜기

서버(방법 1이면 PC의 PowerShell, 방법 2면 SSH 접속한 VPS)에서 docvault 폴더로 이동 후:

```bash
# .env 파일에 토큰 한 줄 추가 (eyJ... 는 3-1에서 복사한 자기 토큰)
echo "CLOUDFLARE_TUNNEL_TOKEN=eyJ여기에토큰" >> .env

# 터널 프로필을 포함해서 재기동
docker compose --profile tunnel up -d
```

Windows PowerShell이라면 `echo` 대신 메모장으로 `.env`를 열어 `CLOUDFLARE_TUNNEL_TOKEN=eyJ...` 한 줄을 추가해도 됩니다.

확인:

```bash
docker compose ps            # tunnel 컨테이너가 Up이면 성공
docker compose logs tunnel   # "Registered tunnel connection"이 보이면 연결됨
```

Cloudflare Tunnels 화면에서도 상태가 **HEALTHY**(초록)로 바뀝니다.

## 3-4. 접속 + 폰에 설치

1. 폰이든 PC든 어디서나 `https://docs.내도메인.com` 접속
2. 로그인 후 폰 브라우저 메뉴 → **"홈 화면에 추가"** → 앱 아이콘 생성
3. 이제 LTE로도, 카페 와이파이로도 내 문서함이 열립니다

> 보너스: HTTPS라서 방법 1의 방화벽 개방(1-6)은 이제 지워도 됩니다:
> `Remove-NetFirewallRule -DisplayName "docvault"`

```bash
docker compose down
tar -xzf backups/docvault-20260901-040000.tar.gz    # data/ 폴더가 복원됨
docker compose up -d --build
```

이사는 백업 파일을 새 서버로 옮겨(예: `scp` 또는 USB) 위 복원 절차 그대로 하면 끝입니다. Windows에서 서버로 파일 보내기: `scp -i 키파일 백업파일.tar.gz ubuntu@IP:~/docvault/backups/`

## B. 문제 해결

| 증상 | 해결 |
|---|---|
| `docker compose up`이 JWT_SECRET 오류로 실패 | `.env` 파일이 docvault 폴더 안에 있는지, `JWT_SECRET=값` 줄이 있는지 확인 |
| `ports are not available ... 3000` 오류 | 다른 프로그램(주로 `npm run dev:server`)이 3000을 쓰는 중. 그 터미널을 닫거나 `netstat -ano \| findstr :3000`으로 PID를 찾아 종료 후 다시 `docker compose up -d` |
| 브라우저에서 안 열림 | `docker compose ps`로 상태 확인 → `docker compose logs app`에서 오류 읽기 |
| 로그인했는데 새로고침하면 풀림 | `.env`의 JWT_SECRET이 도중에 바뀌었는지 확인 (바꾸면 전원 재로그인) |
| 터널이 HEALTHY가 안 됨 | `docker compose logs tunnel` — 토큰 오타가 대부분. Public Hostname의 URL이 `app:3000`(HTTP)인지 확인 |
| 폰에서 "홈 화면에 추가"가 앱처럼 안 됨 | HTTPS(터널 주소)로 접속했는지 확인 — PWA 설치는 HTTPS에서만 완전 동작 |
| Oracle A1 인스턴스가 계속 Out of capacity | 시간대를 바꿔 재시도하거나 E2.1.Micro로 생성 |
| 서버 재부팅 후 앱이 안 떠 있음 | `docker compose --profile tunnel up -d` 한 번 실행 (이후엔 자동 재시작됨) |

## C. 명령어 치트시트

```bash
docker compose ps                          # 상태
docker compose logs app --tail 50          # 앱 로그 최근 50줄
docker compose restart                     # 재시작
docker compose down                        # 정지 (데이터 유지)
docker compose --profile tunnel up -d      # 시작 (터널 포함)
git pull && docker compose up -d --build   # 업데이트
./scripts/backup.sh                        # 백업
```

## D. 보안 체크리스트

- [ ] admin 초기 비밀번호를 바꿨다
- [ ] `.env`의 JWT_SECRET이 무작위 긴 문자열이다 (예시 값 그대로 쓰지 않았다)
- [ ] `.env` 파일을 깃허브에 올리지 않았다 (.gitignore에 이미 포함돼 있음)
- [ ] 외부 노출은 터널(HTTPS)로만 한다 — 3000 포트 직접 개방은 임시 테스트로만
- [ ] 백업 cron을 걸었고, 백업 파일이 실제로 생기는 걸 한 번 확인했다
