# GCP 배포 + 클라우드 학습 가이드

구글 클라우드(GCP)의 무료 서버에 docvault를 올리면서, 클라우드 운영의 기초를 처음부터 배우는 가이드입니다. **아무것도 모른다고 가정하고** 진행합니다.

## 이 가이드를 끝내면 배우게 되는 것

- [ ] 클라우드에서 **가상 머신(VM)**을 만들고 지우는 법
- [ ] **리전/존**이 뭔지, 왜 무료 조건에 리전이 걸려 있는지
- [ ] **SSH**로 원격 서버에 접속하는 법 (브라우저 방식 + 터미널 방식)
- [ ] 리눅스 기본 명령어 (이동·확인·편집·권한)
- [ ] 메모리가 부족한 서버에 **스왑**을 붙이는 이유와 방법
- [ ] 서버에 **Docker**를 설치하고 앱을 돌리는 법
- [ ] **VPC 방화벽**으로 포트를 열고 닫는 법
- [ ] **DNS**(도메인 → IP 연결)와 **DDNS**(IP가 바뀌어도 따라가게)의 원리
- [ ] **리버스 프록시(Caddy)**와 **HTTPS 인증서(Let's Encrypt)** 자동화
- [ ] **cron**으로 반복 작업(백업·DNS 갱신) 자동화
- [ ] 서버 간 **데이터 이사** (scp)
- [ ] 과금 사고를 막는 **예산 알림** 설정

# 0. 개념 먼저 잡기 (5분)

**클라우드**는 구글·아마존 같은 회사의 데이터센터 컴퓨터를 시간 단위로 빌려 쓰는 것입니다. 우리가 빌리는 단위가 **VM(가상 머신)** — 물리 서버 한 대를 소프트웨어로 잘게 쪼갠 "가상 컴퓨터" 한 칸입니다. 물리 서버는 통째로 빌리기엔 크고 비싸서 여러 칸으로 나누고, 각 칸은 서로를 볼 수 없게 격리됩니다.

**이미지**는 디스크 내용물(OS + 기본 설정)을 통째로 떠 놓은 **복사본 틀(거푸집)**입니다. VM을 만들 때 빈 디스크에 OS를 처음부터 설치하는 게 아니라 이 틀을 새 디스크에 찍어내며 시작합니다 — VM 생성이 1분 만에 끝나는 이유. 그래서 "클라우드 VM 이미지"라고 하면 "클라우드 업체가 VM을 찍어낼 때 쓰는 OS 디스크 틀"이라는 뜻입니다. 참고로 **Docker의 "이미지"도 같은 은유**입니다(틀→실행체: VM 이미지→VM, Docker 이미지→컨테이너). IT에서 "이미지"는 거의 항상 "실행 가능한 것의 복사본 틀"로 읽으면 됩니다.

**리전(region)**은 데이터센터가 있는 지역(서울, 오리건, 도쿄...), **존(zone)**은 그 안의 건물 단위입니다. 리전이 멀수록 응답이 느려집니다. GCP 무료 등급은 **미국 리전 3곳에서만** 적용되기 때문에 우리는 미국 서버를 쓰게 됩니다 (한국에서 접속 시 0.15~0.2초쯤의 지연 — 문서 열람 용도로는 체감이 크지 않습니다).

**SSH**는 원격 서버의 터미널을 안전하게(암호화) 여는 표준 방법입니다. 서버에는 화면이 없으므로 모든 조작을 SSH 터미널로 합니다.

**방화벽**은 "어떤 포트로 들어오는 연결을 허용할까"의 목록입니다. GCP는 기본적으로 SSH(22)만 열려 있고 나머지는 전부 차단 — 그래서 뒤에서 우리가 필요한 포트를 직접 열게 됩니다. 이게 학습 포인트입니다.

**docvault의 구조** 복습: Docker 컨테이너 하나에 앱 전부가 들어 있고, 데이터는 `data/` 폴더 하나에 모입니다. 그래서 어떤 서버로 가든 절차는 늘 같습니다: Docker 설치 → 코드 받기 → `.env` → `docker compose up`.

# 1. GCP 가입과 안전장치

## 1-1. 가입

1. https://cloud.google.com/free 접속 → **무료로 시작하기**
2. 구글 계정으로 로그인 → 국가 대한민국, 약관 동의
3. 카드 등록 (본인 확인용. **직접 업그레이드하기 전까지는 자동 청구되지 않습니다**)
4. 가입하면 **$300 크레딧(90일)**을 줍니다 — 이건 보너스고, 우리가 쓸 **Always Free(무기한 무료)** 등급은 크레딧 소진·만료와 무관하게 계속 무료입니다

> **Always Free 조건 (2026 기준, 반드시 이 조합이어야 무료):**
> - VM: **e2-micro** 1대
> - 리전: **us-west1(오리건) / us-central1(아이오와) / us-east1(사우스캐롤라이나)** 중 하나
> - 디스크: **표준 영구 디스크 30GB까지**
> - 트래픽: 월 1GB 무료 (문서 열람 용도로는 충분)
> 조건을 벗어나면(서울 리전, 더 큰 VM, SSD 등) 과금됩니다.

## 1-2. 프로젝트 만들기

> 배우는 것: GCP의 리소스 구조 — 모든 것은 "프로젝트" 안에 담긴다

GCP에서는 VM·방화벽·디스크 등 모든 리소스가 **프로젝트**라는 바구니 안에 만들어집니다. 그래서 어떤 메뉴를 눌러도 "이 페이지를 보려면 프로젝트를 선택하세요"가 먼저 나옵니다.

1. 그 안내 화면의 **프로젝트 만들기** 버튼 클릭 (또는 화면 상단 바의 프로젝트 선택 드롭다운 → 새 프로젝트)
2. 프로젝트 이름: `docvault` / 위치(조직): **조직 없음** 그대로 → **만들기**
3. 만들어지면 **상단 바의 드롭다운에서 `docvault`가 선택돼 있는지 확인** — 여기가 선택돼 있어야 이후 모든 메뉴가 이 프로젝트 기준으로 동작합니다

> 💡 나중에 실험이 끝나면 프로젝트를 통째로 삭제해서 안의 모든 리소스를 한 번에 정리할 수도 있습니다 (IAM 및 관리자 → 설정 → 종료).

## 1-3. 예산 알림부터 걸기 (요금 사고 방지 — 꼭 하세요)

1. 콘솔(https://console.cloud.google.com) 좌측 ☰ → **결제(Billing)** → **예산 및 알림(Budgets & alerts)**
2. **예산 만들기** → 이름 `안전장치`, 금액 **₩5,000** 정도
3. 알림 임계값 50%·90%·100% 기본값 그대로 → 저장

이러면 어떤 이유로든 요금이 발생하기 시작할 때 이메일이 옵니다. 참고로 외부 IP 주소에 소액(월 수천 원)이 과금되는 정책 변화가 있었으니, **첫 달에 결제 화면을 한 번 열어 실제 청구가 0원인지 확인**하는 습관을 들이세요. 요금이 보이면 그때 대응하면 됩니다(이 가이드 부록 참고).

# 2. VM 만들기

> 배우는 것: VM 생성 옵션 읽는 법 — 머신 종류, 이미지, 디스크

## 📚 학습 노트: 머신 패밀리 표 읽는 법

VM 만들기 화면의 시리즈 표(C4, N4, E2, T2A...)는 "어떤 성격의 컴퓨터를 빌릴 거냐"의 메뉴판입니다. 상단 탭이 대분류:

| 대분류 | 뜻 | 대표 시리즈 | 언제 쓰나 |
|---|---|---|---|
| **범용** | CPU·메모리 균형형 | E2(저가형), N 계열(균형), C 계열(고성능) | 웹서버, 일반 앱 — 대부분 여기 |
| **컴퓨팅 최적화** | CPU 성능 특화 | C2, H3 | 게임 서버, 과학 계산 |
| **메모리 최적화** | 램 수백 GB~TB | M 계열 | 대형 DB, 인메모리 분석 |
| **스토리지 최적화** | 디스크 IO 특화 | Z 계열 | 대용량 DB |
| **GPU/TPU** | 그래픽·AI 가속기 | A 계열, G 계열 | 딥러닝, 렌더링 |

범용 안에서의 서열은 대략 **E2(싸다) < N 계열(균형) < C 계열(빠르다)**. 시리즈 이름 뒤 숫자는 세대(N4가 N2보다 최신), `A`가 붙으면 ARM CPU(T2A, C4A — 인텔/AMD가 아닌 구조라 일부 프로그램 호환 주의), `D`는 AMD CPU라는 뜻입니다.

우리가 고르는 **e2-micro**는 "E2 시리즈의 최소형"입니다. `micro < small < medium < standard-2 < ...` 순으로 커지고, micro/small/medium은 **공유 코어**(물리 CPU를 다른 고객과 나눠 쓰고, 짧은 순간만 최대 성능을 내는 방식)라 쌉니다. 문서 서버처럼 대부분의 시간 한가한 워크로드에 딱 맞는 구조예요.

1. 콘솔 ☰ → **Compute Engine → VM 인스턴스**
   - 처음이면 **"사용(Enable)"** 버튼이 나옵니다 → 클릭
   - 누르면 "Compute Engine API 제품 세부정보" 페이지로 이동하는데 **정상입니다.** 이 페이지에서는 아무것도 안 해도 됩니다 ("API 사용해 보기" 버튼이 보이면 활성화된 것)
   - 다시 ☰ → **Compute Engine → VM 인스턴스**로 들어가면 됩니다 (활성화 직후 1~2분 로딩될 수 있음)
2. **인스턴스 만들기** 클릭
3. 새 콘솔 UI는 **왼쪽 사이드바의 단계 탭**(머신 구성 → OS 및 스토리지 → 데이터 보호 → 네트워킹...)으로 나뉘어 있습니다. 탭별로 설정:

**① 머신 구성 탭**

| 항목 | 값 | 왜? |
|---|---|---|
| 이름 | `docvault` | 아무거나 |
| 리전 | **us-west1 (오리건)** | 무료 리전 중 한국에서 제일 가까움 |
| 존 | 아무거나 (us-west1-b 등) | |
| 머신 시리즈 | **E2** ("저렴한 비용, 일상적인 컴퓨팅 처리") 라디오 선택 | |
| 머신 유형 | "사전 설정" 드롭다운에서 **e2-micro (vCPU 2개, 코어 1개, 메모리 1GB)** | 무료 대상은 e2-micro뿐 |
| 프로비저닝 모델 | **표준** (기본값 그대로) | "스팟"은 싸지만 구글이 예고 없이 VM을 끌 수 있는 조건 — 상시 서버엔 부적합하고, 무료 등급도 표준에만 적용됨 |

**② OS 및 스토리지 탭** — "변경" 버튼 클릭

| 항목 | 값 | 왜? |
|---|---|---|
| 운영체제 | **Ubuntu** (기본값 Debian에서 변경) | |
| 버전 | **Ubuntu 24.04 LTS (x86/64)** — 이름에 **"Minimal"이 붙지 않은 것** | Minimal은 이미지 용량을 줄이려고 기본 도구(문서, 편의 명령 등)를 뺀 축소판. 자동화된 대량 서버용이라, 직접 들어가 배우는 용도로는 일반판이 낫다 |
| 부팅 디스크 유형 | **표준 영구 디스크** | 기본값(균형=SSD)으로 두면 과금! |
| 크기 | **30** GB | 무료 한도 최대치 |

바꾼 뒤 우측 "월별 예상 가격" 표에서 **"30GB 표준 영구 디스크 — US$0.00"**을 확인하세요. 무료 조건이 맞았다는 증거입니다.

이 화면의 나머지: **추가 디스크**(데이터용 디스크를 더 붙이는 것 — 불필요), **컨테이너 배포**(VM 하나에 컨테이너 하나를 자동 실행하는 기능인데 "사용 중지됨" 표시 그대로 무시 — 우리는 compose로 여러 컨테이너를 직접 관리합니다)는 건드리지 않습니다.

**③ 데이터 보호 탭** — **"백업 없음"** 선택 ⚠️ 스냅샷 일정이 켜져 있으면 **과금됩니다.** 백업은 우리가 직접 합니다(9장)

> 📚 이 탭의 선택지들: **백업 계획**(별도 Backup 서비스가 VM 통째로 정기 백업 — 유료), **스냅샷 일정**(디스크만 정기 백업 — 유료), **복제**(동기/비동기 — 디스크를 다른 존·리전에 실시간 복사해 재해에 대비하는 기업용 기능, 당연히 유료). 전부 "돈 내고 안심을 사는" 옵션들이고, 우리는 `data/` 폴더 백업 스크립트로 충분합니다. **복제 체크박스들도 모두 해제** 상태 유지.

**④ 네트워킹 탭** — 방화벽 체크박스 3개(**HTTP 허용 / HTTPS 허용 / 부하 분산기 상태 점검 허용**) **모두 체크 안 함** (7장에서 방화벽 규칙을 직접 만들며 배웁니다)

> 📚 이 탭의 나머지 항목: **네트워크 태그**(방화벽 규칙을 특정 VM에만 적용할 때 붙이는 꼬리표 — 7장 학습 노트 참고, 지금은 빈칸), **호스트 이름**(VM 내부에서 부를 이름 — 기본값), **IP 전달**(이 VM을 라우터처럼 쓸 때만 — 해제), **Tier_1 네트워킹**(고대역폭 유료 옵션 — 해제), **부하 분산기**(트래픽을 여러 서버에 나누는 장치 — 서버가 한 대라 무관). 전부 기본값 그대로.

**⑤ 모니터링 가능성 탭** — ⚠️ **"모니터링 및 로깅을 위한 운영 에이전트 설치" 체크를 해제**하세요 (기본이 체크됨!)

> 📚 **운영 에이전트(Ops Agent)**는 VM 안에서 로그·CPU·메모리 지표를 수집해 GCP 콘솔의 Monitoring/Logging 화면으로 보내주는 프로그램입니다. 편하지만 ① 수집량이 무료 한도를 넘으면 **과금**되고(우측 가격표의 "로깅 및 모니터링" 항목이 이것) ② 에이전트 자체가 램을 100MB 안팎 상시 사용하는데 우리 서버는 램이 1GB뿐입니다. 서버 상태는 SSH에서 `docker compose logs`, `free -h`, `df -h`로 직접 보는 걸로 충분하고, 그게 학습에도 낫습니다. **디스플레이 기기**(GUI 화면 캡처용)도 해제 유지.

**⑥ 보안 탭** — 전부 기본값 그대로

> 📚 뭐가 있는지만 알아두기: **서비스 계정**은 "이 VM이 다른 GCP 서비스를 호출할 때 쓰는 신분증"입니다(IAM의 세계 — 우리 앱은 GCP API를 안 쓰므로 기본값 무관). **액세스 범위**는 그 신분증의 권한 범위("기본 액세스 허용" 유지). **보안 VM** 항목의 vTPM·무결성 모니터링(체크됨)은 부팅 과정이 변조되지 않았는지 하드웨어 수준에서 검증하는 기능 — 무료고 이로우니 그대로. **컨피덴셜 VM**(실행 중 메모리까지 암호화하는 기업용 — e2에선 비활성)은 무시.

**⑦ 고급 탭** — 전부 기본값 그대로

> 📚 훑어보기: **삭제 보호**(실수로 VM을 지우는 것 방지 — 켜도 좋지만 지울 때 해제해야 해서 기본 유지), **예약**(reservation — 용량을 미리 사두는 기업 기능, "사용 안 함" 유지), **시작 스크립트**(VM이 부팅될 때마다 자동 실행할 명령 — 나중에 "부팅하면 자동으로 docker compose up"을 넣는 자동화가 가능한 자리라고 기억해 두세요), **메타데이터**(VM에 붙이는 키-값 설정), **데이터 암호화**(디스크는 기본으로 구글 관리 키로 항상 암호화됨 — "Google 관리 암호화 키" 유지. Cloud KMS는 열쇠를 직접 관리하려는 기업용), **단독 테넌시**(물리 서버를 통째로 전세 내는 것 — 무관).

> 💡 우측의 월별 예상 가격(US$7~8)은 **무료 등급 할인이 반영되지 않은 표시 가격**입니다. 조건(e2-micro + 무료 리전 + 표준 디스크)이 맞으면 청구 시 자동 차감되어 실제 0원이 됩니다.

## 📚 학습 노트: 디스크 종류

부팅 디스크 "변경" 화면에서 보게 되는 유형들:

| 유형 | 정체 | 특징 |
|---|---|---|
| **표준 영구 디스크** (pd-standard) | HDD | 제일 쌈. **무료 등급 대상은 이것만** |
| 균형 있는 영구 디스크 (pd-balanced) | 보급형 SSD | VM 만들기의 **기본값** — 그대로 두면 과금됨 |
| SSD 영구 디스크 (pd-ssd) | 고성능 SSD | DB 서버용 |
| 익스트림/하이퍼디스크 | 초고성능 | 대규모 서비스용 |

"영구(persistent)"는 VM을 꺼도 내용이 남는다는 뜻입니다(반대 개념: VM 종료와 함께 사라지는 로컬 SSD). 디스크 성능은 **IOPS**(초당 읽기·쓰기 횟수)로 재는데, 우리 용도(가벼운 SQLite + 파일 몇 개)는 HDD로도 남습니다.

## 📚 학습 노트: 리눅스 배포판 — Debian, Ubuntu, 그리고 버전 숫자

**배포판(distribution)이란?** 리눅스는 엄밀히는 "커널"(하드웨어를 다루는 핵심)만을 말합니다. 그 커널에 패키지 관리자·기본 프로그램·설정을 얹어 완성품으로 묶은 것이 배포판이고, Debian·Ubuntu·CentOS·Alpine 등이 전부 이 완성품들입니다. 핵심은 같아서 명령어 대부분이 통하지만, 패키지 관리 방식과 릴리스 정책이 다릅니다.

**Debian vs Ubuntu — 사실 부모 자식 관계입니다:**

| | Debian | Ubuntu |
|---|---|---|
| 정체 | 1993년부터 순수 커뮤니티가 만드는 원조 배포판 | **Debian을 기반으로** Canonical사가 다듬은 파생판 |
| 성향 | 극도로 보수적·안정 지향, 검증된 옛 버전 선호 | 최신 소프트웨어를 비교적 빨리 수용, 초보자 배려 |
| 자료량 | 많음 | **압도적으로 많음** — 에러 검색하면 답이 제일 잘 나옴 |

GCP 기본값이 Debian인 이유는 구글이 가볍고 보수적인 걸 선호해서인데, 사실 **Debian으로도 이 가이드는 거의 그대로 동작합니다** (둘 다 `apt`를 씁니다). 그래도 Ubuntu로 바꾸는 이유는 하나 — **배우는 입장에서 검색했을 때 나오는 자료의 양**이 다릅니다. 튜토리얼·스택오버플로 답변 대부분이 Ubuntu 기준이에요.

**버전 숫자 읽는 법**: Ubuntu는 `연도.월` 형식입니다 — **22.04 = 2022년 4월 출시**. 매년 4월·10월에 새 버전이 나오고, 그중 **짝수 해 4월판(20.04, 22.04, 24.04...)만 LTS**(Long Term Support, 5년 보안 패치 보장)입니다. 나머지는 9개월 만에 지원이 끝나요. **서버는 항상 LTS를 씁니다** — 홀수 버전을 서버에 깔면 1년도 안 돼 보안 패치가 끊깁니다. 22.04와 24.04 둘 다 LTS라 어느 쪽도 괜찮고, 이 가이드는 콘솔 기본으로 제시되는 **24.04 LTS** 기준입니다.

**x86/64 vs ARM64**는 CPU의 언어(명령어 집합) 차이입니다. 인텔·AMD가 x86, 애플 M칩·그래비톤이 ARM. 프로그램은 CPU 언어에 맞게 빌드돼야 하므로 **VM의 CPU와 이미지가 일치해야** 합니다 — e2-micro는 인텔이니 x86/64.

**부팅 디스크 유형과 크기를 왜 그렇게 정했나**: 유형은 위의 "디스크 종류" 노트대로 무료 대상이 표준(HDD)뿐이기 때문이고, 크기 30GB는 **무료 한도의 최대치**를 그냥 다 받는 겁니다 (OS가 ~8GB를 쓰고 나머지가 문서·백업 공간 — docvault는 텍스트 위주라 사실 이걸 다 쓰기도 어렵습니다). 참고로 영구 디스크는 나중에 **늘릴 수는 있어도 줄일 수는 없습니다.**

4. **만들기** → 1분쯤 후 목록에 초록불과 함께 **외부 IP**가 표시됩니다 (예: `34.83.xx.xx`). 메모해 두세요.

> 💡 존이 "리소스 부족" 오류를 내면 같은 리전의 다른 존으로 바꿔 재시도하세요.

## 📚 학습 노트: 내부 IP와 외부 IP

VM 목록을 보면 IP가 두 개입니다:

- **내부 IP** (10.x.x.x): GCP 데이터센터 안의 사설망 주소. 같은 VPC 안의 VM끼리만 통함
- **외부 IP** (34.x.x.x 등): 인터넷에서 접근하는 공인 주소. 기본은 **임시(ephemeral)** — VM을 중지했다 시작하면 바뀔 수 있음

외부 IP를 **고정(static)으로 예약**할 수도 있지만(VPC 네트워크 → IP 주소), 우리는 7장에서 DDNS로 "IP가 바뀌면 도메인이 따라가게" 만들 것이므로 임시로 충분합니다. 집 인터넷도 사실 임시 공인 IP를 받는 같은 구조입니다.

# 3. SSH로 서버 접속

> 배우는 것: 원격 서버에 들어가는 두 가지 방법

## 방법 A. 브라우저 SSH (제일 쉬움 — 처음엔 이걸로)

VM 목록에서 해당 줄의 **SSH** 버튼 클릭 → 새 창에 검은 터미널이 뜨면 성공. 키 관리를 구글이 대신 해줘서 설정이 필요 없습니다.

## 방법 B. 내 PC의 PowerShell에서 (익숙해지면)

**준비물 없음** — Windows 10/11은 SSH 도구(OpenSSH)를 기본 내장하고 있어서, 아무 PowerShell 창(관리자 권한 불필요, 아무 폴더에서나)에서 바로 진행하면 됩니다.

```powershell
# 1) SSH 키 생성 (최초 1회. 질문 3개 — 저장 위치, 암호 2번 — 는 전부 그냥 Enter)
#    열쇠 한 쌍이 C:\Users\내이름\.ssh\ 에 자동 생성된다
ssh-keygen -t ed25519

# 2) 공개키(자물쇠) 출력 → 나온 한 줄 전체를 복사
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
```

복사한 내용을 GCP 콘솔에 등록합니다 (자물쇠를 서버에 걸어두는 단계 — 이것만이 콘솔에서 할 일):
**Compute Engine → 설정의 "메타데이터" → SSH 키 탭 → 항목 추가** → 붙여넣기 → 저장.

```powershell
# 3) 접속. "이름"은 복사했던 공개키 맨 끝 `이름@PC이름`의 @ 앞부분
ssh 이름@34.83.xx.xx
```

첫 접속 때 `Are you sure you want to continue connecting?` 이 나오면 `yes` (처음 보는 서버의 지문을 기억해 두겠냐는 확인 — 다음부터 안 물어봅니다).

> **개념**: SSH 키는 자물쇠(공개키)와 열쇠(개인키) 한 쌍입니다. 자물쇠는 서버에 걸어두고 열쇠는 내 PC에만 있습니다. 비밀번호와 달리 유출·추측이 사실상 불가능합니다. **개인키(id_ed25519) 파일은 절대 아무에게도 보내지 마세요.**

# 5. 스왑 추가 — 작은 서버의 필수 작업

> 배우는 것: 메모리 부족을 디스크로 버티는 스왑(swap)의 개념, OOM Killer, /etc/fstab

## 📚 학습 노트: 스왑이 뭐고 왜 필수인가

프로그램은 데이터를 **RAM**(빠르지만 작음)에 올려놓고 일합니다. **스왑**은 RAM이 꽉 찼을 때 당장 안 쓰는 내용물을 **디스크에 잠시 내려놓는 비상 공간**입니다 — RAM이 책상이라면 스왑은 넘칠 때 쓰는 서랍.

스왑이 없는 상태에서 RAM이 바닥나면 리눅스는 **OOM Killer**(Out Of Memory Killer)를 발동해 메모리를 많이 쓰는 프로세스를 **강제 종료**합니다. e2-micro는 RAM 1GB뿐인데 Docker 빌드는 순간적으로 그 이상을 요구하므로, 스왑 없이는 빌드가 에러 설명도 없이 `Killed` 한 마디로 죽습니다. 스왑 2GB를 붙이면 초과분이 디스크로 밀려나 느릴지언정 완주합니다.

알아둘 것 두 가지: ① 클라우드 VM 이미지에 스왑이 기본으로 없는 건 "느려지느니 죽고, 더 큰 VM으로 올려라"는 클라우드식 철학 때문입니다. ② 스왑은 디스크라 RAM보다 수백 배 느립니다 — **성능 확장이 아니라 "죽지 않기 위한 보험"**이고, 평소 운영 중에도 스왑 사용량이 계속 높다면 서버가 진짜 좁다는 신호입니다. 2GB라는 크기는 "RAM의 2배" 전통 공식이며 30GB 디스크에 부담 없는 값입니다.

```bash
sudo fallocate -l 2G /swapfile         # 디스크에 2GB 빈 파일 확보 (-l = length)
sudo chmod 600 /swapfile               # root만 읽고 쓰게 — 스왑엔 메모리 내용(비밀번호 등)이
                                       # 내려앉을 수 있어 남이 읽으면 보안 구멍
sudo mkswap /swapfile                  # 파일을 스왑 형식으로 포맷 (make swap)
sudo swapon /swapfile                  # 지금 즉시 활성화 (swap on)
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
# /etc/fstab은 "부팅 때 자동 연결할 저장장치 목록" — 이 줄이 없으면 재부팅 시 스왑이 사라진다.
# `sudo echo >> 파일`은 권한 문제로 안 되기 때문에 `| sudo tee -a`(관리자 권한으로 끝에 추가)를 쓴다

free -h    # Swap 줄에 2.0Gi가 보이면 성공 (-h = 사람이 읽기 좋은 단위)
```

## 📚 학습 노트: 명령어 한 줄씩 완전 해부

리눅스 명령은 대부분 **`명령어 [옵션] [인자]`** 구조입니다. 이 틀로 위 여섯 줄을 뜯어봅니다.

### 1) `sudo fallocate -l 2G /swapfile`

- **`sudo`**: "superuser do" — 관리자(root) 권한으로 실행. 스왑은 시스템 전체에 영향을 주는 설정이라 필요
- **`fallocate`**: "file allocate" — 파일에 디스크 공간을 미리 확보
- **`-l 2G`**: `-l`은 length(길이) 옵션, `2G`는 그 값 (2기가바이트)
- **`/swapfile`**: 만들 파일의 경로. `/`로 시작하므로 최상위에 생성. 이름은 임의지만 관례적으로 이렇게 씀

**왜 빠른가**: 옛 방식 `dd if=/dev/zero of=/swapfile bs=1M count=2000`은 0이라는 데이터를 실제로 2GB어치 써 넣어서 느립니다. `fallocate`는 파일시스템에 "이만큼 예약해 둬"라고 지시만 하므로 즉시 끝납니다.

### 2) `sudo chmod 600 /swapfile`

- **`chmod`**: "change mode" — 파일 접근 권한 변경
- **`600`**: 세 자리가 순서대로 **소유자 / 그룹 / 그 외 모든 사람**의 권한. 각 자리는 읽기 4 + 쓰기 2 + 실행 1의 합

`600`을 풀면: 소유자 `6`=4+2(읽고 쓰기), 그룹 `0`(없음), 그 외 `0`(없음) → **"소유자(root)만 읽고 쓴다."** 자주 보는 값: `644`(남은 읽기만 — 일반 파일 기본), `755`(남은 읽기+실행 — 폴더·프로그램), `700`(나만 전부).

**왜 잠그는가**: 스왑엔 실행 중인 프로그램의 메모리 내용이 그대로 내려앉을 수 있고, 거기엔 비밀번호·토큰이 들어 있을 수 있습니다. 남이 읽으면 그대로 유출이라 관리자 전용으로 잠급니다.

**확인**: `ls -al /swapfile` 출력 앞의 `-rw-------`가 600의 문자 표기입니다 (rwx 3글자씩 소유자/그룹/그 외, `-`는 권한 없음).

### 3) `sudo mkswap /swapfile`

"make swap". 여기까지 `/swapfile`은 그냥 2GB짜리 빈 파일이었고, 커널이 스왑으로 인식할 형태가 아닙니다. `mkswap`이 내부에 스왑 전용 구조(헤더·서명)를 기록해 "이건 스왑용"이라고 알아보게 만듭니다. USB를 FAT32로 포맷해야 컴퓨터가 인식하는 것과 같은 원리 — "스왑 형식으로 포맷"입니다.

### 4) `sudo swapon /swapfile`

"swap on". 형식은 갖췄지만 아직 사용 중은 아닌 상태에서, 이 순간부터 커널이 실제 스왑으로 쓰기 시작합니다. 반대는 `swapoff /swapfile`.

여기까지의 흐름: **공간 확보(fallocate) → 잠금(chmod) → 형식 갖추기(mkswap) → 사용 시작(swapon)**. 단, swapon은 "지금"만 유효 — 재부팅하면 풀리므로 다음 줄이 필요합니다.

### 5) `echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab`

두 부분으로 나눠서 봅니다.

**앞: `echo '...'`** — 문자열을 그대로 출력하는 명령. 출력하려는 내용이 fstab 형식의 한 줄이고, 공백으로 나뉜 6칸입니다:

| 칸 | 값 | 의미 |
|---|---|---|
| 1 | `/swapfile` | 대상 장치(파일) |
| 2 | `none` | 마운트 위치 — 스왑은 폴더에 마운트되는 개념이 아니라서 none |
| 3 | `swap` | 파일시스템 종류 |
| 4 | `sw` | 옵션 (스왑 기본값) |
| 5 | `0` | dump 백업 여부 (안 함) |
| 6 | `0` | 부팅 시 검사 순서 (스왑은 검사 대상 아님) |

일반 디스크라면 `/dev/sdb1 /data ext4 defaults 0 2`처럼 실제 마운트 위치와 파일시스템이 들어갑니다.

**뒤: `| sudo tee -a /etc/fstab`**

- **`|` (파이프)**: 왼쪽 명령의 출력을 오른쪽 명령의 입력으로 넘기는 기호. echo가 만든 문자열이 화면 대신 tee에게 전달됨. 앞으로 계속 만나는 핵심 문법 (`docker compose logs | grep error` 식)
- **`tee`**: 입력받은 내용을 **화면에도 보여주면서 동시에 파일에도 쓰는** 명령. 수도관이 갈라지는 T자 이음관에서 온 이름
- **`-a`**: append — 덮어쓰지 않고 파일 끝에 추가
- **`/etc/fstab`**: 부팅 때 자동 연결할 저장장치 목록 파일

**왜 `sudo echo '...' >> /etc/fstab`은 안 되나**: `>>`(파일 끝에 추가하는 리다이렉션)는 sudo가 아니라 **내 일반 사용자 셸이** 처리합니다. sudo는 echo 하나에만 권한을 줄 뿐 `>>` 쓰기 작업엔 전달되지 않아서, root 소유인 fstab에 Permission denied가 납니다. 그래서 파일 쓰기를 담당할 별도 프로그램(tee)을 sudo로 실행시키는 관용구를 쓰는 겁니다 — echo는 문자열만 만들고, 권한이 필요한 "쓰기"는 sudo tee가 담당.

### 6) `free -h`

- **`free`**: RAM과 스왑 사용 현황 표시
- **`-h`**: human-readable — KB 단위 큰 숫자 대신 `2.0Gi`, `512Mi`처럼 변환

```
              total        used        free      shared  buff/cache   available
Mem:           1.0Gi       300Mi       200Mi        10Mi       500Mi       600Mi
Swap:          2.0Gi          0B       2.0Gi
```

`Swap` 줄의 total이 `2.0Gi`면 등록·활성화 모두 성공입니다. 참고로 `buff/cache`는 리눅스가 남는 램을 디스크 캐시로 활용 중인 것이라 "낭비"가 아니고, 실제 여유는 `available`을 보면 됩니다.

# 6. Docker 설치 + docvault 실행

## 📚 학습 노트: Docker 제대로 이해하기 — 왜 "VM 위에 Docker"인가

**VM과 Docker는 서로 다른 층의 선택입니다.** VM은 "컴퓨터를 빌리는 방법"이고, Docker는 "그 컴퓨터 위에서 앱을 포장·실행하는 방법". 독립적이라 조합이 자유롭습니다 — Docker 없이 VM에 Node를 직접 설치할 수도 있고(전통 방식), VM 없이 컨테이너만 맡기는 서비스도 있습니다. 즉 "도커라서 VM을 쓰는 것"이 아니라, 각각 따로 고른 겁니다.

**Docker를 쓰는 이유**: 앱+실행환경(Node 버전, 라이브러리, 빌드 도구)을 통째로 포장해서 **어느 컴퓨터로 가든 명령 하나로 똑같이 돌기 때문**입니다. 이 가이드에서 Windows PC와 GCP 우분투 양쪽 모두 `docker compose up` 한 줄로 끝나는 게 그 증거입니다. Docker가 없다면 서버를 옮길 때마다 Node 설치·버전 맞추기·네이티브 모듈 빌드 도구 설치를 반복해야 합니다.

**VM을 쓰는 이유** — GCP에서 앱을 돌리는 방식은 여러 층이 있습니다:

| 방식 | 개념 | 우리에게 맞나 |
|---|---|---|
| **VM** (Compute Engine, IaaS) | 컴퓨터를 통째로 빌림 — 자유도 최대, 관리도 내 몫 | ✅ Always Free + **디스크에 데이터를 상시 보관**해야 하는 앱에 적합 + 리눅스 학습 |
| Cloud Run (서버리스 컨테이너) | 컨테이너만 주면 구글이 실행·자동 확장 | ❌ 요청 없으면 껐다 켜는 **무상태** 모델 — 로컬 SQLite·파일을 쓰는 docvault와 상극 |
| GKE (쿠버네티스) | 컨테이너 수백 개의 오케스트레이션 | ❌ 앱 하나엔 과잉, 유료 |
| App Engine (PaaS) | 코드만 주면 실행 | ❌ 제약 많음 |

**VM vs 컨테이너 — 격리의 깊이 차이**: VM은 하드웨어부터 "컴퓨터인 척"을 통째로 하는 무거운 격리(부팅에 분 단위), 컨테이너는 호스트의 리눅스 커널을 공유하면서 프로세스만 격리하는 가벼운 격리(시작에 초 단위)입니다. 지금 우리 구조는 구글 물리 서버 → VM(하드웨어 가상화) → 컨테이너(OS 수준 격리)의 **가상화 두 겹**인데, 컨테이너가 가벼워서 겹쳐도 부담이 적습니다.

**우리 Dockerfile은 멀티스테이지**: 저장소의 `Dockerfile`을 열어 보면 스테이지가 둘입니다 — ① build 스테이지: 개발 도구를 다 깔고 클라이언트를 빌드 ② 런타임 스테이지: 빌드 결과물만 복사해 담은 **가벼운 최종 이미지**. 빌드 도구를 최종 이미지에 남기지 않아 용량·보안 모두 이득을 보는 표준 패턴입니다.

## 📚 학습 노트: Docker 용어 4개

- **이미지(image)**: 프로그램+실행환경을 구운 "설치 CD". `docker compose build`가 만드는 것
- **컨테이너(container)**: 이미지를 실제로 실행한 "돌아가는 인스턴스". 하나의 이미지로 컨테이너 여러 개를 띄울 수 있음
- **볼륨/바인드 마운트**: 컨테이너는 지우면 안의 파일도 사라지므로, 남겨야 할 데이터는 호스트 폴더에 연결해 둠. docvault의 `./data:/app/data`가 그것 — 그래서 컨테이너를 지워도 데이터가 남습니다
- **컴포즈(compose)**: 컨테이너 여러 개(앱+Caddy 등)의 구성을 `docker-compose.yml` 한 파일로 선언하고 `docker compose up` 한 방에 올리는 도구

> **어디에 입력하나**: 이 장의 모든 명령은 5장까지 쓰던 **그 SSH 터미널(서버 안)**에 한 줄씩 이어서 입력합니다.

```bash
# Docker 공식 설치 스크립트
curl -fsSL https://get.docker.com | sudo sh

# 내 계정이 sudo 없이 docker를 쓸 수 있게 그룹에 추가
sudo usermod -aG docker $USER
exit    # 그룹 적용을 위해 나갔다가
```

`exit`을 치면 **SSH 접속이 끊기며 터미널이 닫히는데, 정상입니다.** 그룹 추가는 "다음 로그인부터" 적용되기 때문에 일부러 나가는 것입니다. **다시 접속**(브라우저 SSH면 콘솔에서 SSH 버튼 재클릭, PowerShell이면 `ssh 이름@IP` 재실행)한 뒤, 아래 블록을 같은 방식으로 이어서 입력합니다.

### 📚 학습 노트: 설치 명령 해부

**`curl -fsSL https://get.docker.com | sudo sh`**

- **`curl`**: URL의 내용을 내려받는 명령. 여기서는 get.docker.com이 주는 **설치 스크립트(셸 명령 뭉치 텍스트)**를 받아옵니다
- 옵션 4개를 뭉친 **`-fsSL`**: `-f`(fail — 서버 오류 시 오류 페이지 내용 대신 실패 처리), `-s`(silent — 진행률 숨김), `-S`(show error — 조용히 하되 에러는 표시), `-L`(location — 리다이렉트를 따라감). 설치 스크립트를 받을 때의 관용 조합
- **`| sudo sh`**: 받아온 스크립트 텍스트를 파이프로 **sh(셸 해석기)에 관리자 권한으로 먹여 바로 실행**. "인터넷에서 받은 걸 곧장 root로 실행"하는 패턴이라 원래는 신중해야 하며, Docker 공식 도메인이라서 신뢰하고 쓰는 것입니다 — 아무 사이트에나 이 패턴을 쓰면 안 됩니다

**`sudo usermod -aG docker $USER`**

- **`usermod`**: user modify — 사용자 계정 속성 변경
- **`-aG docker`**: `-G`는 소속 그룹 지정, `-a`는 append(기존 그룹 유지한 채 추가). **`-a` 없이 `-G`만 쓰면 기존 그룹이 전부 교체되어 날아가는 유명한 함정**이 있습니다
- **`$USER`**: 셸이 "현재 로그인한 내 계정명"으로 치환하는 **환경 변수**. 직접 계정명을 써도 되지만 이렇게 쓰면 누구나 복붙 가능
- **왜 하나**: Docker 데몬(상시 실행되는 본체)은 root 권한으로 돕니다. `docker` 그룹에 든 사용자는 sudo 없이 그 데몬에 명령을 보낼 수 있어서, 매번 `sudo docker ...`를 칠 필요가 없어집니다

**`exit`**: 현재 셸 종료 = SSH 접속 종료. 그룹 소속은 **로그인하는 시점에 결정**되므로, 나갔다 들어와야 새 그룹이 반영됩니다.

**설치 출력 읽는 법** — 성공했다면 이런 신호들이 보입니다:

- `Using systemd to manage Docker service` / `Docker daemon enabled and started`: 데몬이 설치·시작됐고 **재부팅 시 자동 시작**으로 등록됨 (`systemctl enable --now`의 결과 — enable=부팅 자동 시작, --now=지금 시작)
- `Client:`와 `Server:` 양쪽에 버전 표시: Docker는 **명령어(Client) + 데몬(Server)** 구조인데 둘 다 정상 응답했다는 확인
- 끝의 rootless mode 안내와 `WARNING: ... equivalent to root access`는 **에러가 아니라 정보성 안내**입니다. "docker 그룹 권한 = 사실상 root"라는 보안 상식을 알려주는 것 — 혼자 쓰는 서버라 표준 방식(usermod)으로 진행하면 됩니다

다시 SSH 접속 후:

```bash

# 코드 받기 + 설정

echo "JWT_SECRET=$(openssl rand -hex 32)" > .env

# ↑ "초기비밀번호로바꾸세요" 자리에 원하는 비밀번호(8자 이상)를 넣어 실행.
#   셸이 $ ` " ! 같은 특수문자를 해석해버리므로 영문+숫자 조합 권장 (복잡한 비밀번호는 로그인 후 앱 설정에서).
```

### 📚 학습 노트: 실행 블록 해부

- **`git clone 주소`**: 깃허브의 저장소(코드 전체 + 변경 이력)를 서버에 복제. 실행하면 현재 위치에 `docvault` 폴더가 생기고, `cd docvault`로 그 안에 들어갑니다
  - ⚠️ **`Username for 'https://github.com':` 이 뜬다면** 저장소가 비공개(private)라 인증을 요구하는 것입니다. 깃허브는 비밀번호 인증을 폐지해서 여기에 계정 비밀번호를 쳐도 실패합니다. **Ctrl+C로 취소**하고 둘 중 하나를 선택:
    - **(추천) 저장소를 public으로 전환** — 저장소 Settings → Danger Zone → Change visibility. `.env`와 `data/`는 gitignore라 저장소에 비밀이 없으므로 안전하고, 이후 clone/pull에 인증이 아예 필요 없어집니다
    - **비공개 유지** — 깃허브 Settings → Developer settings → **Fine-grained token** 발급(해당 저장소만, Contents: Read-only) 후 Username엔 깃허브 아이디, Password엔 **토큰**을 입력 (붙여넣어도 화면에 안 보이는 게 정상). 단 pull 때마다 다시 물어봅니다
- **`echo "JWT_SECRET=$(openssl rand -hex 32)" > .env`** — 세 가지가 겹쳐 있습니다:
  - **`$(명령)`**: **명령 치환** — 괄호 안 명령을 먼저 실행하고 그 출력으로 바꿔치기하는 셸 문법. 앞서 본 `$USER`(변수 치환)의 명령 버전
  - **`openssl rand -hex 32`**: openssl(암호학 도구 모음)로 **난수 32바이트**를 만들어 16진수(hex) 64글자로 출력 — 사람이 못 추측하는 비밀 키 생성의 표준 방법
  - **`>` vs `>>`**: `>`는 파일을 **새로 만들거나 덮어쓰고**, `>>`는 **끝에 추가**. 그래서 첫 줄은 `>`(파일 생성), 둘째 줄(ADMIN...)은 `>>`(추가)를 씁니다. 여기선 내 홈 폴더의 내 파일이라 sudo tee가 필요 없습니다
- **`docker compose up -d --build`**: compose 구성(docker-compose.yml)대로 컨테이너들을 올리는 명령. `--build`는 "이미지를 먼저 (다시) 빌드하고", `-d`는 detached — **백그라운드로 실행**해서 터미널을 돌려받습니다 (-d 없이 실행하면 로그가 화면을 점유하고, Ctrl+C 하면 컨테이너도 꺼짐)
- **`curl http://localhost:3000/...`**: 이번엔 curl을 다운로드가 아니라 **API 호출 테스트**로 쓴 것. `localhost`는 "이 컴퓨터 자신"이라는 뜻의 예약된 이름이라, 방화벽과 무관하게 서버 내부에서의 동작만 확인합니다

### ⚠️ 학습 노트: `!` 히스토리 확장 함정 (실전에서 실제로 겪은 사고)

bash에서 **`!`는 히스토리 확장 트리거**입니다 — `!!`는 "직전 명령 전체", `!$`는 "직전 명령의 마지막 인자"로 **치환**됩니다. 문제는 이 확장이 **큰따옴표(`"`) 안에서도 일어난다**는 것. 예를 들어 비밀번호에 `!!`를 넣어 `echo "...uss02039!!" >> .env`를 실행하면, bash가 `!!` 자리에 직전 명령 문자열을 통째로 끼워 넣어 `.env`에 깨진 값이 저장됩니다 (bash는 치환된 실제 명령을 한 줄 echo해서 보여주는데, 그게 이상하게 보이면 이 확장이 일어난 것).

- **막는 법**: **작은따옴표(`'...'`)는 모든 확장을 막습니다** — 특수문자가 든 문자열은 작은따옴표가 셸의 철칙
- **이미 사고가 났다면** (아직 내 데이터가 없는 첫 설치 시점 기준):

```bash
cat .env                                       # 깨진 줄 확인
docker compose down                            # 잘못된 값으로 admin이 시드됐을 수 있으니 정지
sudo rm -rf data                               # 갓 생긴 DB 삭제 → 다음 기동 때 재시드
sed -i '/^ADMIN_INITIAL_PASSWORD/d' .env       # 깨진 줄만 삭제 (sed -i = 파일을 제자리에서 수정, /패턴/d = 해당 줄 삭제)
echo 'ADMIN_INITIAL_PASSWORD=새비밀번호' >> .env   # 작은따옴표로!
docker compose up -d
```

여기까지 되면 **서버 안에서는** 돌고 있는 겁니다. 이제 밖에서 접속할 길을 뚫습니다.

# 7. 외부에서 접속하기

## 7-1. (학습용 워밍업) 방화벽으로 3000 포트 직접 열어보기

> 배우는 것: VPC 방화벽 규칙. HTTPS가 아니라서 확인 후 다시 닫을 겁니다.

### 📚 학습 노트: 방화벽 규칙의 구성 요소

- **VPC**(Virtual Private Cloud): 내 프로젝트 전용 가상 네트워크. VM들은 이 안에 살고, 방화벽은 이 네트워크의 출입문 규칙입니다
- **인그레스/이그레스**: 들어오는(ingress) / 나가는(egress) 트래픽. 보통 인그레스만 조입니다 (나가는 건 기본 허용)
- **소스 범위**: 누구한테 열어줄 것인가. `0.0.0.0/0`은 "전 세계 모든 IP"라는 뜻의 CIDR 표기 — 특정 집 IP만 허용하려면 `1.2.3.4/32`처럼 좁힐 수 있습니다
- **대상**: 규칙을 어떤 VM에 적용할까. "모든 인스턴스" 또는 VM에 붙인 **네트워크 태그**(예: `web-server` 태그 붙은 VM만)로 지정
- **우선순위**: 숫자가 낮을수록 먼저 평가. 기본 거부(65535)보다 낮은 숫자의 허용 규칙이 이기는 구조

GCP는 기본적으로 **SSH(22)를 제외한 모든 인그레스를 거부**합니다. "기본은 다 막고 필요한 것만 연다"(deny by default) — docvault 서버 코드의 인증 설계와 같은 철학입니다.

1. 콘솔 ☰ → **VPC 네트워크 → 방화벽** → **방화벽 규칙 만들기**
2. 실제 화면의 항목별 입력:

| 항목 | 값 | 설명 |
|---|---|---|
| 이름 | `allow-3000-test` | 소문자·숫자·하이픈만 허용 |
| 로그 | 사용 안함 (기본) | 켜면 로그 수집량만큼 Logging 비용 발생 가능 |
| 네트워크 | default (기본) | VM이 속한 기본 VPC |
| 우선순위 | 1000 (기본) | 낮을수록 먼저 평가 — 기본 거부(65535)보다 낮아 이 허용이 이긴다 |
| 트래픽 방향 | 인그레스 (기본) | 들어오는 트래픽 대상 |
| 일치 시 작업 | 허용 (기본) | |
| **대상** | 드롭다운을 **"네트워크의 모든 인스턴스"로 변경** | 기본값 "지정된 대상 태그"는 태그 붙은 VM에만 적용하는 방식 — VM이 하나라 전체 적용으로 |
| 소스 필터 | IPv4 범위 (기본) | |
| **소스 IPv4 범위** | `0.0.0.0/0` | 전 세계 모든 IP (CIDR 표기) |
| 프로토콜 및 포트 | 지정된 프로토콜 및 포트 → **TCP 체크, 포트 `3000`** | 여러 포트는 쉼표: `80,443` |

3. **만들기** 클릭
4. 내 PC 브라우저에서 `http://외부IP:3000` → 로그인 화면이 보이면 성공!
   - "외부IP" 자리엔 VM 목록의 **실제 숫자 IP**(예: `http://34.83.152.7:3000`)를 넣습니다 — 자리표시 글자를 그대로 치면 `DNS_PROBE_FINISHED_NXDOMAIN`(그런 이름 없음) 오류
   - **`http://`를 직접 붙여서** 입력 — 생략하면 브라우저가 https로 시도해 실패할 수 있음 (이 단계는 아직 HTTP)
5. 원리를 확인했으니 **규칙을 삭제**하세요 (목록에서 체크 → 삭제).

### 📚 학습 노트: 허용 규칙은 보호 장치가 아니라 "벽에 뚫은 문"이다

방화벽이 성벽이라면, **허용 규칙은 성벽에 낸 문**입니다. `allow-3000-test`를 만든 순간 전 세계 누구나 3000번 문까지 올 수 있게 된 것 — 규칙이 많을수록 안전해지는 게 아니라 **지켜야 할 문이 늘어나는** 겁니다. 그래서 대원칙은 "필요한 문만 최소한으로"(deny by default).

방금 만든 문을 닫는 이유 두 가지:

1. **평문(HTTP)이라서** — 3000번으로 오가는 로그인 비밀번호와 문서 내용이 암호화 없이 그대로 인터넷을 건넙니다. 경로 중간 어디서든 들여다볼 수 있습니다
2. **더 좋은 문으로 대체할 거라서** — 다음 단계에서 80·443을 열고 그 앞에 Caddy(문지기)를 세웁니다. 443은 HTTPS라 전 구간 암호화됩니다

"그럼 80·443도 구멍 아닌가?" — 맞습니다. 하지만 ① 암호화되고 ② 검증된 문지기(Caddy)가 지키고 ③ 그 뒤의 앱도 로그인을 요구하는 **통제된 구멍**입니다. 보안의 목표는 "구멍 0개"가 아니라 "모든 구멍이 통제된 상태"입니다.

## 7-2. (본편) 무료 도메인 + 자동 HTTPS — DuckDNS + Caddy

> 배우는 것: DNS, DDNS, 리버스 프록시, TLS 인증서 자동 발급
> 결과물: `https://내이름.duckdns.org` — 돈 한 푼 안 드는 고정 HTTPS 주소

**개념 먼저**: 도메인은 "IP 주소에 붙이는 이름표"(DNS)입니다. DuckDNS는 `xxx.duckdns.org` 서브도메인을 무료로 빌려주는 서비스이고, **Caddy**는 우리 서버 앞단에서 ① 도메인으로 온 요청을 앱에 전달(리버스 프록시)하고 ② HTTPS 인증서를 Let's Encrypt에서 자동 발급·갱신해 주는 웹서버입니다.

### 📚 학습 노트: 왜 이 조합인가 — 도메인의 필요성, DuckDNS와 Caddy의 선택 이유

**IP 그대로 쓰면 안 되나?** 세 가지 문제: ① VM 외부 IP는 임시라 재시작 시 바뀔 수 있고 ② HTTPS 인증서는 IP가 아니라 **도메인 앞으로** 발급되며 ③ 숫자 주소는 외워 쓸 수 없습니다. 그래서 "변하지 않는 이름"이 필요합니다.

**외부 접속 선택지 비교** — 왜 DuckDNS인가:

| 선택지 | 비용 | 특징 |
|---|---|---|
| **DuckDNS** | **0원** | 무료 서브도메인 + **DDNS 내장**(IP 변경을 스크립트로 자동 갱신) — 임시 IP 문제까지 함께 해결 |
| 도메인 구입 | 연 1~2만원 | 진짜 내 이름. 나중에 사면 Caddyfile의 도메인만 바꾸면 됨 |
| Cloudflare Tunnel | 0원 + 도메인비 | 포트를 아예 안 열어도 되는 방식이지만 유료 도메인이 전제 |
| Tailscale | 0원 | 고정 주소를 주지만 접속하는 기기마다 전용 앱 설치·로그인 필요 |

"돈 0원 + 아무 기기에서나 URL만으로 접속"을 동시에 만족하는 것이 DuckDNS뿐입니다. 트레이드오프는 주소가 `xxx.duckdns.org` 꼴이라는 것.

**Caddy는 뭐고 왜 Caddy인가**: 이 자리(리버스 프록시)의 전통 표준은 **Nginx**입니다. 그런데도 Caddy를 쓰는 이유는 **HTTPS 인증서의 발급·90일 갱신·HTTP→HTTPS 리다이렉트를 완전 자동으로** 처리해주기 때문 — 우리 설정 파일(저장소의 `Caddyfile`)은 "이 도메인으로 오면 app:3000에 넘겨라" 통째로 3줄입니다. Nginx로 같은 걸 하려면 certbot 별도 설치 + 갱신 cron + 설정 수십 줄이 필요하고, "인증서 만료 사고"는 그 방식의 고전적 함정입니다. (실무 비교는 부록 로드맵의 "Nginx vs Caddy" 참고)

### 📚 학습 노트: HTTPS와 인증서는 어떻게 공짜로 되나

- **HTTPS = HTTP + TLS 암호화.** 중간에서 훔쳐보거나(도청) 바꿔치기(변조)를 막습니다. 브라우저 자물쇠 아이콘이 이것
- **인증서**는 "이 도메인의 주인이 이 서버가 맞다"는 것을 **CA**(인증기관)가 서명한 문서입니다. 브라우저는 유명 CA 목록을 내장하고 있어 그 서명을 신뢰합니다
- **Let's Encrypt**는 무료 CA입니다. 돈 대신 **소유 증명**을 요구하는데, 방식이 "지금 그 도메인의 80 포트로 내가 접속해 볼 테니 내가 준 암호문을 보여줘라"(HTTP-01 챌린지)입니다 — **80 포트를 열어야 하는 이유**가 이것
- 인증서는 90일짜리라 갱신이 필요한데, Caddy가 만료 전에 알아서 다시 받습니다. 예전엔 이 갱신을 수동/cron으로 하다 만료 사고가 흔했습니다
- **리버스 프록시**는 "손님(인터넷)을 대신 맞아 뒷방(앱)으로 안내하는 데스크"입니다. 암호화 처리, 여러 앱 라우팅, 접근 제어를 데스크 한 곳에서 처리하게 되는 구조로, 실무 서버의 표준 구성입니다

### ① DuckDNS에서 이름 만들기

1. https://www.duckdns.org 접속 → 구글 계정으로 로그인
2. 원하는 이름 입력(예: `mydocvault`) → **add domain**
3. 방금 만든 줄의 IP 칸에 **GCP 외부 IP**를 넣고 update
4. 페이지 상단의 **token**을 복사해 두세요 (IP 자동 갱신에 씁니다)

### ② IP 자동 갱신 걸어두기 (DDNS)

GCP 외부 IP는 VM을 껐다 켜면 바뀔 수 있습니다. 5분마다 내 IP를 DuckDNS에 알려주는 스크립트를 걸어 도메인이 항상 따라오게 합니다. **서버 SSH에서**:

```bash
mkdir -p ~/duckdns
# 아래 한 줄에서 mydocvault 와 토큰을 자기 것으로 바꿔 실행
echo 'curl -s "https://www.duckdns.org/update?domains=mydocvault&token=여기에토큰&ip="' > ~/duckdns/duck.sh
chmod 700 ~/duckdns/duck.sh
~/duckdns/duck.sh; echo    # OK 가 출력되면 성공

# 5분마다 자동 실행 (cron 등록)
crontab -e     # 처음이면 1(nano) 선택
# 열린 파일 맨 아래에 다음 한 줄 추가 후 Ctrl+O, Ctrl+X:
# */5 * * * * ~/duckdns/duck.sh >/dev/null 2>&1
```

> **cron**은 리눅스의 예약 실행기입니다. `*/5 * * * *`는 "5분마다"라는 뜻 (분 시 일 월 요일).

### ③ GCP 방화벽에서 80·443 열기

7-1과 같은 방법으로 규칙 하나 생성: 이름 `allow-web`, 대상 "네트워크의 모든 인스턴스", 소스 `0.0.0.0/0`, TCP 포트란에 `80,443` (쉼표 구분).
(80은 인증서 발급·HTTP→HTTPS 리다이렉트용, 443이 실제 HTTPS 포트입니다)

### ④ Caddy 켜기

```bash
cd ~/docvault
echo "DOCVAULT_DOMAIN=mydocvault.duckdns.org" >> .env    # 자기 도메인으로
docker compose --profile edge up -d

docker compose logs caddy --tail 20   # "certificate obtained successfully" 류가 보이면 발급 완료
```

1~2분 뒤 **`https://mydocvault.duckdns.org`** 접속 → 자물쇠 아이콘과 함께 열리면 완성입니다. 폰에서도 LTE로 접속해 보고 **"홈 화면에 추가"**로 PWA 설치까지 해보세요.

## 7-3. (대안) 내 도메인을 샀다면 — Cloudflare Tunnel

# 8. 기존 데이터 이사 (PC → GCP)

> 배우는 것: scp — SSH 위에서 파일 복사

지금까지 PC에서 쓰던 문서·계정을 그대로 옮깁니다. **PC의 PowerShell에서**:

```powershell
cd C:\Github\docvault
docker compose down                          # 일관된 상태로 스냅샷 뜨려고 잠깐 정지
tar -czf data-move.tar.gz data               # data/ 압축
scp data-move.tar.gz 계정명@GCP외부IP:~/docvault/   # 서버로 전송
```

**서버 SSH에서**:

```bash
cd ~/docvault
docker compose down
rm -rf data                       # 서버에서 갓 만든 빈 데이터 제거
tar -xzf data-move.tar.gz         # PC 데이터 복원
docker compose --profile edge up -d
```

접속해서 파일·계정이 그대로인지 확인하면 이사 끝. PC 쪽은 이제 안 띄워도 됩니다 (`docker compose down` 상태 유지).

| 빌드가 중간에 죽음/멈춤 | 스왑(5장) 했는지 `free -h`로 확인. 스왑 후에도 죽으면 `docker compose build` 단독 실행으로 로그 확인 |
| 빌드가 `JavaScript heap out of memory` / exit 134로 실패 | Node가 컨테이너 RAM(1GB)에 맞춰 힙 한도를 ~500MB로 잡아 스왑을 써보기도 전에 자폭하는 것. Dockerfile의 빌드 명령에 `NODE_OPTIONS=--max-old-space-size=2048`이 포함돼 있는지 확인 — 구버전이면 `git pull` 후 재빌드. (exit 134 = SIGABRT, 프로세스 자체 중단) |
| `https://...duckdns.org` 인증서 오류 | ① duckdns.org에서 IP가 현재 외부 IP와 같은지 ② 방화벽 80·443 열렸는지 ③ `docker compose logs caddy`의 오류 메시지 |
| 도메인 접속이 갑자기 안 됨 | VM 재시작으로 IP가 바뀐 경우 — duck.sh cron이 도는지 확인 (`crontab -l`), 수동으로 `~/duckdns/duck.sh` 실행 |
| SSH가 안 됨 | VM이 Running인지, (방법 B) 키를 메타데이터에 넣었는지. 급하면 브라우저 SSH로 |
| `permission denied` (docker) | `sudo usermod -aG docker $USER` 후 재접속했는지 |
| 요금이 청구됨 | 결제 → 보고서에서 항목 확인. 대부분 ① 리전 실수 ② 디스크가 SSD ③ 외부 IP 요금. VM 사양은 수정(중지 후 머신유형 변경)으로 바로잡을 수 있음 |
| VM을 갈아엎고 싶음 | backups/ 만 내려받고 VM 삭제 → 새로 만들어 이 가이드 5장부터 재실행 → 백업 복원 |

# 11. 다음에 공부하면 좋은 것들 (로드맵)

여기까지 했다면 이미 "리눅스 서버에 Docker로 서비스를 올리고 도메인·HTTPS·백업까지 운영"하는 사람입니다. 더 가보고 싶다면:

- **systemd** — 리눅스가 부팅 때 서비스를 관리하는 방식. `systemctl status docker` 부터
- **GCP 스냅샷** — 디스크 통째 백업. 콘솔에서 클릭 몇 번으로 VM 전체 복원점 생성
- **IAM** — 클라우드 권한 체계. "누가 무엇을 할 수 있나"의 표준 모델
- **gcloud CLI** — 콘솔 클릭 대신 명령어로 VM 생성·관리 (자동화의 시작)
- **Nginx vs Caddy** — 리버스 프록시 비교. 실무에선 Nginx가 표준이라 개념 비교해볼 것
- **fail2ban / SSH 포트 변경** — 서버가 받는 무차별 로그인 시도 로그(`sudo journalctl -u ssh`)를 구경해보고 방어 걸기
- **모니터링** — GCP Monitoring에서 CPU·메모리 그래프 보기, 알림 만들기
- **Terraform** — "인프라를 코드로". 오늘 클릭으로 만든 것들을 코드 한 장으로 재현하는 도구
