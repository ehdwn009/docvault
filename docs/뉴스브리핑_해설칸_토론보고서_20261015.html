"해설" 칸과 "기사 맥락이 실린 묻기" — 어디에, 언제, 얼마나 깊게

사용자 제안: 기사마다 원인·영향이 있다 없다 하고 얕다, "토지거래허가가 뭐지" 같은 용어를 물을 길이 없다, 질문할 때 기사 내용이 실려 있어야 한다. 이에 대해 한 세션이 낸 초안("해설 탭 신설 · 전 분야 고정 4칸 · 핵심은 미리 + 주요는 열 때 생성 · 끌어서 묻기 + 문맥 4,000자 + 원문도 함께 스위치")을, 초안을 모르는 네 역할이 코드와 설계 문서를 읽고 검토했다.

합의 (4/4)

해설은 "탭"이 아니라 기본 보기 맨 아래의 접힌 점선 상자로, 회차를 만들 때 같은 요약 호출 안에서 핵심·주요 전부 미리 쓴다. 네 역할 모두 탭을 반대했다 — 보기 칩은 기기가 기억해서 한 번 고르면 다음 기사부터 AI 글로 열리고, 그건 직전 토론이 칩을 버린 이유 그대로다. 초안의 "열 때 생성"도 전원 반대 — 원문을 저장하지 않으니 열 때는 요약을 또 푸는 "추론의 추론"이 되고, 새 표·라우트·월 비용 합산이 따라붙는다.

  • 칸: 말뜻(용어 0~3, 기사에 있을 때만) · 왜 이렇게 됐나 · 그래서 어떻게 되나 · 다음에 볼 것. 정치·사회·세계는 "그래서 어떻게 되나"를 뺀다(3칸). 참고 기사는 해설 없음. 빈 칸·빈 상자는 안 그린다.
  • 깊이: 연쇄 추론은 1단계까지(둘째 단계는 재료 근거가 있을 때만). 단 대상은 "가계·대출자·세입자"처럼 사람까지 내려온다. 숫자 대조는 해설 전 칸에 drop 강제, 금지어·정부 대상 유불리 금지 그대로.
  • 표시: 줄마다 꼬리표는 없다. 칸 제목 오른쪽에 영향 칸과 같은 기호 둘 — 기사가 말한 칸은 「— 언론사」, 기사 밖 칸은 「AI 추론」 알약. 데이터에는 칸마다 kind(stated / inferred / outside)를 남긴다. 머리말 고정 문구 "요약을 보고 AI가 푼 글 · 제도·수치는 바뀔 수 있어요".
  • 묻기: 폰 기사 화면에서 문장을 고르면 하단 [이전/다음] 막대가 「…」물어보기로 바뀐다. 문맥은 클라이언트가 보내지 않고 서버가 fileId+itemId로 "우리가 쓴 글 전체"를 조립(브리핑 전용 상한 4,000자), 질문 기록에는 [기사가 말한 것]/[AI 해설] 꼬리표를 달아 넘긴다. 원문 탭에서 고른 문장은 그 호출에만 싣고 저장하지 않는다(quote null).
  • "원문도 함께" 스위치는 1차에서 미룬다(3/4). 전제인 앱 안 원문 보기의 품질 측정(briefing:readcheck)이 아직 없다.
  • 비용: 회차당 +$0.40(핵심 Opus·주요 Sonnet, 출력만 늘어남), 시간 +2~3분. 출력 상한 16k의 절반 안, 20분 한도까지 5분 여유. 월 합계 약 $45로 한도 $110 안.
초안과 달라진 점 여섯: 탭 → 접힌 상자 · 전 분야 4칸 → 정치·사회·세계 3칸 · 핵심만 미리 → 핵심·주요 전부 미리(참고 제외) · 2단계 연쇄 → 1단계 · 줄 꼬리표 없음 → 칸 단위 기호 · 원문 스위치 → 미룸. 초안이 맞았던 것: 끌어서 묻기 연결, 문맥 4,000자, 우리 글만 저장.

토론 설정

사용자가 실제 기사 화면 두 장(원/달러 환율 1,338.3원 — 영향 칸 없음 · 서울 아파트 토허 신청 3,678건 — 영향 한 줄)과 일반 문서의 「시기의」물어보기 버튼 화면을 보고 제안했다. 네 역할(읽는 사람 대변 · 수집·파이프라인·비용 · 화면 디자인 · 정확성·저작권 감시)은 직전 토론(2026-10-11 영향 칸)의 합의와 감시 조건, 개선 합의안, summarize.ts·ask.ts·BriefingView.tsx·Viewer.tsx를 각자 읽었다. 초안은 "한 세션의 제안이며 동의할 의무가 없다"고 명시했다. 1라운드는 서로를 모른 채, 2라운드는 다른 세 입장을 보고 쟁점 8개에 찬성·양보·고수를 적었다.

발견 한 가지(디자인·읽는 사람): 폰 기사 화면에서 물어보기가 안 뜨는 원인은 초안이 짚은 "선택이 뷰어 본문 상자 밖"이 아니라, 선택은 잡히는데 뷰어 도구막대(z-20)가 기사 시트(z-40) 아래 깔려 버튼이 가려지는 것이다(Viewer.tsx:1071, BriefingView.tsx:1065). 질문 시트(z-30)도 같은 스택 아래에 있어 실기기 확인이 필요하다.

합의안

해설 상자

  • 데이터: 회차 JSON의 기사마다 explain — 칸 배열, 칸마다 kind(terms / why / effect / watch), text, from[], basis(stated / inferred / outside). 요약 스키마에 칸별 src를 받아 코드가 basis를 정한다: from 있고 숫자 통과 → stated, from 있고 방향 어휘가 재료에 없음 → inferred, from 없음 → outside. outside는 말뜻·왜에만 허용, 숫자·날짜·고유명사가 있으면 삭제.
  • 생성: summarize.ts 같은 호출. 해설 전용 system 문구를 SYSTEM_BASE 뒤에 덧붙인다 — "말뜻·배경은 기사 밖 지식을 써도 되나 재료와 어긋나면 재료 우선, 모르면 비운다, 현행 수치·날짜 금지". 예측 어미(~할 것이다·전망·예상된다) 정규식 삭제, "~되면" 조건문만. 영향 칸·왜 중요한가와 겹치는 줄은 삭제(기존 overlapsWith). 대상이 정부·정당·정책이면 방향 없음(기존 POLICY_TARGET).
  • 화면: 기본 보기 블록 뒤·근거줄 앞. 접힌 줄 「해설 · 토지거래허가 · 전세사기특별법 ⌄」(용어 없으면 「해설 · 왜 · 그래서 · 다음」). 펼치면 머리말 한 줄 + 칸. 말뜻 칸은 항상 「AI 추론」. 기사마다 접힘, 기억 안 함. 0칸이면 상자 없음. 틀린 곳 알리기에 "해설이 이상함" 추가.
  • 끄기: IMPACT_MODE처럼 EXPLAIN_MODE: 'off' | 'show' 한 상수. 실행 기록 stats에 explain.dropped.

끌어서 묻기 + 문맥

  • 기사 시트가 선택을 직접 읽는다(Viewer의 blockContext는 안 씀 — 이웃이 근거줄·알리기 글). 폰은 하단 막대 교체, 선택 중 좌우 밀기 끄기, 질문 시트를 기사 시트 위로.
  • 클라이언트는 fileId + itemId + quote만 보내고, 서버가 회차에서 우리 글 전체를 조립해 ask_threads.context에 저장(브리핑 전용 ASK.BRIEFING_CONTEXT_MAX_CHARS 4,000, 문서용 1,500은 그대로). 문맥은 [기사가 말한 것] / [AI 해설] 두 묶음으로 나누고 안내문에 "해설은 AI 글이니 사실로 인용하지 말 것".
  • 원문 탭에서 고른 문장은 그 호출에만 싣고 quote는 null. 화면엔 그 세션 동안만 고른 문장이 보이고 기록엔 "원문 문장으로 물음" 한 줄. 질문 시트 문맥 칩에 무엇이 붙었는지 적는다("제목·요약·해설 함께").

결정해 주셔야 할 것

1. 해설 상자 이름과 칸 이름

해설 · 말뜻 / 왜 이렇게 됐나 / 그래서 어떻게 되나 / 다음에 볼 것디자인 제안. 기존 칸(용어·배경·앞으로)과 다른 이름이라 사실 칸과 안 헷갈린다
다른 이름"풀이", "AI 해설" 등. 기존 칸 이름과 겹치지만 않으면 된다
권고 디자인 제안 그대로.

2. 해설에 웹 검색을 쓸지

안 쓴다 (1차)말뜻·배경은 모델 기억 + 재료 우선. 현행 수치 금지로 시점 오류를 막는다. 비용 0
쓴다용어 정의의 시점 오류는 줄지만 건당 +$0.01~0.02, 인용 본문 저장 금지 조건이 따라온다
권고 1차는 안 쓴다. 틀린 곳 알리기 "해설이 이상함" 집계를 2주 보고 정한다.

3. "원문도 함께" 스위치

미룬다 (3/4)앱 안 원문 보기의 추출 품질(briefing:readcheck 70%/50%)을 먼저 재고, 우리 글 4,000자로 답이 모자랄 때 넣는다
1차 포함 (읽는 사람)원문 탭 가서 다시 드래그하는 왕복이 번거롭다. 조건: 받기 실패·지연이면 원문 없이 보내고 알린다
권고 미룬다. 원문 탭에서 고른 문장이 호출에 실리므로 1차 요구는 그것으로 채워진다.

(a) 요약 호출 안에 넣을 때 수치. 지금 출력은 주요 1건 ≈ 700토큰(리드·왜·칸·5W·영향·JSON), 핵심 1건 ≈ 1,000토큰. 해설 +400/건이면 주요 6건 묶음 4.2k→6.6k, 핵심 3건 묶음 3k→4.2k, effort low 생각 토큰 1~2k를 더해도 9k 안 — 16k의 절반 남는다. 시간: 묶음당 출력 +1.2~2.4k ≈ +20~35초, 묶음 ~22개·동시 4 → +2~3분. 현재 10~12분이라 20분 한도까지 5분 남는다. (b) 전부 미리 생성해도 체험 손실 없다. 읽는 사람의 "펼칠 때 생성"은 접힘·펼침 기억 안 함이라는 자리 결정이지 생성 시점 결정이 아니다 — 미리 만들어도 접어 두면 같은 체험이고, 기다림·뼈대 줄·실패 상태가 사라진다. 열 때 만들면 재료가 우리 요약뿐(원문 미저장)이라 내용은 더 얕다. 치르는 값은 안 펼친 분량 ≈ 월 $10.

(c) 칸 단위 from/기사 밖. 스키마에 칸마다 src를 받고 코드가 from = parseSrc(src)로 세 상태를 정한다: from 있고 숫자 대조 통과 → stated, from 있고 방향 어휘가 재료에 없음 → inferred(verifyImpact 그대로), from 없음 → outside("기사 밖") — outside는 ①말뜻·②배경에만 허용하고 숫자·날짜·고유명사가 있으면 삭제(drop 강제). ③은 impact를 넓히고 ④는 next를 필수 시도로 바꾸면 된다. 즉 해설 = 기존 네 칸의 "항상 시도 + 상태 꼬리표"이고 새 구조는 없다.

(a) 미리 생성되면 상자는 상태가 하나뿐이다 — 접힌 한 줄 + 펼침. 대기·실패·[다시]가 없고 머리말은 고정 문구 하나("요약을 보고 AI가 푼 글 · 제도·수치는 바뀔 수 있어요"). 접힌 줄에 말뜻 칸의 용어를 미리 보인다: 「해설 · 토지거래허가 · 전세사기특별법 ⌄」 — "이 말이 뭐지"가 한 번 눌러서 끝나고, 용어가 없으면 「해설 · 왜 · 그래서 · 다음」. 해설이 0칸인 기사(참고·실패)는 상자 자체가 없다.

(b) 칸 단위 from/기사 밖 — 색 없이, 칸 제목 줄 오른쪽 끝에: 기사가 말한 칸은 「— 동아일보」(From 컴포넌트 :1347), 기사 밖 칸은 테두리 알약 「AI 추론」(:1273). 영향 칸과 같은 문법이라 새로 배울 기호가 없고, 상자 전체는 점선, 칸은 구분선 없이 제목 굵게(BLOCK_LABEL 꼴). 말뜻 칸은 항상 "AI 추론" 알약(재료에 정의가 있을 리 없다).

(c) 정치·사회의 ③칸 — "당사자 나열"로 두면 「그래서 누구에게 · 정부 · 야당 · 금융노조」 한 줄이 모든 정치 기사에 같은 꼴로 서고, 바로 위 5W의 "누가"와 겹쳐 읽는 사람이 "왜 두 번?"이 된다. 빼면 3칸 상자가 되는데, 칸 수가 기사마다 다른 건 이미 blocks(배경·숫자·경과)가 그렇게 그려져 어색하지 않다. 그래서 뺀다 — 빈 칸은 안 그린다는 원칙 그대로.

## 2라운드 — 정확성·저작권 감시

(a) 같은 요약 호출에서 원문 재료를 보며 쓰면 줄어든다 — 기사가 현행 기준을 말하면 모델이 그걸 쓰고, 칸마다 from을 받을 수 있어 "추론의 추론"도 사라진다. 그래도 남는 것: 용어 풀이의 정의 자체는 여전히 모델 기억이다(기사는 "토지거래허가"를 쓰지 정의하지 않는다). 조건 셋은 유지 — ⑴ 재료와 어긋나면 재료 우선·모르면 빈 칸 지시, ⑵ 해설 전 칸 숫자 drop(재료에 없는 수치 삭제), ⑶ from 없는 칸은 데이터에 inferred(impact 재사용 찬성).
(b) 읽는 사람 쪽으로 양보 — 정치·사회·세계는 ③칸 삭제. "유불리 없는 칸은 일반론"은 정확성 쪽에서도 맞다.
(c) 줄 꼬리표 포기. 대신 칸별 kind는 데이터에 반드시 남기고, 화면은 머리말 한 줄이 "기사 밖 지식: 말뜻·다음에 볼 것"처럼 inferred 칸 이름을 적는다. 문맥의 [기사가 말한 것]/[AI 해설] 꼬리표(읽는 사람 제안)는 필수 조건에 넣는다.
