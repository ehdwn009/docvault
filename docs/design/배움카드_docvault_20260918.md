시안(화면 12장 + 흐름표): https://claude.ai/artifact/74a2P3Gnb1yExbG2KF2d55 (비공개 링크 — 소유자만 열림)

## 배경

사용자는 이 앱에 올려 둔 문서(정독본·가이드)를 교재 삼아 공부한다. 읽다가 모르는 용어가 나오면 밖의 챗봇에 물어보는데, **답을 들으면 그 답 속 용어가 또 궁금해지고, 그렇게 물어본 것들이 어디에도 정리되지 않는다.** 질문은 나무처럼 뻗는데 기록은 한 줄로 쌓이기 때문이다.

이 기능은 두 가지를 앱 안으로 들인다.

1. **읽던 자리에서 바로 묻기** — 문장을 드래그하면 그 문장과 앞뒤 문맥이 붙은 채로 LLM에게 물어본다.
2. **답을 개념 단위의 카드로 남기기** — 대화를 통째로가 아니라 개념 하나 = 카드 한 장으로 저장하고, 카드끼리·카드와 문서를 연결한다.

## 원칙

- **카드는 저절로 생기지 않는다.** "카드로 저장"을 눌렀을 때만 생긴다. 챗봇은 일상 질문도 받지만, 카드 서랍이 일기장이 되지 않는 이유가 이것이다.
- **개념 하나 = 카드 한 장.** 같은 용어를 다른 문서·다른 날 다시 물어보면 새 카드가 아니라 기존 카드에 **이어쓰기**가 기본값이다. 같은 용어의 다른 측면(자동차의 주행법 / 차체)은 한 카드 안의 소제목이 되고, 커지면 **나누기**로 떼어낸다.
- **카드는 평범한 md 파일이다.** 새 저장 방식을 만들지 않는다. 편집·버전 기록·태그·검색·공유·백업이 전부 기존 기능 그대로 동작해야 한다. 카드 전용 폴더(`📚 배움 카드/`)에 LLM이 제안한 주제 폴더로 나뉘어 들어간다.
- **대화는 자동 보관, 카드는 명시적 저장.** 저장 안 하고 닫은 대화는 서버에 남았다가 30일 뒤 정리된다. 카드가 된 대화는 카드의 "원 대화"로 계속 산다.
- **LLM에는 문서 전체를 보내지 않는다.** 선택 문장 + 앞뒤 문단 + 문서 제목만 보낸다. 비용과 개인정보(남의 공유 문서 포함) 양쪽 이유다. "문서 전체 요약" 같은 기능은 범위 밖.
- **LLM 호출은 서버에서만.** API 키는 서버 env(`ANTHROPIC_API_KEY`)에만 있고, 사용자별 하루 질문 한도로 비용을 막는다.

## 카드의 모양 — 머리말(기계용) + 본문(사람용)

정해진 양식을 본문에 강요하지 않는다. 칸이 여덟 개 있으면 AI는 없는 비유를 지어내고, 절차·비교·문제 해결이 전부 "자세히" 한 칸에 욱여넣어지고, 사용자가 칸을 지우면 다음 재구성 때 AI가 도로 넣는다 — 시안 "2판 5·6·7"에서 확인한 불편. 그래서 **앱이 읽는 부분(머리말)과 사람이 쓰는 부분(본문)을 나눈다.**

```markdown
---
한 줄: 하드웨어와 프로그램 사이에서 자원을 나눠 주는 관리자
별칭: [kernel, 리눅스 커널]
종류: 개념
주제: 운영체제
태그: [운영체제, 리눅스]
연결: [운영체제, 셸, 시스템 콜]
출처:
  - docker-learning-guide.html · "Windows에는 리눅스 커널이 없으므로…" (대화 #12)
---
건물 관리인 같은 거예요. 입주민(프로그램)은 전기실에 직접 안 들어가고
관리인(커널)에게 부탁해요. 이 부탁을 **시스템 콜**이라고 해요.

확인: `uname -r` → 버전에 microsoft가 보인다
```

- **제목 = 파일 이름**(`커널.md`). 머리말에 제목을 두지 않는다 — 두 군데면 반드시 어긋난다.
- **필수는 한 줄뿐**(제목은 파일 이름이니까). 나머지 머리말은 있으면 쓰고 없으면 안 쓴다.
- **본문은 자유.** 소제목이 있어도 없어도, 두 줄이어도 된다. 검색·중복 감지·서랍 목록·연결·출처는 머리말만 읽으므로 본문을 아무리 고쳐도 기능이 안 깨진다.
- **종류**(개념·절차·비교·문제 해결)는 AI가 초안 뼈대를 고를 때의 힌트이고 서랍의 필터일 뿐, 본문에 강제되지 않는다.
- 머리말 문법은 일부러 좁다: `키: 값`, `키: [a, b]`, `키:` 아래 `  - 항목`. YAML 전체가 아니다 — 편집기에서 손으로 고칠 수 있고, 라이브러리 없이 서버·클라이언트가 같은 규칙을 갖기 위해 (`lib/frontmatter.ts` 양쪽).
- 카드는 **files의 md 파일(kind='card')** 이다. 편집·버전 기록·태그·검색·공유·백업이 그대로 된다. 다만 **파일 트리(API-021)에는 나오지 않고 서랍(SCR-181)에서만** 보인다 — 문서와 섞이면 구분이 안 된다.
- 카드 ↔ 대화는 `card_threads`로 잇는다. 카드가 참조하는 대화는 30일 정리에서 빠진다(카드의 "원 대화").

카드는 두 종류다. **개념 카드**(개념당 한 장)와 **주제 카드**(대화 정리 때 개념 카드들을 엮는 요약 한 장). 주제 카드는 머리말 `종류: 주제`로 구분한다 — 따로 표를 두지 않고 종류 하나를 더한 것이라, 서랍·검색·연결이 개념 카드와 똑같이 된다.

## 같은 개념·비슷한 카드 — 덧붙이지 않고 다시 짠다

가장 중요하게 본 문제: 비슷한 카드가 흩어지거나, 이어쓰기로 한 카드 안이 무질서해지는 것 (시안 "2판 2·3·4").

1. 저장을 누르면 AI가 초안을 짜면서 **기존 카드 목록(제목·한 줄·별칭)** 을 같이 보고 겹치는 카드를 고른다. 제목·별칭이 정확히 같은 카드는 AI 없이도 잡는다.
2. AI가 **판단을 먼저 말한다**: 같은 개념 / 같은 개념의 다른 측면 / 관련만 있음 / 이름만 비슷한 다른 개념 + 근거 한두 문장 + 추천(합치기 / 새 카드+연결 / 그냥 새 카드).
3. **합치기 = 재구성.** AI가 기존 카드 + 새 답을 읽고 카드를 통째로 다시 짠다 — 한 줄 정의를 둘을 아우르게 다듬고, 소제목을 새로 나누고, 기존 본문의 모양은 유지한다. 저장 전에 **지금 → 합친 뒤**를 나란히 보여 주고 "무엇이 바뀌었나" 목록을 붙인다. 지시("종류는 표로")를 적어 다시 짤 수 있고, 이전 판은 버전 기록에 남는다.
4. 다른 개념이면 **새 카드로 만들고 서로 연결**을 먼저 추천한다. 어느 쪽을 고르든 나중에 합치기·나누기로 되돌릴 수 있다 — 그래서 저장 순간에 고민을 오래 안 해도 된다.
5. 결정은 늘 사용자. AI는 근거와 추천만.

## 사용자 흐름 — 경우의 수

시안의 흐름표(0번 아트보드)에 A~M 열세 가지를 그렸다. 요지만 적는다.

| 경우 | 결정 |
|---|---|
| A 기본 | 드래그 → 물어보기 → 문서 옆 패널에서 대화 → 카드로 저장 → md 파일 + 형광펜 + 서랍 |
| B 꼬리질문 | 대화 1개에서 카드 N개. 저장 때마다 "새 카드 / 기존 카드에 덧붙이기". 같은 대화의 카드끼리 자동 연결 |
| C 같은 용어 재질문 | 제목·별칭이 같은 카드가 있으면 저장 전에 알림 + LLM이 기존 카드를 읽고 답. 기본값 이어쓰기 |
| D 껐다 다시 켬 | 문서를 열면 이 문서를 출처로 둔 카드를 조회해 형광펜 복원. 문서가 편집돼 문장을 못 찾으면 카드에 "출처 위치 잃음", 카드 자체는 멀쩡 |
| E 답 속 모르는 단어 | 지금 물어보기(꼬리질문) / 나중에(빈 카드 생성) |
| F 카드→카드 | [[링크]] 클릭. 없는 카드면 "지금 물어볼까요?" → 출발 카드를 문맥으로 새 대화 |
| G 드래그 없이 질문 | 서랍·Ctrl+K에서 시작. 출처 없는 카드. 나중에 문서에서 같은 용어를 만나면 C로 이어짐 |
| H 저장 안 하고 닫음 | 대화 자동 보관, "지난 대화"에서 복구. 카드로 안 만든 대화는 30일 뒤 정리 |
| I 카드 정리 | 이름 바꾸기(옛 이름은 별칭으로 보존 → 링크 안 깨짐) · 삭제(휴지통, 가리키던 링크는 빈 카드로) · 나누기 · 합치기 |
| J 모바일 | 문서와 대화를 동시에 못 봄 → 바텀 시트. 선택 아래쪽에 우리 버튼(OS 기본 메뉴는 위쪽) |
| K 남의 공유 문서 | 카드는 내 것, 형광펜도 나만 보임. 문서는 안 건드림 |
| L 실패 | 하루 한도 초과(입력만 잠김) · LLM 오류(질문 글 보존 + 다시 시도) · 답이 틀림(md라 편집기로 고침) |
| M 대화 통째로 정리 | [대화 정리] → LLM이 개념 N개를 체크리스트로 제안 (이미 있는 카드는 이어쓰기 표시) → 개념 카드 N장 + 주제 카드 1장 |

## 1판 상세

**화면 (IA — SCR-180 질문 패널)**
- 뷰어(SCR-150) 안에서 문장을 드래그하면 **PC**는 선택 위에 작은 바 [물어보기]가 뜬다. **터치**는 떠 있는 바를 두지 않는다 — iOS·안드로이드의 선택 메뉴가 위·아래 어디든 떠서 겹친다(v0.23.2에서 실측). 대신 아래 도구막대의 [질문]이 문장을 고른 동안 "💬 「…」 물어보기"로 바뀌고, 그동안 도구막대는 접히지 않는다.
- [물어보기] → PC는 뷰어 오른쪽에 패널(버전 기록 패널과 같은 자리·같은 폭), 터치는 바텀 시트. 패널 첫 줄에 문맥 칩(문서 이름 + 선택 문장). 입력창은 **비워 둔다**(채워 두면 다른 걸 물을 때 지우는 일이 생긴다) — 대신 입력창 위에 [무슨 뜻이야?] [쉽게 설명해 줘] [왜 그래?] 버튼이 있어 한 번 탭으로 보낸다(v0.23.2).
- 답은 스트리밍으로 흘러 들어오고 md로 그린다. 답 아래 [복사] [더 쉽게]. 대화 중 문서에서 다시 드래그하면 그 문장이 다음 질문에 붙는다.
- 헤더의 [질문] 버튼(터치는 아래 도구막대)으로 드래그 없이도 연다(G). 패널을 닫아도 대화는 남아 있어 다시 열면 이어진다.
- 패널 머리: 오늘 질문 n/30(관리자는 n번) · [지난 대화] · [새 대화] · 닫기. 터치 시트는 손잡이를 끌어올리면 화면 가득 펼쳐진다.
- 문맥 갈아타기: 아직 질문을 한 번도 안 보냈으면 새로 고른 문장이 문맥을 **대체**하고, 보낸 뒤부터는 다음 질문의 **인용**으로 붙는다(v0.23.2).
- HTML 문서는 격리 iframe 안이라 부모가 선택을 읽을 수 없다 — 렌더러 심이 선택 문장·문맥·좌표를 postMessage로 보고한다 (목차·스크롤과 같은 통로).

**서버 (API 명세 — API-101~105)**
- `ask_threads` / `ask_messages` 두 테이블 (ERD). 대화는 파일 id를 참조하되 파일이 지워져도 남는다(SET NULL).
- 첫 요청에만 문맥(문서 제목·선택 문장·앞뒤 문단)을 실어 보내고, 이후는 대화 이력 + 새 질문.
- 답변 스트리밍은 SSE. 답이 끝나면 assistant 메시지를 저장하고, 중간에 실패하면 사용자 질문만 남긴다(다시 시도 가능).
- 하루 한도는 사용자별 user 메시지 수(UTC 날짜 기준)로 센다. 한도를 넘으면 입력만 막히고 읽기는 된다.
- 30일 지난 대화는 기동 시 + 하루 1회 정리(휴지통 비움과 같은 주기). 2판부터는 카드가 참조하는 대화는 예외.
- 시스템 프롬프트: "코딩 입문자의 학습 동반자. 초심자 눈높이, 비유 하나, 가능하면 직접 확인할 명령 하나. 선택 문장을 근거로 답하고 모르면 모른다고." 일상 질문도 거절하지 않는다(경계가 흐릿해 엉뚱한 거절만 생긴다).
- **웹 검색 (v0.24)**: 모델의 지식은 학습 시점에서 끊기므로 버전·화면·명령 유효성 같은 "시점에 따라 달라지는" 질문은 옛 답이 될 수 있다. Anthropic의 서버 도구 `web_search`를 붙이되 **모델이 판단**해서 필요할 때만 쓰게 한다(항상 검색은 개념 질문에 낭비, 사용자 토글은 언제 켤지 알아야 해서 탈락). 답당 최대 3회. 검색한 답은 끝에 `🌐 참고한 곳:` 링크가 붙는다 — "이 답이 어디서 왔나"를 볼 수 있는 게 학습에 좋다. 검색 결과도 문맥으로 들어가므로 프롬프트 인젝션 방어 문구는 검색 결과에도 같이 적용된다.

**정한 값 (server/src/constants.ts)**

| 항목 | 값 | 이유 |
|---|---|---|
| 모델 | `claude-opus-5` | 설명 품질. 비용은 한도로 막는다 |
| 하루 질문 한도 | 30 (관리자는 없음) | 공부 세션 하나에 넉넉하고, 폭주는 막는 값. 되돌릴 수 있으니 낮게 잡지 않았다. 키를 넣고 요금을 내는 관리자에게는 걸지 않는다 |
| 대화 보관 | 30일 | 휴지통과 같은 감각 |
| 문맥 크기 | 선택 문장 500자 · 앞뒤 문단 합쳐 1500자 | 문서 전체를 안 보내는 선 |
| 답 최대 길이 | 4096 토큰 | 설명 하나 분량. 더 길면 "더 자세히"로 이어 묻는다 |
| 웹 검색 | 모델 판단, 답당 최대 3회, 출처 최대 5개 | 검색 1회 ≈ 10원 + 결과 토큰. 30번 한도 안에서 부담 작음 |

**열어 둔 것 (써 보고 정한다)**: 답 속 모르는 단어 점선 표시(1판에서는 안 함 — 산만한지 써 봐야 안다), 개념 지도 시기, 한도·보관 기간 숫자.

## 범위 밖

- 문서 전체를 읽는 질문("이 문서 요약해 줘") — 비용이 문서당 수십 질문 값이라 별도 기능으로 나중에 판단.
- 편집기(SCR-160) 안에서 물어보기 — 1판은 뷰어만.
- 카드 공유·협업 — 카드는 md 파일이라 기존 공유 토글로 충분하다고 보고 따로 만들지 않는다.

## 보안·비용

- 키는 서버 env에만. 클라이언트는 `/ask/*`만 부른다. 키가 없으면 `ASK_NOT_CONFIGURED`(503)로 패널이 "관리자가 아직 연결하지 않았어요"를 보여 준다.
- 사용자가 보낸 문장·문맥이 Anthropic으로 나간다 — 공유 문서(남의 문서)의 문장도 포함될 수 있다. 문서 전체가 아니라 선택 부분만 나가는 것이 이 위험을 줄이는 장치이며, README에 한 줄 적는다.
- 프롬프트 인젝션: 문서 문맥은 사용자 메시지 안의 인용으로만 실린다(system이 아님). 문서가 LLM에게 지시하는 글을 담고 있어도 "학습 동반자" 역할을 벗어나지 않도록 system에 명시한다.

## 2판 첫 조각 상세 (v0.26)

**화면** — SCR-181 서랍(레일 📚): 검색(제목·별칭·한 줄·태그), 주제별/최근 묶기, [+ 빈 카드](AI 없이 머리말 한 줄만 채워 시작), 우클릭·⋯ 메뉴의 [삭제](휴지통 + 실행 취소 — 카드 전용 삭제 API를 두지 않고 API-036을 쓴다). SCR-182 저장 창: 답 아래 [📚 카드로 저장] → 초안 로딩 → (비슷한 카드 있으면) 판단·선택 → 머리말+본문 확인 → 저장 → 카드가 뷰어에 열림. 합치기는 미리보기(지금/합친 뒤/바뀐 것/다시 짜기 지시) → 저장. PC는 모달, 터치는 전체 화면. 카드 뷰(뷰어): 머리말은 제목·한 줄 콜아웃·별칭·종류·태그 칩으로, 본문은 md로, 아래에 연결·출처. 카드에서 [이어서 질문]·드래그 질문이 그대로 되므로 카드가 카드를 낳는다.

**서버** — API-111~115 (`routes/cards.ts`). 초안·재구성은 구조화 출력(zod 스키마)으로 받아 모양을 보장한다. 판단이 목록에 없는 카드를 가리키면 버린다. 재구성 저장은 편집기 저장과 같은 스냅샷 규칙(`lib/content.ts`로 뽑아 공유). 카드 초안·재구성 호출은 하루 한도에 세지 않는다 — 이번 조각의 단순화이며, 사용량 통계에도 아직 안 잡힌다(열어 둔 것).

**이번 조각에 없는 것** — 나누기·합치기(카드끼리), [[위키링크]]·역링크·빈 카드 표시·출처 형광펜(3판), 파일 트리에 카드 보이기 스위치.

## 2판 둘째 조각 — 대화 통째로 카드로 (v0.28)

한 대화에서 꼬리질문으로 개념 여럿을 배웠을 때 답마다 저장하는 건 번거롭고, 대화 전체를 한 장에 넣으면 "개념 하나 = 카드 한 장"이 깨진다. 그래서 세 갈래를 한 화면에 뒀다.

- **답 골라 담기 (SCR-180)** — 답마다 네모. 고른 답들 → 한 장. LLM 판단 없이 손으로 고르는 정밀 도구. 서버는 API-112가 `messageIds[]`를 받는다.
- **대화 전체 → 한 장 (SCR-182)** — API-112에 messageId 없이. 여럿을 아우르는 한 장이라 종류가 비교·절차로 기울도록 지시한다.
- **대화 정리 (SCR-183, 흐름 M)** — API-116이 개념 N개(≤8)를 뽑고, 기존 카드와 같은 개념은 **이어쓰기**로 표시한다. 같은 개념 판정은 LLM(`existingCardId`)과 제목·별칭 정확 일치 둘 다 — LLM이 놓쳐도 이름이 같으면 이어쓰기다. 이어쓰기 항목은 이 단계에서 재구성(API-113과 같은 호출)까지 해 둔다 — 그래야 저장(API-117)이 LLM 없이 한 트랜잭션으로 끝나고, 체크리스트에서 "무엇이 더해지나"를 미리 보여 줄 수 있다. 주제 카드(kind=주제)는 개념 카드들로 가는 연결을 갖고, 개념 카드에도 주제 카드로 가는 연결이 붙는다(양방향이어야 서랍에서 오갈 수 있다).
- **되돌리기 한 번** — API-117이 새 카드 id들과 이어쓴 카드의 저장 전 versionId를 돌려주고, 토스트 [되돌리기]가 휴지통 이동 + 버전 복원을 한꺼번에 한다.

**이 조각에 없는 것** — 체크리스트에서 초안 편집(펼쳐 보기만 — 고치려면 저장 뒤 카드를 편집), 지난 대화 목록에서 바로 정리하기, 이어쓰기 항목의 "다시 짜기" 지시.

## 출처 클릭 — 카드에서 문서로 (v0.29)

출처 칸은 사람이 읽는 글자(문서명 · 인용 80자)와 기계가 쓰는 열쇠(`(대화 #N)`)를 한 줄에 같이 둔다. 클릭하면 열쇠로 대화(API-105)를 다시 읽어 문서 id와 드래그했던 문장 전체를 얻고, 문서를 열어 그 문장을 **글자로 찾아** 형광펜을 칠한다 (`client/src/lib/findQuote.ts`, HTML은 심의 ES5 복사본). 줄 번호를 저장하지 않는 이유: 문서가 편집되면 줄 번호는 반드시 어긋나지만 문장은 대개 살아남는다. 못 찾으면 앞 30자로 한 번 더 찾고, 그래도 없으면 문서만 열고 알린다 — 카드는 멀쩡하다(흐름 D). 연결 칩은 제목·별칭으로 카드를 찾아 연다. 문서를 열 때 그 문서를 출처로 둔 카드들의 형광펜을 한꺼번에 복원하는 것(흐름 D 전반)은 3판.

## 활용 ① — 내보내기 (v0.30)

카드는 머리말(기계용)이 있어서 그대로 다른 모양이 된다. 용어집 md는 제목·별칭·한 줄·주제만으로 만들고(본문은 안 씀 — 용어집은 훑는 것), Anki는 앞면=제목(+별칭), 뒷면=한 줄+본문 앞부분. 둘 다 `lib/cardExport.ts` 한 곳. 용어집은 내 파일 최상위 `용어집.md` 하나를 계속 갱신한다 — 카드가 원천이고 파일은 출력물이라, 파일을 손으로 고치면 다음 내보내기에 덮인다(버전 기록에는 남는다). 범위는 주제 단위 — 태그 단위는 필요해지면.

## 활용 ② — 문서 속 용어 밑줄 (v0.31)

카드 제목·별칭을 문서에서 글자로 찾아 점선 밑줄(문단당 첫 등장). 누르면 한 줄 정의와 [카드 열기]·[이 용어 질문]. 출처 형광펜과 같은 찾기 코드를 쓰고, 표시는 CSS Highlight API라 DOM을 안 건드린다. 설정으로 끌 수 있다(USER_SETTINGS.term_highlight). "카드 없는 용어 제안"은 뒤로 — 무엇이 "용어"인지 고르는 기준(빈도? 명사?)이 아직 없다.

## 활용 ③ — 복습 (v0.32)

카드는 정리의 결과이지 기억은 아니다. 서랍 상단 "오늘 복습 N장" → 제목만 보고 떠올리기 → 뒤집어 확인 → 몰랐다(내일)/알았다(간격 두 배). 규칙을 라이트너 상자 하나로 좁힌 이유: SM-2 같은 공식은 값이 다섯 개라 초심자가 버튼을 고르다 지친다. 새 카드는 다음 날부터, 하루 20장 상한, 주제 카드는 제외. 점수·스트릭 없음. 상태는 USER_FILE_STATE.

## 활용 ④ — 질문 때 카드 문맥 (v0.33)

질문에 카드 이름이 걸리면 그 카드를 시스템 프롬프트에 덧붙인다 — 대화 이력이 아니라 "이 사람이 아는 것"이라 시스템 쪽. 띠로 무엇이 가는지 보여 주고 ✕로 뺄 수 있다(무엇을 보내는지 모르게 하지 않는다 — 문서 전체를 안 보낸다는 원칙과 같은 결). 답 아래 "함께 본 카드"는 meta로만 오고 저장하지 않는다.

## 활용 ⑤ — 카드 지도 (v0.34)

서랍의 "지도" 보기. 점·선·색·점선(없는 카드). 설계 4판의 "개념 지도"를 당겨 온 것으로, 카드 50장쯤부터 의미가 있다. 없는 카드 점은 3판 "빈 카드"의 입구가 된다 — [빈 카드 만들기]로 그 자리를 채운다.

## 대화 정리 흐름 수정 (v0.35)

첫 판의 세 가지 불편 — 누르자마자 LLM이 돌고, 30초 넘게 걸리고, 창을 닫으면 결과가 사라짐 — 을 한 번에. (1) 시작 전 선택 화면(개념별 / 한 장). (2) 두 단계: 1단계는 개념 목록만(본문 없음, 빠른 모델 CARD.MODEL, effort low) → 몇 초; 2단계 본문·재구성은 항목별로 뒤에서(동시 3개). (3) 결과를 ask_threads.outline_json에 저장 — 다시 열면 그대로, 새 답이 붙었으면 "새로 정리" 띠, 카드로 저장하면 지움. 카드 초안·재구성·정리는 모두 답변 모델(Opus)이 아니라 CARD.MODEL(Sonnet)을 쓴다 — 대화를 구조화하는 일이라 깊은 추론보다 속도.

## 챗봇 — 문서 없이 시작하는 대화 (v0.40)

레일에 말풍선(대화, SCR-187). 지금 읽는 문서와 상관없이 뭐든 묻는 대화이고, 질문 패널(SCR-180)과 **같은 부품**(`AskPanel`, `file=null`·`inline`)이다 — 답 밑의 카드로 저장, 헤더의 카드로(개념별/한 장/골라 담기), 지난 대화 30일 보관, 대화 정리 결과 저장까지 전부 그대로. 문서 대화와 자유 대화는 같은 표(ask_threads, file_id NULL)라 지난 대화 목록에 섞여 나오고 표시만 다르다(📄 문서 이름 / 💬 자유 대화). 새로 정한 것 둘:

- **"내 자료 참고" 스위치** — 입력창 위. 기본 꺼짐(순수 챗봇), 질문마다 바꿀 수 있고 끈 상태를 기기가 기억한다(localStorage). 켜면 (1) 이름이 걸린 내 카드 최대 3장(활용 ④와 같은 규칙, 띠로 미리 보이고 ✕로 뺀다) + (2) **질문 낱말로 내 문서를 전문 검색해 맞는 단락 최대 3개**(FTS5 snippet 48토큰, `lib/askDocs.ts`)를 시스템 프롬프트 뒤에 붙인다. 문서 전체는 절대 안 간다. 답 밑에 "함께 본 카드/문서" 칩 — 누르면 열린다. 요청은 `myStuff: true|false`; 문서 질문은 이 칸을 보내지 않아 지금 동작(설정에 따라 카드만) 그대로다. 한국어 조사("라우터에서")는 떼고 접두 검색(`"라우터"*`)을 OR로 잇는다 — 질문은 문장이라 AND면 거의 안 걸린다. 낱말 맞추기라 "그거 뭐였지" 같은 질문엔 못 찾고, 그러면 그냥 답한다.
- **모델 칩** — 헤더 오른쪽, 문서 질문 패널에도 같이 단다. 빠름(Haiku 4.5) / 균형(Sonnet 5, 기본) / 깊게(Opus 5). 목록은 서버 상수 `ASK_MODELS` 한 곳(단가·effort 지원·검색 도구 버전까지) — 새 모델은 거기 한 줄. 고른 모델은 대화에 저장되고(ask_threads.model, API-107) 다음 답부터; 마지막에 고른 것을 기기가 기억해 새 대화의 기본으로 쓴다. 답마다 어느 모델이었는지 남긴다(ask_messages.model) — 화면의 답 아래 표시와 관리자 AI 사용량의 **모델별 단가** 계산에 쓴다(모델 칸이 없는 옛 답은 전부 Opus). Haiku 4.5는 `output_config.effort`를 받지 않고 최신 검색 도구(`web_search_20260209`)도 못 써서 상수에 그 차이를 적어 두었다. 하루 30번 한도는 모델과 무관하게 합산.
