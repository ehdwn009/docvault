## 레이아웃 개요

로그인 후 전체 화면은 단일 워크스페이스(SCR-100)입니다. 좌측 아이콘 레일(48px)에서 패널을 전환하고, 패널 우측 본문 영역에 뷰어/편집기 또는 설정 콘텐츠가 표시됩니다. 모바일에서는 레일+패널이 드로어(서랍)로 전환됩니다.

## 비고

- **글로벌 내비게이션**: 아이콘 레일이 유일한 전역 내비게이션. 상단 헤더는 두지 않고 뷰어/편집기 헤더에 파일명·액션 버튼을 배치합니다.
- **URL 라우팅**: SPA지만 딥링크를 지원합니다 — `/login`, `/f/{fileId}` (파일 열람), `/admin/*`. 폰에서 특정 문서를 북마크해 바로 열 수 있게 하기 위함입니다.
- **단축키**: `[` 파일 패널 토글, `Ctrl+K` 커맨드 팔레트, `E` 편집 모드, `Ctrl+S` 저장, `Escape` 패널 닫기. 모바일에는 해당 없음.
- **권한 정책**: 모든 화면이 로그인 필수(로그인 화면 제외). 관리자 메뉴는 role=admin에만 렌더링하며 서버 API도 이중으로 검사합니다.
- **반응형 기준**: md(768px) 미만에서 레일은 하단 탭 또는 햄버거 드로어로, 편집기 분할 화면은 탭 전환(에디터/미리보기)으로 대체합니다.
- 화면별 상세 구성·동작은 다음 단계인 화면설계서에서 다룹니다.

## 업로드·파일 관리 UX 확장 (2026-08-15)

기존 API를 그대로 쓰는 클라이언트 UX 확장. 서버 변경 없음.

**업로드 입구 (v0.4)**
- 클립보드 붙여넣기: 입력창 밖에서 Ctrl+V — 이미지는 즉시 업로드(자동 이름), 텍스트는 파일명 입력 후 md로 저장. 편집기·이름변경·대화상자 등 입력 요소에 포커스가 있으면 가로채지 않는다.
- 트리 폴더별 드롭: OS 파일을 트리의 폴더 위에 떨어뜨리면 해당 폴더로 업로드 (기존 하이라이트 재사용).
- 전역 드롭 (v0.5): 개별 드롭 존 밖이라도 앱 화면 어디에 놓든 최상위로 업로드된다 (window 레벨에서 브라우저 기본 동작을 막고 수거).

**다중 선택 (v0.4)**
- 진입: Ctrl+클릭(PC) 또는 컨텍스트 메뉴 "선택"(터치). 선택 모드에서는 행 클릭이 열람 대신 토글, Shift+클릭은 보이는 순서 기준 범위 선택.
- 일괄 작업 바(패널 상단): 이동(폴더 선택 모달) · 삭제(확인 후) · 해제. 폴더는 다중 선택 대상에서 제외(파일만).
- 이동(단일 DnD 포함)은 실행 취소 토스트 5초 제공. 삭제는 휴지통 도입(로드맵) 전까지 확인 대화상자 유지.

**폴더 업로드·충돌 처리 (v0.5)**
- 폴더 선택 업로드(webkitdirectory, PC 전용)와 폴더 드래그(항목 재귀 순회) 지원. 폴더 체인은 기존 폴더 API로 클라이언트가 생성 후 파일 업로드.
- 이름 충돌은 업로드 전 클라이언트가 검사해 일괄 선택 대화상자 제공: 덮어쓰기(텍스트=버전 스냅샷 후 본문 교체, 바이너리=삭제 후 재업로드) / 이름 바꿔 저장(자동 " (2)" 접미) / 건너뛰기.

**휴지통·격자 보기·공유 시트 (v0.6)**
- 휴지통: 파일 삭제는 soft delete — 30일 보관 후 자동 영구 삭제 (상세는 ERD·API 명세). 삭제 확인 대화상자를 없애고 실행 취소(복원)로 대체. 폴더 삭제 시 구조는 삭제되고 파일은 휴지통으로.
- 격자 보기: 내 파일 패널의 목록/격자 토글(기기별 취향이라 localStorage 저장). 격자는 이미지 썸네일(/raw) 중심의 열람용이고, 다중 선택 등 정리 작업은 목록 보기가 담당.
- 공유 시트: manifest share_target(POST /share-target, /api/v1 밖이라 인증 직접 검사) — 폰 공유로 파일·텍스트 수신, 이름 충돌은 자동 개명, 실패는 조용히 건너뛰고 홈으로.

## 탭 바 + 분할 보기 (2026-08-27, v0.15)

서버 변경 없는 클라이언트 확장. **"열려 있다"(탭)와 "보이고 있다"(분할)를 분리**하는 것이 핵심 설계.

**탭 바 (SCR-153, 항상 표시)**
- 본문 영역 맨 위 한 줄. 문서를 열면 탭이 쌓이고, 이미 열린 문서는 그 탭으로 전환. 탭 클릭 = 전환, 호버 시 × = 닫기, 넘치면 탭 바 안에서 가로 스크롤.
- 몰입 모드에서는 탭 바도 숨긴다 (몰입 모드의 약속: 본문만).
- 탭·분할 상태는 세션 한정(새로고침 시 딥링크의 활성 문서 하나만 복원). URL 라우팅은 기존 그대로 활성 문서만 `/f/{id}`.

**분할 (SCR-154)**
- 배치 규칙: **보던 문서는 제자리, 새 문서가 새 칸으로.** 진입은 파일 컨텍스트 메뉴(⋯/우클릭)의 "분할로 열기"와 PC의 Alt+클릭 (Ctrl+클릭은 다중 선택이 선점).
- 데스크톱(768px 이상): 프리셋 — 2개=좌우, 3개=좌1+우2, 4개=2×2 (상한 4). 주 구분선 드래그로 비율 조절(20~80%).
- 모바일(768px 미만): **상하 2분할까지만**. 3번째부터는 탭 대기.
- 활성 칸: 마지막에 조작한 칸에 강조 테두리. 탭 클릭·단축키는 활성 칸에 적용. 이미 화면에 있는 문서의 탭을 누르면 그 칸을 활성화.
- 자리 바꾸기: 2분할일 때 구분선 가운데의 ⇄ 버튼 (경우의 수가 하나라 버튼이 드래그보다 빠름). 탭 드래그 배치는 후속(v2).
- 칸 닫기: 각 칸의 × 는 칸만 닫고 탭은 남는다. 탭 × 는 문서를 완전히 닫는다.
- 각 칸은 독립 뷰어 — 글자 배율·스크롤·목차·편집이 문서별로 따로. 분할 중 E(편집)는 활성 칸 자리만 편집기로 바뀐다 (왼쪽 보면서 오른쪽에 쓰기).

## 분할 컨트롤러 + 모바일 UX 재편 (2026-08-28, v0.16)

**원칙**: 모바일의 본질은 읽기다 — **크롬(UI)은 기본적으로 안 보이고, 부르면 엄지 앞(바텀 시트)에 온다.** 조작 패러다임은 기기 특성(터치/PC, CSS pc:/touch: 변형과 같은 판정)으로 가른다.

**분할 컨트롤러 (SCR-155, 전 기기)**
- 구분선의 ⇄/⇅ 마이크로 버튼을 없애고 **알약 손잡이**로 교체. 손잡이 **탭 = 컨트롤러 팝업**: 비율 프리셋 3개(왼/위 크게 · 반반 · 오른/아래 크게) + 자리 바꾸기(2칸일 때) + 분할 해제(활성 칸만 남김).
- 폰에서 원하는 비율은 연속값이 아니라 이산 선택이라는 판단 — 정밀 드래그를 기본 경로에서 제외. **드래그는 보조**로 유지하되 보이지 않는 확장 터치 존(±12px)으로 잡기 쉽게. 탭/드래그 구분은 이동 거리 임계값.
- ⋯ 메뉴에 **"분할 보기"**: 이미 열린 탭끼리 분할. 대기 탭이 하나면 즉시 분할, 여럿이면 선택 대화상자. (트리의 "분할로 열기"=새 문서, ⋯의 "분할 보기"=열린 문서 — 진입점의 역할 분담)

**모바일(터치) 재편**
- **크롬 자동 숨김**: 본문을 아래로 스크롤하면 헤더·하단 도구막대가 접히고, 위로 긁거나 문서 상단 근처(48px)면 복귀. 편집 모드·몰입 모드는 예외. 화면 맨 위에 **읽기 진행률 줄**(2px, 우리가 그리는 형식만 — HTML은 iframe이라 전체 높이를 모름).
- **탭 바 제거 → 문서 스위처 시트**: 터치에서는 상단 탭 바를 렌더링하지 않는다. 헤더의 파일명이 버튼(▾)이 되어 **열린 문서 목록 바텀 시트**를 연다(항목: 이름·활성 표시·분할로 열기·닫기). **헤더 좌우 스와이프**로 이전/다음 문서 전환.
- **바텀 시트 통일**: ⋯ 메뉴와 목차(SCR-151)를 터치에서는 팝오버/좌측 드로어 대신 화면 하단에서 올라오는 시트로. safe-area 여백 포함.
- **이어 읽기 첫 화면**: 터치에서 열린 문서가 없을 때, 안내 문구 대신 **최근 열람 카드**(최대 3개, 마지막 열람 시각 표시)를 보여준다. 서버에 저장된 열람 기록을 그대로 활용.
- 하단 고정 통합 바는 **채택하지 않음** — 자동 숨김 크롬 + 시트가 같은 목적(엄지 존)을 비용(키보드·safe-area·분할 간섭) 없이 달성.

**문서 내부 링크 (같은 릴리스)**
- md 문서 속 상대 경로 링크(`[이름](부록/용어집.md)`)는 브라우저 이동 대신 **그 파일을 탭으로** 연다. Alt+클릭 = 분할로. 링크를 품은 문서의 폴더에서 출발해 `../`·하위 폴더명을 클라이언트가 트리에서 풀며, 서버 변경 없음.
- 줄 번호 앵커(`#L16-L26`)가 붙으면 파일을 열고 **그 줄로 스크롤 + 형광펜 하이라이트** (코드 뷰어).
- 대상이 트리에 없으면(업로드 범위 밖·공유 문서 기준) "연결된 파일을 찾을 수 없습니다" 토스트. 외부 URL(`http…`)과 `#제목` 앵커는 기존 브라우저 동작 그대로.

## 읽는 흐름 개선 (2026-08-31, v0.17)

서버 변경 없는 클라이언트 확장. "설명 md + 대상 코드(html)"를 나란히 읽는 흐름을 목표로 한다.

**코드로 보기 (SCR-150 확장)**
- ⋯ 메뉴에 **"코드로 보기 ↔ 문서로 보기"** 토글. md·html·텍스트를 렌더링 대신 코드 뷰어(문법 강조 + 줄 번호)로 보여준다. 같은 본문을 보여주는 방식만 바꾸는 것이라 서버·저장과 무관, 상태는 세션 한정.
- **줄 번호 앵커(`#L16-L26`)가 붙은 링크로 열리면 자동으로 코드 보기** — 줄을 가리키는 링크는 "코드를 보라"는 뜻으로 해석한다. 이로써 html 대상 줄 앵커도 동작하게 된다 (기존에는 렌더링돼 버려 줄 하이라이트가 불가능했다).
- 코드 보기 중에는 목차 버튼을 숨기고, 읽던 위치 저장도 멈춘다 (검사용 임시 모드이지 읽기 모드가 아니다 — 렌더링 보기의 읽던 위치를 덮어쓰지 않게).

**탭 우클릭 메뉴 + Alt+클릭 (SCR-153 확장, PC 전용)**
- 탭 우클릭 → 컨텍스트 메뉴: 분할로 열기 / 닫기 / 다른 탭 모두 닫기 / 오른쪽 탭 모두 닫기. 일괄 닫기에 미저장 문서가 섞여 있으면 확인 한 번.
- **Alt+클릭 = 분할로 열기** — 트리·md 링크와 같은 문법을 탭에도 준다 (배울 게 늘지 않게 문법 통일).

**탭 드래그 배치 (SCR-153·154, v0.15에서 "후속(v2)"로 미뤘던 것)**
- 탭을 끌어 **탭 바 안에 놓으면 순서 바꾸기**, **본문 영역에 놓으면 배치**: 기존 칸 위 = 그 칸에 표시(이미 다른 칸에 보이는 문서면 두 칸을 맞바꿈), 오른쪽 끝(세로 분할이면 아래 끝) 스트립 = 새 칸으로 분할.
- 드래그 중에만 본문 위에 드롭 존 오버레이를 깐다 — iframe(HTML·PDF)이 드래그 이벤트를 삼키는 문제를 드래그 막(비율 드래그와 같은 수법)으로 푼다. 터치에는 탭 바가 없으므로 PC 전용.

**분할 구분선 히트 존 보정 (SCR-155)**
- 구분선의 넓은 투명 히트 존(±12px)이 왼쪽 칸의 세로 스크롤바를 덮어 스크롤바를 집기 어려웠다. **PC(정밀 포인터)에서는 히트 존을 왼쪽(첫 칸 쪽)으로 확장하지 않는다** — 스크롤바가 구분선에 붙는 쪽은 왼쪽뿐이고, 넓은 존은 애초에 손가락용이다. 터치는 그대로 ±12px.

**단축키 레지스트리 (도움말 화면은 후속)**
- 단축키·제스처 정의를 `lib/shortcuts.ts` 한 곳에 모은다. 후속(설정 → 단축키 도움말, `?` 치트시트)이 이 목록을 읽어 그린다 — 도움말을 손으로 쓰면 반드시 낡는다 (ERD 이중 기재 원칙과 같은 이유).

## 정리하는 흐름 — 트리 폴더 선택 + 키보드 탐색 (2026-08-31, v0.18)

서버 변경 없는 클라이언트 확장. 다중 선택(Ctrl/Shift+클릭)과 트리 내부 드래그 이동(스프링 로딩 포함)은 기존 기능 — 이번에 더하는 것은 둘이다.

**폴더 선택 (SCR-110 확장, 목록 보기 전용)**
- 폴더 행 클릭 = **펼침 토글 + 선택**. 선택된 폴더는 파일처럼 강조되고, 패널의 **"+ 업로드" / "+ 폴더" / "폴더째 업로드"가 그 폴더를 대상**으로 동작한다 (기존에는 항상 최상위였고, 폴더 지정은 우클릭 메뉴로만 가능했다).
- 선택은 다른 폴더를 클릭하거나 트리의 빈 곳을 클릭하면 풀린다. 파일을 열어도 유지된다 — "이 폴더에서 작업 중"이라는 상태이지 일회성 지정이 아니다.
- 격자 보기(FileGrid)에는 적용하지 않는다 — 격자는 훑어보기 화면이고, 정리 작업은 목록에서 한다.

**키보드 탐색 (SCR-110 확장, PC)**
- 트리가 포커스를 받으면(클릭 또는 Tab): **↑/↓** 위아래 이동(펼쳐진 행 순서), **→** 폴더 펼치기·펼쳐져 있으면 첫 자식으로, **←** 폴더 접기·파일이면 부모 폴더로, **Enter** 파일 열기/폴더 토글+선택, **Space** 파일 다중 선택 토글, **F2** 이름 변경, **Delete** 삭제(파일=휴지통+실행 취소 토스트, 폴더=확인 대화상자 — 기존 삭제 흐름 그대로).
- 포커스 행은 얇은 테두리로 표시하고, 화면 밖으로 나가면 따라 스크롤한다. 이름 변경 입력 중에는 트리 단축키를 멈춘다.
- 새 단축키는 전부 `lib/shortcuts.ts` 레지스트리에 등록한다.

## 내 공간 — 테마 + 단축키 도움말 (2026-08-31, v0.19)

**앱 테마 프리셋 (SCR-141 확장)**
- 앱 껍데기(레일·패널·탭·헤더)의 색을 프리셋으로 고른다: **미드나잇 블루(기본, 기존 색) · 그래파이트 · 딥 그린 · 오베르진 · 페이퍼(라이트) · 아이보리(라이트 웜)**.
- 구현 방식: Tailwind 4의 색 유틸리티가 CSS 변수를 참조하는 것을 이용해, **`[data-app-theme=…]` 아래에서 slate·sky 램프 변수만 재정의**한다. 컴포넌트의 클래스는 한 줄도 바꾸지 않는다 — 새 테마 추가 = index.css에 변수 블록 하나. 라이트 테마는 램프를 뒤집는다(어두움 기준으로 짜인 의미 체계 — `bg-slate-950`=앱 배경, `text-slate-100`=본문 — 를 그대로 유지하기 위해).
- 저장은 localStorage(`dv_apptheme`) — 보기 모드(list/grid)와 같은 "기기별 취향" 분류. 서버 설정이 아니므로 스키마 변경 없음. 라이트 테마는 `color-scheme: light`로 스크롤바·네이티브 컨트롤도 맞춘다.
- 코드 뷰어의 어두운 배경(에디터 관례)과 뷰어 본문 테마는 앱 테마와 독립 — "밝은 껍데기 + 어두운 본문" 조합도 가능하다.

**뷰어 테마 확장 (SCR-141)**
- 3종 → 6종: 라이트 · 세피아 · **북 그린(연녹 종이)** · **그레이(눈부심 줄인 연회색)** · 다크 · **나이트(부드러운 다크)**.
- 렌더러들의 다크 판정은 `theme === 'dark'` 직접 비교 대신 공용 `isDarkViewerTheme()`로 통일한다 — 테마를 더할 때 판정 누락이 안 나게. HTML 문서에 남기는 `data-theme` 표식은 기존 3값(light/dark/sepia) 계약을 유지하고 새 테마를 가장 가까운 값으로 접는다.
- 서버 zod enum·Drizzle enum도 함께 확장 (컬럼 자체는 text — 마이그레이션 없음).

**단축키 도움말 (SCR-145 신설) + 신규 단축키**
- `?` (또는 Ctrl+/) 어디서든 → 단축키·제스처 치트시트 오버레이. 설정 패널의 "단축키·제스처" 버튼도 같은 오버레이를 연다. 내용은 `lib/shortcuts.ts` 레지스트리를 읽어 그린다 (손으로 쓴 표 금지 — 레지스트리 원칙).
- 신규 단축키 (입력 중에는 무시): **E** = 활성 문서 편집 (⋯ 메뉴가 이미 "편집 (E)"라고 약속하고 있었으나 미구현이었다), **Z** = 몰입 모드 토글, **Ctrl+B** = 왼쪽 패널 접기/펴기(PC), **Alt+1~4** = 분할 칸 활성화.
