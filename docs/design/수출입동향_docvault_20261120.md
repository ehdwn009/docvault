# 수출입 동향 설계: docvault

| 작성자 | | 작성일 | 2026-11-20 | 버전 | v0.1 | 상태 | 1단계(도착·보관·알림) v0.67.0 · 2단계(자동 해부) v0.68.0 · 3단계 시안 검토 중 |

산업통상부가 매달 1일 내는 「YYYY년 M월 수출입 동향」 보도자료(PDF 약 36쪽)를 Loft가 알아서 가져와 쌓고, 36쪽을 빠짐없이 읽어 **헤드라인을 문장 단위로 해부하고, 떨어진 쪽의 수치·해설 사이 관계를 이어서** 보여 준다.

- 토론 보고서: [docs/수출입동향_자동수집_토론보고서_20261120.html](../수출입동향_자동수집_토론보고서_20261120.html)
- 화면 시안(헤드라인 해부): https://claude.ai/artifact/2fiF5M6mx8b49XG1E7jJVv (비공개 링크)

## 사용자 요구 (2026-11-20)

- 사이트에서 매번 자동으로 가져온다. **예약 시각에 안 올라와 있으면 그것도 알린다.**
- 숫자 추이와 짧은 해설만으로는 부족하다. **PDF의 해설 문장을 전부 읽고 가져다 쓴다.** 크고 중요한 것만 추리다 세밀한 변화를 놓치면 나비효과가 된다.
- 3쪽 표와 7쪽 표처럼 **떨어진 수치들 사이의 관계**를 놓치지 않는다. 원문을 통째로 재현하자는 것은 아니다.
- 헤드라인은 포괄적인 숫자만 늘어놓지 말고 **파고들 수 있게** 한다.

## 원칙

- **숫자의 근거는 원문 PDF 하나.** AI가 쓴 문장 속 숫자와 인용은 전부 그 쪽 텍스트와 글자 단위로 대조하고, 대조에 실패한 것은 버린다(시안에서 인용 415개 전부 통과). 원문 숫자로 계산한 값은 "✎ 계산"으로 따로 표시하고 식을 남긴다.
- **원본은 Loft 문서로 남긴다.** PDF는 「수출입동향」 폴더에 보통 파일로 쌓인다 — 검색·휴지통·내보내기·백업이 기존 그대로 동작한다. 브리핑과 같은 결정이다("회차 하나 = 문서 하나").
- **모든 계정이 본다.** 공공누리 제1유형(출처표시) 자료라 폴더를 전체 공개(`folders.is_shared=1`)로 두고, 도착 알림도 모든 계정에 보낸다. 못 가져왔다는 알림은 할 수 있는 일이 있는 관리자에게만.
- **사이트에 예의를 지킨다.** 평소 한 달 요청은 20회 안팎, 소급은 요청 사이 3초. User-Agent는 개인정보 없는 일반 이름. robots.txt는 `/kor/article`·`/attach/down`을 허용한다(2026-11-20 확인).
- **외부 의존 제로 원칙과의 경계.** 사이트가 바뀌어 못 가져와도 Loft의 다른 기능은 멈추지 않고, 이미 받은 PDF는 문서로 남는다. 바뀐 것은 알림으로 안다.

## 1단계 — 도착과 보관

### 어디를 보나 (2026-11-20 실측)

- 보도자료 게시판 `ATCL3f49a5a8c`. 목록 검색 `GET /kor/article/ATCL3f49a5a8c?searchCondition=1&searchKeyword=수출입&startDtD=…&endDtD=…&pageIndex=N`(한 쪽 10줄). 날짜 필터가 동작한다.
- **RSS는 쓰지 않는다.** 최근 10건(약 3일치)뿐이라 하루에 보도자료가 많으면 1일 글이 밀려나고, 첨부·부서 정보가 없다.
- **검색어는 "수출입"이다.** "수출입 동향"으로 찾으면 띄어쓰기 없이 올라온 2026년 8월호 「수출입동향」이 빠진다.
- 목록 줄에서 글 번호(`article.view('172360')`)·제목·담당 부서·등록일을 읽고, 상세 `…/{글번호}/view`에서 첨부 링크(`/attach/down/…` + `title="파일명 다운로드"`)를 읽는다. **PDF만 받는다**(확장자로 판단) — 최근 13개월 모두 PDF가 있었고(13/13), 원본은 HWPX 5개월·구형 HWP 8개월로 들쭉날쭉하다. 첨부 순서도 달마다 다르다.
- 다운로드 응답에 ETag·Last-Modified가 없다. 같은 파일인지는 sha256으로 본다.

### 제목 판정

수집 담당이 게시판 597줄 전부로 검증한 규칙(2015-12~2026-10 정규 게시 131개월, 빈틈·중복·대상월 불일치 0)을 그대로 옮긴다.

1. NFKC 정규화, 공백 정리.
2. `수출입\s*동향`이 있어야 한다.
3. 제외어 중 하나라도 있으면 아니다: ICT·정보통신·디지털·IT산업·서비스·에너지·지역별·전략물자·점검·고시·물류·비교·대책·상정·경쟁국·안전인증. (같은 달 「정보통신산업(ICT) 수출입 동향」, 「전략물자 수출입고시」가 검색에 함께 걸린다.)
4. 제목에서 연월을 읽는다(`2026년 10월`, `'26년 10월`, `2025년 연간 및 12월` 모두). 못 읽으면 **담당 부서가 수출입과이고 등록일이 1~3일**일 때 등록월의 전월로 본다.
5. 읽은 연월이 "등록월의 전월"과 같아야 통과한다.
6. 2016-12-09에 일괄 이관된 과거 글(1997~2015년, 대부분 HWP)은 대상이 아니다.

### 언제 보나 — 예약 시각과 게시 시각이 어긋나도 되게

보도는 매달 1일 11:00(일요일이어도 1일)인데 게시판에 오르는 정확한 시각은 알 수 없다. 그래서 시각 하나에 걸지 않고 **창(window)을 둔다.** 서버의 1분 틱이 한국시간을 보고, 대상 달(지난달) 호가 아직 없으면 아래 시각마다 한 번씩 목록을 본다.

| 날 | 확인 시각(한국시간) | 못 찾았을 때 |
|---|---|---|
| 1일 | 11:10 · 13:00 · 18:00 | 18:00에도 없으면 관리자에게 「아직 안 올라왔어요 — 2일부터 매일 10시에 다시 봅니다」 |
| 2~10일 | 매일 10:00 | 4일 10:00에도 없으면 관리자에게 「4일까지 못 찾았어요 — 게시판을 직접 확인해 주세요」 |

- 서버가 그 시각에 꺼져 있었으면 켜진 뒤 첫 틱에 지난 시각분을 한 번 본다(같은 시각을 두 번 보지 않는다 — 기억은 메모리, 재기동하면 마지막 지난 시각을 한 번 더 볼 수 있으나 해가 없다).
- 10일이 지나면 그 달은 더 보지 않는다. 다음 달 1일에 대상이 바뀐다.
- 찾으면 그 달의 남은 확인은 하지 않는다.

### 저장

- **폴더**: 첫 관리자(가장 작은 id의 활성 관리자) 소유의 최상위 폴더 「수출입동향」, `is_shared=1`. 폴더 id는 `app_settings`의 `trade_folder_id`에 적는다. 폴더가 지워졌으면 다시 만든다.
- **파일**: `2026년 10월 수출입 동향.pdf`(이름이 겹치면 기존 사본 규칙), 보통 PDF 파일(`kind='doc'`, `file_type='pdf'`). 바이너리 저장 규칙 그대로 `data/files/{ownerId}/{uuid}`.
- **기록**: `trade_releases`에 한 줄(아래 ERD). `(source, period)`가 유일 — 같은 달을 두 번 받지 않는다. 정정본 감시(게시 후 재확인)는 하지 않는다: 다음 달 호의 13개월 표가 고친 값을 어차피 실어 온다(9월→10월호 겹치는 396칸 중 약 100칸 정정 실측).
- **크기 상한**: PDF 30MB(`TRADE.PDF_MAX_BYTES`). 실측 최대 2.44MB(2026년 6월호)라 브리핑 본문 상한(2MB)은 쓸 수 없다. 응답이 `%PDF`로 시작하지 않으면 받지 않는다.

### 소급

`trade_releases`가 비어 있으면(처음 배포) 서버가 켜진 뒤 한 번, 최근 12개월(대상 달 포함 12개)을 채운다. 목록을 날짜 범위로 넘기며 후보를 모으고, 달마다 상세 → PDF 순으로 요청 사이 3초를 둔다. 달마다 알림을 보내면 12통이라, 끝나면 **한 통**(「수출입 동향 지난 12개월치를 담았어요」)만 모든 계정에 보낸다. 일부를 못 받으면 받은 것만 남기고 관리자에게 못 받은 달을 알린다 — 다음 기동 때 소급은 다시 돌지 않는다(표가 비어 있지 않으므로). 빠진 달은 다음 단계의 수동 확인으로 채운다.

### 알림

| 종류 | 받는 사람 | 제목 / 본문 | 누르면 |
|---|---|---|---|
| `trade_ready` | 모든 활성 계정 | 「10월 수출입 동향이 올라왔어요」 / 「산업통상부 · 11월 1일 · PDF 36쪽」 | 그 PDF |
| `trade_missing` | 관리자 | 「10월 수출입 동향을 아직 못 찾았어요」 / 이유 | 없음 |

`dedupe_key`: `trade:{period}:ready`, `trade:{period}:missing:{d1|d4}`, `trade:backfill`. 사이트가 바뀐 것으로 보이면(목록 응답은 200인데 줄을 하나도 못 읽음, 404, 다른 주소로 이동) 이유에 그대로 적는다.

## 2단계 — 해부 결과 받기 (v0.68.0)

새 호를 받으면 서버가 **claude.ai 예약 작업을 켜서** 분석 스킬 `trade-report`(`.claude/skills/trade-report/`)를 돌리고, 돌아온 해부 결과를 **다시 대조한 뒤** 저장한다. 예약 시각을 따로 정하지 않으므로 게시 시각과 어긋날 일이 없다 — "찾는 순간 켠다".

### 사용자 쪽 새 설정은 없다

브리핑 구독에 이미 연결해 둔 것을 그대로 쓴다(사용자 결정 2026-11-20 "매달 자동 실행").

- **트리거**: 브리핑 구독의 예약 작업 fire 주소·토큰(USER_SETTINGS.briefing_trigger_enc). 트리거를 넣어 둔 관리자가 없으면 해부는 조용히 건너뛴다 — 1단계(PDF·알림)는 그대로 동작한다.
- **연결 열쇠**: 같은 열쇠, 같은 경로 접두어 `/api/v1/briefing/jobs/`. 클라우드 환경의 네트워크 시크릿이 이 접두어에만 붙으므로 수출입 일감의 주소도 그 아래에 둔다(`…/jobs/{jobId}/trade/…`). 이 접두어는 "예약 작업이 서버를 부르는 공용 창구"다 — 지시서의 `kind`가 일감 종류를 가른다(`edition` 브리핑 회차 · `ping` 연결 확인 · `trade` 수출입 동향 해부).
- **예약 작업 지시문**: 그대로("…BRIEFING_JOB_ID로 briefing-subscription 스킬을 실전 모드로 실행해"). 그래서 서버가 쏘는 줄도 `BRIEFING_JOB_ID=<uuid> — …`이고, briefing-subscription 스킬이 지시서의 `kind: "trade"`를 보고 `trade-report` 스킬로 넘긴다.
- **네트워크**: 세션은 산업통상부 사이트에 접속하지 않는다 — 원문 쪽별 텍스트를 서버가 준다("재료는 서버가", 브리핑 v0.59와 같은 결정).

### 흐름

| 누가 | 하는 일 |
|---|---|
| 서버 | 새 호 PDF를 받은 직후(정기 확인), 또는 기동 뒤 첫 틱에 "가장 최근 호에 해부가 없고 시도한 적도 없으면" → `trade_jobs`에 한 줄(`job_id` uuid, 마감 = 지금 + 3시간) → 예약 작업 fire. 호마다 자동 시도는 한 번 — 실패를 매분 다시 켜면 사용량이 샌다 |
| 세션 | 지시서(API-151, `kind: "trade"`) → 쪽별 텍스트(API-157) → 에이전트 A·B·C가 조사 → 리더가 엮기 → `npm run trade:job -w server -- build`로 **서버와 같은 코드**로 대조 → 완성본(API-158) |
| 서버 | 완성본을 원문 쪽 텍스트와 **다시 대조**(세션의 대조를 믿지 않는다). 통과하면 ① 해부 JSON을 `trade_releases.analysis_json`에 ② 같은 내용을 담은 한 장짜리 HTML 문서(「2026년 10월 수출입 동향 해부.html」)를 「수출입동향」 폴더에 ③ 모든 계정에 도착 알림. 3단계 전용 화면이 생기기 전까지는 이 HTML 문서가 화면이다 |
| 서버 | 마감까지 완성본이 안 오면 `missing`, 트리거를 못 쏘면 `error` — 관리자에게 「해부를 만들지 못했어요」 알림 |

### 서버의 대조 (`lib/trade/verify.ts` — 스킬의 `trade:job build`와 같은 함수)

- `{page, quote}`가 있는 모든 자리: 그 쪽 텍스트에 quote가 있어야 한다(띄어쓰기·줄바꿈만 무시). 전월 호 인용은 `doc: "prev"` 또는 `prev` 열쇠 아래.
- 목록의 한 항목이 틀리면 그 항목만 뺀다. **1쪽 문장(claims[].claim)이 틀리면 거절**(422) — 조용히 빼지 않고 고쳐 다시 보내게 한다(`TRADE.RESULT_RESEND_MAX`번까지).
- 풀어보기(underneath)는 인용이 있거나 "원문 숫자로 계산" + 식이 있어야 한다.
- **숫자 표**(`tableRows`): 줄마다 출처 줄 인용이 원문에 있고, 값 하나하나가 그 줄에 그대로 있어야 한다. 화면의 13개월 추이(series·itemSeries)는 세션이 준 값을 쓰지 않고 **대조를 통과한 tableRows에서 서버가 만든다** — 표와 그림이 어긋날 수 없다.
- 뺀 항목이 인용의 30%를 넘거나 claims가 비면 거절.
- 뺀 항목을 가리키던 id는 걷어 낸다.

### Docker

## 3단계 — 전용 화면 (시안 검토 중)
