## 1. 조사 개요

| 항목 | 내용 |
|---|---|
| 조사 목적 | docvault(폐쇄형 문서 열람·편집 플랫폼)가 대체하려는 기존 앱들의 기능·과금·불만을 파악하고, 보강·차별화 방향을 도출한다 |
| 조사 범위 | ① iOS 문서 뷰어/파일 관리자 ② 로컬 HTML/MD 뷰어·에디터 ③ 노트/위키형 문서 도구 ④ 셀프호스팅 문서·서재 플랫폼 |
| 조사 방법 | 데스크리서치 — 공식 사이트/문서, App Store 설명·리뷰 집계 사이트(JustUseApp, AppGrooves 등), 커뮤니티(Reddit, MacRumors 포럼), GitHub 이슈 |
| 조사 기간 | 2026-08-18 (1일) |

조사의 출발점은 작성자 본인의 페인 포인트다: **아이폰에서 로컬 HTML 학습자료(긴 정독본)를 열어 보기 어렵고, Documents by Readdle의 유료 구독은 쓰기 싫다.** 따라서 이 보고서는 일반적 시장 규모 산정보다 "같은 페인을 가진 사용자들이 무엇을 쓰고, 무엇에 불만인가"에 집중한다.

## 2. 시장 정의 및 세분화

"개인이 자기 문서를 모바일(특히 iOS)에서 열람·정독·관리하는 도구" 시장으로 정의하고, 4개 세그먼트로 나눈다.

| 세그먼트 | 대표 제품 | 특성 |
|---|---|---|
| A. iOS 파일 관리자 + 뷰어 | Documents by Readdle, GoodReader, FileBrowser | 파일 반입·정리 중심, 뷰어는 PDF 위주 |
| B. 로컬 HTML/코드 뷰어·에디터 | HTMLViewer Pro+, HTML Reader, Textastic, Koder | iOS 사파리가 로컬 HTML을 제대로 못 여는 틈새를 메움 |
| C. 노트/문서 앱 | Obsidian, Notion | MD 작성·정리 중심, 열람은 부수 기능 |
| D. 셀프호스팅 문서·서재 | Outline, BookStack, Wiki.js, Kavita, Calibre-web, Paperless-ngx | 내 서버가 원본, 웹으로 접근. docvault가 속한 세그먼트 |

배경 사실: iOS 사파리는 로컬 HTML 파일을 상대경로 리소스까지 포함해 직접 열 수 없어(Apple 개발자 포럼에서 반복 확인되는 제약), 세그먼트 B라는 니치가 형성되어 있다. 이는 docvault의 문제의식이 실재하는 수요임을 뒷받침한다.

## 3. 시장 규모 및 성장 전망

개인 프로젝트 특성상 정량적 TAM/SAM/SOM 산정은 이 조사의 목적이 아니며 수행하지 않았다. 정성적 근거만 남긴다.

- Documents by Readdle는 App Store 리뷰 수십만 건 규모의 대형 앱으로, "파일 반입+열람" 수요 자체는 대중적이다.
- 셀프호스팅 세그먼트는 Outline(GitHub 스타 35K+), Kavita, BookStack 등이 활발히 성장 중 — 구독 거부·데이터 소유 흐름을 탄 확장 시장이다.

## 4. 시장 동향 / 트렌드

| 트렌드 | 내용 | 근거 |
|---|---|---|
| 구독 전환에 대한 반발 | 일회성 구매였던 앱들이 구독으로 전환하며 사용자 이탈·혹평 반복. GoodReader는 고가 일회성 옵션($79.99)을 따로 만들어 구독 거부층을 흡수 | Documents·GoodReader·Textastic 리뷰, Tom's Guide 포럼 |
| 데이터 소유·셀프호스팅 확산 | "내 서버에 내 문서" 수요 증가. r/selfhosted 계열 생태계 성장 | Outline·Kavita·Paperless-ngx의 성장 |
| 오프라인 우선 재평가 | 클라우드 우선의 대표주자 Notion이 수년간의 불만 끝에 2025-08 오프라인 모드 도입 | TechCrunch 2025-08-20 |
| 네이티브 앱 대신 PWA | 셀프호스팅 진영은 대부분 전용 앱 없이 반응형 웹+PWA로 대응하고, 사용자도 수용 | Outline 공식 문서, BookStack 23.10 릴리스 |
| 방치 리스크에 민감 | 업데이트가 끊긴 앱(Koder, Wiki.js v3)에서 사용자가 빠르게 이탈 | 커뮤니티 이탈 논의 다수 |

## 5. 고객 분석

| 세그먼트 | 특성 | 핵심 니즈 | 페인 포인트 |
|---|---|---|---|
| 학습자 (작성자 본인 유형) | 긴 학습자료(HTML/MD)를 만들어 폰으로 정독 | 읽던 위치 이어읽기, 목차, 다크모드, 글자 크기 | 로컬 HTML을 iOS에서 열기 어려움, 리더 기능 부재 |
| 구독 거부층 | 도구는 사되 구독은 거부 | 일회성 구매 또는 무료/자가호스팅 | 기존 앱들의 구독 전환·가격 인상 |
| 셀프호스터 | NAS/서버 운영, 데이터 소유 중시 | 웹 접근, 백업 용이성, 꾸준한 유지보수 | 설정 난이도, 프로젝트 방치, 백그라운드 작업 불안정 |
| 아카이버 | 웹페이지·문서를 저장해 두고 다시 읽음 | 통째 저장, 오프라인 열람, 검색 | 반입 워크플로가 수동적, 미리보기 불안정 |

### 6.2 리더 기능 보유 현황 (긴 HTML/MD 정독 관점)

| 제품 | 읽던 위치 기억 | 목차 | 글자 크기 조절 | 다크모드 | 오프라인 |
|---|---|---|---|---|---|
| Kavita | O (서버 저장, 기기 간) | O | O | O | △ (서버 접속 필요) |
| HTMLViewer Pro+ | 확인 못 함 | 확인 못 함 | 확인 못 함 | O | O (로컬) |
| Textastic | X (편집기 관점) | △ (심볼 목록) | O (폰트) | O | O (로컬) |
| Documents / GoodReader | PDF는 기억 (HTML은 아님, 추정) | PDF 목차만 | PDF 확대 위주 | 부분 | O (로컬) |
| Obsidian | △ (플러그인) | O (헤딩) | O | O | O (로컬) |
| Notion / Outline / BookStack | X (확인 범위 내) | O (헤딩) | X~△ | O | X~△ |
| **docvault (현재)** | **O (서버 저장)** | **O (헤딩)** | **X (미구현)** | **O (테마 연동)** | **X (접속 필요)** |

핵심 발견: **"긴 HTML/MD를 모바일에서 정독하는 리더 경험(위치 기억 + 목차 + 글자 크기 + 다크모드 + 오프라인)을 한 번에 갖춘 제품이 없다.** 서재형(Kavita)은 EPUB 중심이고, 위키형은 위치 기억이 없고, HTML 뷰어는 리더 기능이 얕다. docvault는 이미 3개 항목을 갖춰 이 빈칸에 가장 가깝다.

### 6.3 제품별 상세

#### Documents by Readdle (기준 제품)
- **기능**: 파일 열람·정리·클라우드 동기화, 내장 PDF 리더, 미디어 플레이어, 내장 브라우저(파일 다운로드), ZIP 해제.
- **과금**: Starter(무료) / Plus(고급 PDF 편집·주석·서명) / Pro(AI 요약). Pro 연 $29.99 안내, Plus $9.99/월 표기도 확인(지역·시기별 변동).
- **실제 불만** (JustUseApp·AppGrooves 리뷰, MacRumors 포럼):
  - "예전엔 $5 일회성이었는데 지금은 월 $12.95" — 가격 배신감이 리뷰에 반복 등장
  - 앱 내 Readdle 자사 앱 상시 홍보 배너
  - iOS 업데이트 후 즐겨찾기 초기화·파일 재다운로드 사례
  - iCloud 다중 다운로드 시 큐 제어(중지·순서 변경) 불가
  - 큰 파일에서 미리보기 표시 불안정
- **docvault 시사점**: "관리 기능은 무료, 정작 쓰고 싶은 기능은 구독"이라는 구조와 광고가 핵심 이탈 요인. 반면 "무료 범위가 넓은 뷰어+파일관리 통합" UX 자체는 참고 가치.

#### GoodReader
- **기능**: PDF 주석·멀티윈도우, 주요 클라우드 연동. 읽던 위치 기억은 직접 확정하지 못함(추정: PDF 리더 표준 기능으로 보유 가능성 높음).
- **과금**: 기본 $5.99 + Pro Pack 구독 $17.99/년, 또는 **일회성 $79.99 (구독 없음)**.
- **불만**: 고급 기능 구독화 반발, 간헐적 크래시·동기화 문제.
- **시사점**: 구독 거부층이 고가 일회성도 지불할 만큼 실재한다. docvault는 자가호스팅이라 이 문제 자체가 없음이 강점.

#### FileBrowser (Stratospherix)
- **기능**: SMB/NAS/클라우드 접속 특화 파일 관리자. 일회성 구매. 지원 응답 빠름(24시간 내).
- **불만**: SFTP 대용량 다운로드 멈춤("Calculating..."), 초기 접속 디렉터리 지정 불가, 홍보와 실기능 불일치.
- **시사점**: "네트워크의 파일을 아이폰에서 본다"는 목적은 같지만 열람 경험이 부차적 — docvault처럼 열람을 1급 기능으로 만드는 것이 차별화.

#### HTML 뷰어·에디터군 (HTMLViewer Pro+, HTML Reader, Textastic, Koder)
- **HTMLViewer Pro+**: 오프라인 HTML 열람·편집, WebKit 렌더링, 소스 보기, 다크모드, 폴더·즐겨찾기·검색.
- **HTML Reader**: 통째로 저장한 웹사이트 오프라인 열람, ZIP 해제.
- **Textastic**: HTML/MD 로컬 미리보기(외부 리소스는 같은 샌드박스 폴더 필요), 심볼 목록, 커스텀 폰트. $9.99 일회성이었다가 구독 병행으로 전환.
- **Koder**: 무료였으나 2022년 이후 업데이트 중단, 사실상 방치.
- **시사점**: 이 니치의 한계는 ① 방치 리스크 ② 편집기 관점이라 정독(리딩) 기능 빈약 ③ ZIP 수동 반입 워크플로. docvault의 서버 저장+ZIP 내보내기가 반입 문제를 근본 해결. HTMLViewer Pro+가 내세우는 "다크모드+즐겨찾기+검색"은 이 시장에서 팔리는 기능 세트라는 방증.

#### Obsidian
- **기능**: 로컬 MD 볼트, 플러그인 생태계, 모바일 앱. 동기화는 유료 애드온(연 결제 시 월 $8 수준).
- **불만**: 모바일 기동 iPhone 11급 5~8초, 플러그인 25개+면 수십 초(지연 로딩 플러그인이 따로 생겼을 정도). 큰 파일에서 메모리 한계로 크래시. iCloud 동기화 느림. 1.7.x에서 공식적으로 기동 성능 개선 착수(문제 인정).
- **시사점**: 모바일에서 "즉시 열림"이 결정적 품질 지표. 초기 로드 최소화·큰 문서 처리를 신경 쓸 것. "동기화에 돈 내라" 구조가 욕먹는 지점 — docvault는 서버가 곧 원본이라 동기화 문제가 없다.

#### Notion
- **불만**: 수년간 1순위 불만이 오프라인 불가 + 모바일 느림. 2025-08에야 오프라인 모드 도입(페이지 다운로드 방식, 일부 블록은 여전히 온라인 필요).
- **시사점**: 클라우드 우선 구조의 반면교사. docvault도 약한 회선·폐쇄망에서의 열람 내성(캐시)을 로드맵에 둘 가치.

#### 셀프호스팅 위키 (Outline, BookStack, Wiki.js)
- **Outline**: GitHub 스타 35K+, MD 호환, 빠름. 네이티브 앱 없음 — 공식적으로 PWA(홈 화면 추가) 안내.
- **BookStack**: 책-챕터-페이지 구조 직관적. 23.10에서 PWA 매니페스트 기본 추가. 전용 앱 없음.
- **Wiki.js**: v3가 2021년부터 개발 중이나 2026년 현재 베타도 미출시("No ETA"), v2는 유지보수 모드 — 사용자 이탈 진행.
- **시사점**: docvault와 가장 유사한 카테고리. 공통 해법이 "반응형 웹+PWA"이고 수용됨 → docvault의 SPA 접근이 시장 표준과 일치. Wiki.js 사례는 거창한 리라이트보다 꾸준한 소규모 릴리스가 신뢰를 만든다는 교훈.

#### 셀프호스팅 서재 (Kavita, Calibre-web)
- **Kavita**: EPUB·PDF·만화 리딩 서버. **읽던 위치를 서버에 저장해 기기 간 이어읽기**가 핵심 셀링포인트. 반응형 웹 리더 내장, iOS는 서드파티(Panels)가 OPDS+진행도 API로 연동. 단, 1단/2단 모드 전환 시 진행도 어긋나는 동기화 드리프트 이슈 존재(GitHub #4446).
- **Calibre-web**: Calibre 서재의 웹 프론트엔드, Kobo 동기화. 불만은 주로 Docker·리버스 프록시 설정 난이도.
- **시사점**: "읽던 위치 서버 저장 + 기기 간 이어읽기"가 이 카테고리의 킬러 기능. 진행도는 픽셀이 아니라 문서 구조(헤딩/블록) 기준으로 저장해야 화면 폭이 달라져도 안 어긋난다는 것이 Kavita 이슈의 교훈 — **docvault의 현재 이어읽기는 scrollTop(픽셀) 저장이라 같은 함정에 해당**.

#### Paperless-ngx
- **기능**: 스캔 문서 아카이빙(OCR·태깅·검색). 공식 모바일 앱 없이 서드파티 Swift Paperless(4.9점)가 빈틈을 메움.
- **불만**: 임포트 작업 불안정 — "Database is locked", "File not found"에 자동 재시도 없음, 재시작 필요.
- **시사점**: 셀프호스팅 앱은 백그라운드 작업의 안정성(자동 재시도·명확한 상태 표시)이 체감 품질을 좌우. 개방 API가 서드파티 생태계를 만든다는 점도 확인.

## 7. 종합 분석 (docvault 관점 SWOT)

| 강점(S) | 약점(W) |
|---|---|
| 구독·광고 없음(자가호스팅), 서버가 원본이라 동기화 문제 자체가 없음, 이어읽기·목차·테마 등 리더 기능 기반 보유, 폐쇄망 대응(폰트 자가호스팅), 꾸준한 릴리스 문화(CHANGELOG) | 1인 개발(방치 리스크와 동일 구조), 오프라인 열람 불가(접속 필수), 글자 크기 조절 미구현, 이어읽기가 픽셀 기준, 형식 지원 범위 아직 좁음(MD/HTML) |

|---|---|

## 8. 기회 및 시사점

우선순위 순:

1. **리더 모드 완성이 최대 차별화** — 시장의 빈칸. 이미 있는 이어읽기·목차·다크모드에 ① 글자 크기·줄간격 조절 ② 이어읽기의 헤딩(앵커) 기준 전환(Kavita 드리프트 교훈)을 더한다.
2. **PWA 매니페스트** — 홈 화면 추가만으로 "앱처럼" 열리게. Outline·BookStack·Kavita 모두 이 노선으로 성립. 저비용 고효율.
3. **오프라인 내성** — 최근 문서 서비스워커 캐시까지 가면 Notion류 약점을 완전히 회피. (장기 과제)
4. **모바일 기동 속도를 품질 지표로** — Obsidian 반면교사. "열자마자 읽힌다"가 체감 품질의 절반.
5. **백그라운드 작업 안정성** — ZIP 내보내기·향후 대량 업로드에 명확한 진행 상태와 실패 시 재시도(Paperless-ngx 교훈).
6. **구독·광고 없음을 정체성으로 유지** — 이 시장 이탈 1순위 원인이 과금 구조.
7. **꾸준한 소규모 릴리스 유지** — Wiki.js·Koder의 몰락 vs BookStack의 꾸준함.

## 9. 결론 및 제언

docvault가 겨냥한 페인 포인트(iOS에서 로컬 HTML 정독 + 구독 거부)는 실재하는 수요이며, 이를 온전히 해결하는 기존 제품은 없다. 세그먼트별로 반쪽짜리 해법만 존재한다 — 파일 관리자는 정독 경험이 없고, HTML 뷰어는 반입이 수동이고, 위키는 위치 기억이 없고, 서재형은 EPUB 중심이다. **docvault는 "내 서버의 문서를 모바일에서 책처럼 읽는 리더"로 포지셔닝하고, 8절의 1~2번(리더 모드 완성, PWA)을 다음 릴리스 목표로 제안한다.**
