## 2026-08-14 — 왜 어떤 볼드는 `**` 그대로 보일까 (한글 조사와 CommonMark)

**무슨 일이 있었나**: md 문서에서 `**VM(가상 머신)**`은 볼드가 되는데 `**리버스 프록시(Caddy)**와`는 `**`가 그대로 노출됐다.

**원리는 뭔가**: 마크다운 표준(CommonMark)은 닫는 `**` 앞이 `)` 같은 문장부호이면, 뒤에 공백·문장부호가 와야만 "볼드 닫기"로 인정한다. 영어는 단어 뒤에 바로 글자가 붙을 일이 없어 문제가 안 되지만, 한국어는 조사(`와`, `로`, `입니다`)가 바로 붙어서 자주 걸린다. 표준 자체의 유명한 CJK(한중일) 허점.

**우리 코드 어디를 고쳤나**: 문서를 고치는 대신 뷰어를 고쳤다 — `client/src/renderers/MarkdownRenderer.tsx`에 `remark-cjk-friendly` 플러그인 한 줄 추가. 렌더러 하나를 뷰어·편집기·패치노트가 공유하고 있어서 한 곳만 고치면 전부 적용된다 (모듈화의 이득).

**갈 곳**: 2부 2-8(React·렌더링) 보강 시 실전 사례로

## 2026-08-15 — 폴더를 지우면 휴지통의 파일까지 증발할 뻔한 이야기 (FK cascade의 함정)

**무슨 일이 있었나**: 휴지통 기능(삭제 = soft delete)을 만들다가, 폴더 삭제를 그대로 두면 안 된다는 걸 발견했다. 폴더를 지우는 순간 안의 파일들이 휴지통에 가지도 못하고 DB에서 즉시 하드 삭제된다.

**원리는 뭔가**: 외래 키의 `onDelete: cascade`("가리키던 행이 지워지면 나도 지워라" — 3부 3-4)는 **애플리케이션 코드를 거치지 않고 DB가 직접 실행하는 규칙**이다. 파일이 `folder_id`로 폴더를 가리키고 있는 한, 폴더 행 삭제 = 파일 행 연쇄 삭제. 코드에서 "삭제 전에 휴지통으로 보내야지"라고 생각해도, 사슬이 걸려 있으면 소용없다. 해결은 순서 보장: 트랜잭션 안에서 ① 파일들의 `folder_id`를 먼저 NULL로 끊고(cascade 사슬에서 탈출) 동시에 `deleted_at`을 찍은 뒤 → ② 폴더를 지운다.

**우리 코드 어디를 고쳤나**: `server/src/routes/folders.ts`의 폴더 삭제 라우트 — DELETE 대신 UPDATE(분리+휴지통행) 후 폴더만 삭제. 부수 교훈: soft delete를 도입하면 "그 테이블을 읽는 모든 쿼리"(트리·검색·공유·통계·권한 검사)에 `deleted_at IS NULL` 필터가 필요해진다 — 한 컬럼 추가가 시스템 전체를 훑게 만든다.

**갈 곳**: 3부 3-4(외래 키·cascade) 실전 사례

## 2026-08-15 — HTML 문서의 목차를 눌렀더니 화면이 하얘진 이야기 (iframe 격리와 base URL)

**무슨 일이 있었나**: 목차가 달린 긴 HTML 학습 문서를 docvault에 올리고 목차의 `#앵커` 링크를 눌렀더니, 해당 절로 이동하는 대신 화면 전체가 하얗게 변했다. 파일 탐색기에서 같은 파일을 직접 열면 멀쩡했다.

**원리는 뭔가**: 우리 뷰어는 HTML을 `iframe sandbox`(모래상자) 안에 `srcdoc`으로 넣어 렌더링한다 — 문서가 세션 쿠키나 부모 창을 건드리지 못하게 하는 보안 격리다. 그런데 srcdoc으로 주입된 문서는 **자기 주소가 없어서 부모 페이지의 주소를 base URL(상대 주소의 기준점)로 물려받는다**. 그래서 `href="#s31"`은 "이 문서의 s31로 스크롤"이 아니라 "docvault 앱 주소 + #s31로 이동"으로 해석되고, iframe이 쿠키도 API도 없는 격리 상태로 앱을 다시 로드하려다 빈 화면이 된다. 부수 발견: 같은 격리 때문에 뷰어의 "읽던 위치 저장"도 HTML에서는 죽어 있었다 — 스크롤이 iframe 안에서 일어나서 바깥(Viewer)에는 보이지 않았던 것. 격리된 iframe과 부모가 대화할 유일한 공식 통로는 `postMessage`(쪽지 던지기)다.

**우리 코드 어디를 고쳤나**: `client/src/renderers/HtmlRenderer.tsx` — 문서에 주입하는 심(shim) 스크립트에 두 가지를 추가했다. ① `#앵커` 클릭을 가로채(preventDefault) `scrollIntoView` 스크롤로 바꾼다. ② 스크롤 위치를 `postMessage`로 부모에 보고하고, 열 때는 심어 둔 위치로 복원한다. 받는 쪽(`Viewer.tsx`)은 `e.source`가 그 iframe인 메시지만 신뢰한다. 문서를 고치지 않고 뷰어를 고쳤으므로 앞으로 올릴 모든 HTML 문서에 자동 적용된다 (볼드 사례와 같은 교훈 — 렌더러 한 곳 수정이 전체에 미친다).

**갈 곳**: 1장(웹의 동작 원리 — 주소와 상대 경로) 또는 2부(React·컴포넌트 통신) 보강 시 실전 사례로
