# 0장. 코드가 뭐길래 — 프로그램의 정체와 우리 프로젝트 폴더

## 이 장을 끝내면 알게 되는 것

- [ ] **프로그램·코드·실행**이 무슨 관계인지
- [ ] 코드 파일도 결국 **그냥 글자 파일**이라는 것 (확장자의 의미)
- [ ] **경로**(폴더 주소) 읽는 법
- [ ] **터미널**이 뭐고 개발자들이 왜 쓰는지
- [ ] 우리 프로젝트 폴더에 뭐가 들어 있는지
- [ ] 코드 한 글자를 직접 고쳐서 **화면이 바뀌는 걸 내 눈으로** 확인

---

## 0-1. 프로그램 = 명령서, 코드 = 그 명령서의 글

**프로그램**은 컴퓨터에게 시킬 일을 순서대로 적은 **명령서**입니다. 카카오톡도, 크롬도, docvault도 전부 명령서 뭉치입니다. **코드**는 그 명령서를 사람이 읽고 쓸 수 있게 글자로 적은 것이고, **실행**은 컴퓨터가 명령서를 위에서부터 한 줄씩 따라 하는 일입니다.

요리에 비유하면 — 코드는 **레시피**(글자), 실행은 **요리하는 행위**, 화면에 뜬 docvault는 **완성된 음식**입니다. 레시피를 고치면 다음에 만드는 음식이 달라지듯, 코드를 고치면 다음 실행부터 프로그램이 달라집니다.

실제 예를 봅시다. 우리 서버 코드에 이런 한 줄이 있습니다 (`server/src/index.ts`):

```ts
api.get('/health', (c) => c.json({ status: 'ok', version: APP_VERSION }));
```

암호처럼 보이지만, 한국어로 풀면 한 문장입니다:

> "누가 `/health` 주소로 **물어보면**(get), '상태 좋음, 버전은 이거'라고 **대답해라**(json)."

실제로 브라우저 주소창에 `내도메인/api/v1/health`를 쳐 보면, 서버가 이 한 줄 때문에 `{"status":"ok","version":"0.3.0"}`이라고 답합니다. **코드 한 줄 = 컴퓨터와 맺은 약속 하나**입니다.

여기서 중요한 감각 하나 — `get`, `json` 같은 단어는 우리가 발명한 게 아니라 **이미 만들어져 있는 부품의 이름**입니다. 프로그래밍은 대부분 무에서 창조하는 게 아니라, **남이 만든 부품을 조립해서 내 명령서를 완성하는 일**입니다. 레고와 같습니다.

## 0-2. 코드 파일은 그냥 글자 파일이다

`.md` 문서도 `.ts` 코드도 메모장으로 열면 열립니다. 전부 **텍스트 파일**(순수한 글자)이기 때문입니다. 파일 이름 끝의 **확장자**는 "이 글자들을 어떻게 취급할지"에 대한 힌트입니다:

| 확장자 | 정체 | 주로 누가 읽나 |
|---|---|---|
| `.md` | 마크다운 문서 | 사람 + 마크다운 렌더러 |
| `.html` | 웹 문서 | 브라우저 |
| `.ts` `.tsx` | TypeScript 코드 | 개발 도구(빌드 후 실행됨) |
| `.json` | 데이터·설정 | 프로그램들끼리 |
| `.png` `.pdf` | **바이너리** (글자 아님) | 전용 프로그램 |

마지막 줄이 중요합니다. 이미지·PDF처럼 글자가 아닌 파일을 **바이너리**라고 부릅니다. 메모장으로 열면 깨진 외계어가 나오는 것들이죠.

> 💡 **우리 코드에서 보기** — docvault가 파일을 저장하는 방식이 정확히 이 구분을 따릅니다: 텍스트(md·html·txt)는 본문을 DB에 넣고, 바이너리(이미지·PDF)는 디스크에 원본을 두고 DB에는 위치만 적습니다. "텍스트냐 바이너리냐"는 개발 전반에서 계속 만나게 되는 구분입니다.

## 0-3. 경로 — 컴퓨터의 주소 체계

`c:\Github\docvault\client\src\screens\Login.tsx`

이 줄을 읽는 법: 왼쪽이 가장 큰 상자, 오른쪽으로 갈수록 그 안의 작은 상자입니다. "서울시 → 강남구 → 역삼동 → 건물 → 호수"처럼, **C드라이브 → Github 폴더 → docvault 폴더 → ... → Login.tsx 파일**. 이런 "파일의 전체 주소"를 **경로(path)**라고 합니다.

알아둘 것 두 가지:

- 구분자가 두 종류입니다. Windows는 `\`, 그 외(리눅스 서버, 웹 주소, 코드 안)는 거의 전부 `/`. 우리가 GCP 서버에서 쓰던 `cd ~/docvault`의 `/`가 그것입니다.
- 경로 앞에 드라이브부터 다 적으면 **절대 경로**, "지금 있는 위치 기준"으로 적으면 **상대 경로**입니다. 상대 경로에서 `..`은 "한 칸 위 폴더"라는 뜻입니다. 코드 안에서 자주 보게 됩니다 (`import ... from '../lib/api'` — "한 칸 위로 가서 lib 폴더의 api").

## 0-4. 터미널 — 글자로 컴퓨터를 부리는 곳

마우스로 하는 모든 일(폴더 열기, 파일 복사, 프로그램 실행)은 **글자 명령으로도** 할 수 있습니다. 그 글자 명령을 입력하는 창이 **터미널**입니다.

왜 굳이 글자로? 개발 도구들은 대부분 **버튼 달린 화면이 없고 명령만 있기 때문**입니다. 그리고 이미 겪으셨죠 — GCP 서버는 화면 자체가 없어서 SSH 터미널이 유일한 조작법이었습니다. 터미널에 익숙해지는 건 선택이 아니라 필수입니다.

명령의 구조는 대체로 이렇습니다:

```
npm  run  dev:client
(도구) (하위명령)  (대상)
```

→ "npm이라는 도구야, 이 프로젝트에 등록된 `dev:client`라는 작업을 실행해라." 뜻만 통하면 됩니다. 명령을 외울 필요는 없고, **"명령어 + 대상 + 옵션" 구조로 읽는 눈**만 생기면 됩니다.

VS Code에서는 <kbd>Ctrl</kbd>+<kbd>`</kbd>(1 왼쪽의 백틱 키)로 터미널을 엽니다. 지금 보고 있는 프로젝트 폴더에서 바로 열리기 때문에 개발자들은 거의 항상 이걸 씁니다.

## 0-5. 우리 프로젝트 폴더 투어

`c:\Github\docvault`를 열면 보이는 것들의 정체:

| 이름 | 정체 |
|---|---|
| `client/` | **화면 쪽 코드** — 브라우저에서 돌아가는 것 전부 (로그인 화면, 파일 목록, 뷰어...) |
| `server/` | **서버 쪽 코드** — 데이터를 지키고, 로그인을 검사하고, 요청에 응답하는 쪽 |
| `docs/` | 사람이 읽는 문서 — 설계서, GCP 가이드, 지금 이 학습자료 |
| `data/` | **실제 데이터** (DB 파일, 업로드된 원본). 코드가 아니라 "사용 결과물"이라 Git에 안 올림 — 백업할 건 이 폴더 |
| `node_modules/` | npm이 설치해 준 **남의 부품들** (0-1의 레고 조각). 수만 개 파일이지만 지워도 명령 하나로 복구되는 소모품 |
| `package.json` | 프로젝트의 **신분증 + 부품 목록 + 명령 모음**. `npm run dev:client`가 뭘 하는지도 여기 적혀 있음 |
| `CHANGELOG.md` | 사용자용 패치노트 — 앱의 설정 → 정보에 뜨는 그 내용의 원본 |
| `CLAUDE.md` | AI(Claude)에게 주는 작업 규칙서 |
| `Dockerfile` | 이 앱을 서버에서 돌릴 "포장 방법" 명령서 (4장에서 배움) |

왜 화면 쪽(`client/`)과 서버 쪽(`server/`)이 나뉘어 있는지 — 이게 웹 개발의 가장 중요한 구조인데, 1장에서 제대로 다룹니다. 지금은 "내 브라우저에서 도는 코드와, 저 멀리 서버에서 도는 코드가 따로 있다"만 기억하세요.

## 직접 해보기 (10분) — 코드 한 글자 바꿔서 내 눈으로 확인

> 배우는 것: 수정 → 저장 → 반영의 사이클, 그리고 "내 컴퓨터에서만 도는 연습용 복사본" 개념

1. VS Code로 docvault 프로젝트를 열고 <kbd>Ctrl</kbd>+<kbd>`</kbd>로 터미널을 엽니다
2. `npm run dev:server` 입력 → 서버가 켜집니다 (글자가 몇 줄 올라오고 멈춘 것처럼 보이면 정상 — 대기 중인 겁니다)
3. 터미널 우측 상단 `+` 버튼으로 **터미널을 하나 더** 열고 `npm run dev:client` 입력 → 화면 쪽도 켜집니다
4. 브라우저에서 `http://localhost:5173` 접속 → docvault 로그인 화면이 뜹니다
   - **localhost**는 "내 컴퓨터 자신"을 가리키는 특수 주소입니다. 지금 보는 건 GCP의 진짜 서비스가 아니라 **내 컴퓨터에서 도는 연습용 복사본** — 마음껏 망가뜨려도 됩니다
5. VS Code에서 `client/src/screens/Login.tsx`를 열고, `docvault`라고 적힌 글자를 찾아(<kbd>Ctrl</kbd>+<kbd>F</kbd>) `docvault!!`로 바꾼 뒤 저장(<kbd>Ctrl</kbd>+<kbd>S</kbd>)
6. 브라우저를 보세요 — **새로고침도 안 했는데 로그인 화면 제목이 바뀌어 있습니다** (개발 서버의 즉시 반영 기능)
7. <kbd>Ctrl</kbd>+<kbd>Z</kbd>로 되돌리고 다시 저장 → 화면도 원래대로
8. 다 봤으면 각 터미널에서 <kbd>Ctrl</kbd>+<kbd>C</kbd> → 개발 서버 종료

방금 한 것이 개발의 최소 단위 사이클입니다: **고친다 → 저장한다 → 눈으로 확인한다.** 앞으로 배우는 모든 것이 이 사이클 위에 얹힙니다.

## 자주 하는 실수

- **터미널 창을 닫으면 개발 서버도 꺼집니다.** 터미널은 그 안에서 실행한 프로그램의 "집"입니다 — 집이 없어지면 프로그램도 죽습니다.
- `localhost:5173`이 안 열리면: `npm run dev:client`가 켜져 있는지, 터미널에 빨간 에러가 없는지부터 확인하세요.
- 코드를 고쳤는데 반영이 안 되면: **저장을 안 한 경우가 90%**입니다 (VS Code 탭 제목에 ●가 있으면 미저장).
