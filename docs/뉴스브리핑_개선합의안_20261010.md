## 0. 한 장 요약

1. **빈 요약은 0건으로 만든다.** 재료가 없는 핵심·주요 기사는 싣지 않거나 참고로 내린다. "요약이 없는 기사예요" 화면은 없어진다. 비용은 들지 않는다.
2. **기사를 더 모으기보다 읽을 거리를 늘린다.** Google 뉴스는 "몇 곳이 다뤘나"를 세는 신호로만 쓰고, 요약 재료는 언론사 직접 RSS와 원문에서 가져온다. 직접 RSS는 27곳에서 약 70곳으로 늘린다.
3. **글 모양은 필수 2칸 + 골라 쓰는 칸 0~3개**로 바꾼다. 리드와 "왜 중요한가"만 늘 쓰고, 배경·숫자·경과·반응·앞으로·용어는 재료가 있을 때만 쓴다.
4. **핵심 기사는 여러 언론 본문을 엮어 미리 길게 쓴다.** 본문 2곳 이상을 읽은 핵심은 500~700자, 주요는 250~400자다. 누를 때 만들면 30초를 기다려야 하므로 회차를 만들 때 미리 쓴다.
5. **AI가 지어내지 못하게 막는 장치를 함께 넣는다.** 문단마다 근거 언론사를 표시하고, 숫자는 그 근거 글에 실제로 있는지 대조하고, 원 제목을 남기고, 틀린 곳을 알리는 버튼을 둔다. AI를 부르지 않는 코드 검사라 비용은 0이다.
6. **폰은 기사를 전체 화면으로 열고 이전·다음으로 넘긴다.** 원문을 다녀오면 그 기사로 돌아온다.
7. **앱 안 원문 보기는 측정한 뒤 정한다.** 추출 품질 70% 이상, 버튼이 붙는 핵심·주요 50% 이상일 때만 넣는다. 넣는다면 누를 때만 받고, 저장하지 않고, 관리자만 본다.
8. **비용은 월 약 $60에서 약 $108이 된다.** 월 한도는 $80에서 $110으로 올린다. 한도에 닿으면 자동 생성은 멈춘다.

**하지 않기로 한 것**: Google 뉴스 링크 해독, "더 깊게" 버튼(1차), 이미지, 언론사 성향 표시, "배경" 칸에 AI 일반 지식 쓰기.

## 2. 네 사람이 합의한 원칙

1. **재료만큼만 쓴다.** 근거로 받은 글이 늘어난 만큼만 요약을 늘린다. 빈 칸을 채우라고 하면 일반론이 나온다. 기사마다 칸 수가 다른 것은 재료 차이를 정직하게 보여 주는 것이다.
2. **빈칸을 내보내지 않는 것도 정확성이다.** 핵심·주요를 "요약 없음"으로 싣는 지금의 구조는 버그로 본다.
3. **깊이는 미리, 질문은 누를 때.** 목록과 펼침에 보이는 글은 모두 회차를 만들 때 쓴다. 누를 때 만드는 것은 질문 답변과 앱 안 원문뿐이다.
4. **본문은 어디에도 남기지 않는다.** 원문·피드 전문·추출문은 DB, 파일, 백업, 검색 색인, 질문 기록, 서버 로그, 브라우저 캐시 어디에도 남기지 않는다. 지금 원칙을 그대로 지키고, 빈틈 두 곳(질문 기록, 폰 캐시)을 새로 막는다.
5. **사람이 누르는 기록은 회차 파일 밖에 둔다.** 회차 JSON은 기계가 만든 문서다. 읽음·신고처럼 사람이 남기는 기록은 `USER_FILE_STATE`에 둔다. 회차 파일에 쓰면 저장할 때마다 버전이 쌓인다.

## 3. 수집: 무엇을 바꾸나

Kagi News는 피드가 1만 개가 넘어서 "많이 다룬 사건"(신호)과 "겹치는 기사"(재료)가 저절로 같이 온다. 우리는 67곳이라 둘을 나눠야 한다. **신호는 Google 뉴스 검색에서, 재료는 직접 RSS와 원문에서** 가져오고, 그 둘을 이어 붙인다.

**Google 뉴스 링크 해독은 하지 않는다**(네 명 모두 동의). 비공개 내부 방식이라 예고 없이 깨지고, 요청이 몰리면 후보의 58%를 대는 Google 뉴스 RSS까지 막힐 수 있다. S3와 S5로 대부분을 대신한다. **다시 볼 조건**: S3·S5를 적용한 뒤에도 핵심·주요의 "제목만" 비율이 10%를 넘을 때. 그때도 회차 생성 경로에는 넣지 않고, 실패 응답이 한 번 나면 24시간 정지한다.

**통신사(Reuters·AP·Bloomberg)만 다룬 기사**: 공식 RSS가 없어 Google로만 들어온다. 같은 사건을 다룬 CNBC·BBC·NYT·Guardian 직접 기사와 묶이면 그 본문을 쓰고, 묶이지 않으면 참고로 내린다. 이 손실은 감수한다.

## 4. 쓰기(AI): 무엇을 바꾸나

### 4.1 글 모양: 필수 2칸 + 골라 쓰는 칸

| 구분 | 내용 |
|---|---|
| 필수 | **리드**(무슨 일, 2~3문장, 첫 문장 굵게) + **왜 중요한가**(한두 문장) |
| 골라 쓰는 칸 (0~3개) | 정해진 6종에서만: `background` 배경 · `numbers` 숫자 · `timeline` 경과 · `reactions` 반응 · `next` 앞으로 · `terms` 용어 |
| 칸 이름 | 데이터에는 종류만 저장하고, 화면이 라벨 문구를 붙인다(고정 라벨이든 질문형이든 화면에서 바꿀 수 있다) |
| 그리는 순서 | 배경 → 숫자 → 경과 → 반응 → 앞으로 → 용어 (고정) |
| 지시문 완화 | "제목에 쓴 것 반복 금지" → "주어는 다시 써도 된다. 대신 제목에 없는 사실 둘 이상" (조각 문장 해소) |
| 그대로 유지 | 주어진 글 밖의 사실 금지(`ai.ts:102`), 원문 문장 베끼지 않기 |

### 4.2 길이

| 등급 | 조건 | 길이 |
|---|---|---|
| 핵심 | 본문 2곳 이상, 또는 1곳 2,000자 이상 | 500~700자 |
| 핵심 | 본문 1곳 | 300~450자 |
| 주요 | 본문 또는 발췌 | 250~400자 (지금 200~300) |
| 참고 | 지금처럼 | 1~2문장 |

목표 길이는 코드가 기사마다 `min(등급 상한, 재료 글자 수 ÷ 3)`으로 계산해 지시문에 넣는다. 결과가 상한의 1.3배를 넘으면 실행 기록에 남긴다.

### 4.3 여러 언론 엮기

- **매체마다 수치가 다르면 평균 내지 않는다.** "A 기준 x, B 기준 y"로 나란히 쓴다.
- **언론사마다 강조한 점**(`angles`): 본문을 2곳 이상 읽은 핵심에만, 최대 3줄, 실제로 다를 때만 쓴다. 근거는 한 곳이어야 하고, "편향·왜곡" 같은 평가어는 쓰지 않는다. 리드와 겹치면 버린다. 다 같은 내용이면 칸을 그리지 않는다.
- **"갱신됨" 기사의 바뀐 점 한 줄**(`changed`): 이어받은 이슈는 직전 회차의 요약도 입력에 넣는다. 지금은 제목만 넣는다(`readPrevious`). 바뀐 점은 이번 재료에서만 쓴다. 새 사실이 없으면 "갱신됨"을 붙이지 않는다.

### 4.4 재료가 없을 때 (Q1 결론)

| 재료 | 처리 |
|---|---|
| 같은 사건 다른 보도의 본문·발췌가 있음 | 그것으로 쓴다 |
| 발췌만 있음 | 참고로 내리고 한 문장 |
| 제목뿐 | **AI 문장 없이** 참고로 "제목만" 표시. 해외 기사는 제목 번역만. 누르면 펼치지 않고 바로 원문 |
| 위 어느 것도 안 됨 | 싣지 않는다 |

- 어떤 경우든 **오늘의 핵심 상자에는 오르지 않는다.**
- "왜 중요한가"가 일반론("관심이 쏠린다", "귀추가 주목된다")이라 거르개에 걸려 비면, 그 기사는 핵심에서 주요로 낮춘다.

### 4.5 검증 단계 (새 파일 `verify.ts`, AI 호출 없음, 비용 0)

1. **추출문·제목 겹침**: 받아 온 본문에 제목의 핵심어가 충분히 있는가. 기준은 글자 2개씩 겹침 40%이고, D0 측정으로 조정한다. 엉뚱한 페이지(목록, 오류 화면)와 잘못 붙은 기사를 거른다.
2. **숫자 대조**: 요약에 나온 숫자가 **그 칸의 근거 재료 안에** 같은 값으로 있는가.
   - 글자가 아니라 값으로 비교한다. 쉼표, 만·억·조, thousand·million·billion을 숫자로 바꾼다.
   - `%`와 `%p`, `원`과 `달러`는 다른 것으로 본다.
   - "약·가량·안팎"이 붙으면 1% 이내 차이를 허용한다.
   - 통과 못 한 숫자가 든 **문장만** 지운다. 칸 전체를 지우지 않는다.
   - 숫자 칩은 더 엄격하게 본다. 값과 항목 이름이 같은 재료에 함께 있어야 한다.
   - 로마자 고유명사(회사명 등)도 같은 방식으로 확인한다.
3. **근거 표시 확인**: 칸의 `from`이 실제로 읽은 재료를 가리키는지 본다. 비었거나 엉뚱하면 그 칸을 버린다.
4. **도입 순서**(읽는 사람 대변의 우려 반영): 숫자 대조는 **처음 2주는 기록만** 한다(`stats.numberDrops`). 맞는 글을 지워 다시 얕아지는지 확인한 뒤 문장 삭제를 켠다. 여러 언론 엮기(S7)는 삭제를 켠 뒤에 켠다. 감시 쪽의 "숫자 대조 없는 종합 금지"를 지키는 순서다.

### 4.6 호출 구조

| 단계 | 지금 | 바꾼 뒤 |
|---|---|---|
| 분류·선별·합치기 | Haiku | 그대로(후보가 늘어 호출 수만 증가) |
| 핵심 | Sonnet, 8건 묶음 | Sonnet, **3건 묶음**, 재료마다 기호와 언론사 이름표 |
| 주요 | Sonnet, 8건 묶음 | 8건 묶음 유지, 재료 2곳 |
| 참고 | Haiku 선별 단계에서 | 그대로 |

## 5. 데이터 모양

### 5.1 회차 JSON (version 1 유지. 더하는 칸은 모두 없어도 된다)

```
EditionItem += {
  originalTitle?: string     // 대표 기사의 원 제목 — 원문 카드의 글자
  sources?: { id: 'A'|'B'|'C', source: string, url: string }[]
                             // 본문을 실제로 읽은 재료. 화면의 "○○ 등 3곳 본문" 표시 근거

  summaryFrom?: ('A'|'B'|'C')[]
  blocks?: {
    kind: 'background'|'numbers'|'timeline'|'reactions'|'next'|'terms',
    text?: string,
    pairs?: { label: string, value: string }[],   // 숫자 칩
    items?: { date: string, text: string }[],     // 경과
    from: ('A'|'B'|'C')[]                         // 필수
  }[]
  angles?: { from: 'A'|'B'|'C', text: string }[]  // 다를 때만, 최대 3
  readUrl?: string           // 앱 안 원문으로 받을 주소(본문이 아니라 주소)
  changed?: string           // 갱신됨일 때 바뀐 점 한 줄
}
stats += { basis?: { body, lede, title }, bodiesRead?, numberDrops?, extractRejected?, attached? }
```

- 화면은 `blocks` → `detail` → `summary` 순서로 찾아 그린다. 옛 회차도 그대로 보인다.
- 핵심·주요는 `summary`와 `why`가 비면 저장 단계에서 탈락한다.
- 진행자 정리: 파이프라인은 `readFrom`(이름 목록)을, 감시는 `sources`(기호·이름·주소)를 제안했다. `sources`가 더 많은 것을 담아 그쪽으로 합쳤다. 화면은 `sources`의 이름으로 "연합뉴스·한겨레·KBS 본문"을 그린다.

### 5.2 회차 밖

```
USER_FILE_STATE += flag_items   // [{ id, at, reason: 'number'|'mixed'|'overstated'|'other', note? }]
```

- 신고는 회차 파일이 아니라 읽음 기록(`read_items`)과 같은 자리에 둔다. 감시는 회차 JSON을 제안했지만, 나머지 셋이 "버전이 쌓인다"며 반대해 이쪽으로 정했다.
- ERD는 엔티티 블록과 관계 설명을 같이 고친다.

## 6. 보여주기: 무엇을 바꾸나

### 6.1 목록: 거의 그대로

- 바꾸는 것은 두 가지뿐이다.
  - **"제목만" 참고 기사**: 줄 끝에 "제목만 · 원문" 표시를 하고, 누르면 펼치지 않고 바로 원문으로 간다.
  - **"갱신됨" 기사**: 셋째 줄에 바뀐 점 한 줄(흐린 글씨, 한 줄로 자름). 목록을 흔들지 않는다는 원칙의 유일한 예외다. 점심판에서 같은 이야기를 다시 펼쳐 보는 낭비가 더 크다고 판단했다.
- 앱 안 원문을 열 수 있는지는 목록에서 표시하지 않는다(차이가 미세해 읽히지 않는다). 상세의 원문 카드가 알려 준다.

### 6.2 폰 상세: 핵심·주요는 전체 화면 시트, 참고는 그 자리 펼침

지금처럼 목록 안에서 들여 쓴 채 펼치면, 360px 폭에서 글 폭이 약 290px로 줄어 긴 글을 넣을 수 없다.

1. **위 고정 막대**: [← 목록] · "국내 · 환율·금리" · [요약 | 원문] 전환(앱 안 원문이 될 때만)
2. **중요도 배지 + 제목**, 짧은 출처 줄 "연합뉴스 외 11곳 · 15:40"
3. **바뀐 점**(갱신됨일 때): 한 줄 "지난 판 이후: …" + [지난 판 ›]
4. **리드 2~3문장**: 첫 문장 굵게, 라벨 없음
5. **왜 중요한가**: 왼쪽 세로 선. 지금의 파란 상자보다 가볍다
6. **골라 쓴 칸 0~3개**: 회색 소제목 대신 문단 첫머리에 굵은 라벨. 숫자는 칩, 경과는 날짜 열. 본문을 2곳 이상 읽었으면 문단 끝에 흐린 글씨로 근거 언론사 이름
7. **언론사마다 다른 점**(다를 때만): 언론사 + 한 문장, 최대 3줄
8. **근거 줄**: "연합뉴스·한겨레·KBS 본문을 읽고 AI가 정리". 재료가 얇으면 주황 글씨로 경고. 오른쪽 끝에 작은 "틀린 곳 알리기"
9. **원문 카드**(전체 폭): 원 제목 두 줄 + "연합뉴스 · 15:40 · 앱에서 읽기" 또는 "사이트에서 열기 ↗". 아래에 다른 보도 언론사 링크
10. **[이 기사 묻기]**(44px)
11. **아래 고정 이동 막대**: ‹ 이전 · 3/18 · 다음 ›. 좌우로 밀어도 넘어간다

- **출처 줄 표현**: "12곳 보도 종합"이 아니라 "12곳 보도 · 3곳 본문 정리"라고 쓴다. 실제로 읽은 곳은 최대 3곳이라 "종합"은 과장이다(두 참가자가 같이 지적).
- **틀린 곳 알리기**: 누르면 아래에 네 가지 선택지가 뜬다(숫자가 틀림 / 다른 사건이 섞임 / 제목이 과장됨 / 기타). 한 번 누르면 끝나고, 그 자리에 "알렸어요"만 남는다. 패널에 "이번 달 신고 n건"을 보인다.

### 6.3 PC (보이는 폭 880px 이상)

- 오른쪽 칸에 위 2~10번을 같은 순서로 그린다. 글 폭은 약 68자로 묶는다.
- 칸 머리에 [요약 | 원문] 전환을, 바닥에 키 안내를 둔다.
- 키: J/K 이동 · O 앱 안 원문 · Shift+O 새 탭 · R 전환 · A 묻기

### 6.4 원문 왕복 줄이기: 비용 0인 것부터

- **원문을 다녀오면 그 기사로 복귀**: 원문을 열 때 기기에 `{fileId, itemId, at}`만 적는다. 화면으로 돌아오거나 30분 안에 앱이 다시 뜨면 그 기사를 연다. 복귀는 한 번만 하고 기록을 지운다. 그사이 새 회차가 생겼으면 복귀하지 않는다. 설계 SCR-191 9번("회차는 항상 맨 위에서 연다")의 예외로 적는다.
- **뒤로 제스처로 시트 닫기**: 주소에 `#a=기사id`를 쌓는다. 이 값은 회차의 기사 id 목록에 있을 때만 쓰고, 화면 요소를 찾는 데 그대로 넣지 않는다(선택자 주입 방지). 이전·다음은 기록을 바꿔치기(`replaceState`)해서 뒤로 가기가 쌓이지 않게 한다.

### 6.5 화면 상태

| 상태 | 보이는 것 |
|---|---|

### 6.6 이 기사 묻기

- 앱에 있는 AI 질문 기능(API-101~109, 답을 흘려보냄, 웹 검색 최대 3회)에 연결한다. 뉴스용 안내문을 붙인다. 지금 안내문은 학습 동반자용이다.
- **넘기는 것은 우리가 쓴 글뿐이다**: 제목·요약·칸·언론사 이름·원문 주소. 질문 기록은 DB 표(`ask_threads.quote`·`context`, `ask_messages`)에 저장되므로 원문 본문을 넘기면 본문이 남는다.
- 앱 안 원문 화면에서는 "드래그해서 묻기"를 끈다. 같은 이유다.

## 7. 앱 안 원문 보기: 측정한 뒤 정한다

**판정**: 네 명 모두 조건부 찬성. 넣을지는 측정 결과로 정한다.

**D0 측정** (AI 호출 없음): 최근 회차의 `readUrl` 표본으로 아래 두 비율을 잰다. 표본 20건은 사람이 눈으로 확인한다.

| 기준 | 값 | 뜻 |
|---|---|---|
| 품질 통과율 | **70% 이상** | `readUrl`이 있는 기사 중 "600자 이상 + 제목 핵심어 겹침 + 잡문(기자 메일·관련 기사 목록) 없음"을 통과한 비율. 60%면 열 번 중 서너 번 실패라 결국 안 쓰게 된다 |
| 범위 | **50% 이상** | 핵심·주요 중 `readUrl`이 붙는 비율. 이보다 낮으면 버튼을 볼 일이 거의 없다 |

70%에 못 미치는 사이트는 "원문 보기 제외" 목록에 넣고 다시 잰다. 그래도 미달이면 앱 안 원문은 통째로 보류한다. 그 경우 왕복 문제는 복귀 장치와 묻기로 줄인다.

**넣는다면 지킬 조건** (약속이 아니라 코드로 강제):

1. 관리자만. 다중 사용자·공개 서비스로 바뀌면 자동으로 꺼진다(설계 보안 절에 명시).
2. 누를 때만 받는다. 미리 받아 두지 않는다.
3. API는 기사 id만 받고 서버가 회차에서 `readUrl`을 찾는다. 임의 주소를 받지 않으니 열린 프록시가 되지 않는다.
4. 동시 1건, 20초 제한. 회차를 만드는 중에는 줄을 세운다.
5. 디스크·DB에 저장하지 않는다. 메모리 캐시는 10분·20건까지만 허용한다. 응답은 `Cache-Control: no-store`로 보내고 서비스 워커 캐시에서 뺀다. 이걸 안 하면 폰에서 "저장하지 않음"이 깨진다(감시가 새로 찾은 위험).
6. 유료벽 우회 금지. 숨김 본문 꺼내기나 UA 위장도 하지 않는다. 짧게 추출되면 사이트로 보낸다.
7. 글자만 보인다. 이미지는 넣지 않는다.
8. 화면은 문단 문자열을 React 텍스트로만 그린다. HTML을 넣지 않는다.
9. 본문 추출에는 Readability + linkedom을 이 기능에만 쓴다(1건 약 104MB, jsdom은 420MB라 제외). 회차 만들기에서는 지금의 가벼운 추출을 유지한다.

법률 해석은 1차 보고서 5장과 같다(사적 이용 복제·일시적 복제의 취지에 가장 가깝지만 언론사 약관은 회색 지대, 법률 자문 아님).

## 11. 끝까지 남은 이견과 정리한 방법

| 이견 | 입장 | 정리 |
|---|---|---|
| 제목뿐인 기사 | 파이프라인: 뺀다 / 감시: AI 문장 없이 "제목만"으로 남긴다 / 읽는 사람·디자인: 참고로 한 문장 | **"제목만" 참고로 남기고 AI 문장은 쓰지 않는다**(해외는 번역만). 지어낼 위험이 0이면서 기사는 잃지 않는다. 누르면 바로 원문 |
| 숫자 대조 시작 시점 | 감시: 처음부터 삭제 / 읽는 사람: 2주 기록 후 | **2주 기록 후 삭제**. 대신 여러 언론 엮기(S7)는 삭제를 켠 뒤에 켠다. 감시의 "대조 없는 종합 금지"도 함께 지켜진다 |
| 신고 저장 위치 | 감시: 회차 JSON / 나머지: `USER_FILE_STATE` | **`USER_FILE_STATE`** (3:1, 버전 누적 문제) |
| 원 제목 위치 | 감시: 출처 줄 아래 / 디자인: 원문 카드 글자 | **원문 카드 글자**. 원문 링크와 한 덩어리가 되어 줄이 늘지 않는다. 감시의 요구(원 제목이 보일 것)는 충족한다 |
| 근거 표시 데이터 | 파이프라인: `readFrom` 이름 목록 / 감시: 기호 붙은 `sources` | **`sources` + 칸마다 `from`**. 출처가 섞이는 것을 칸 단위로 잡을 수 있다 |
| 앱 안 원문 기준 | 60% / 70% / 90%+50% | **품질 70% + 범위 50%** (세 사람이 70을 냈고, 범위 기준은 둘이 냈다) |
| "더 깊게" 버튼 | 1라운드엔 디자인·읽는 사람이 요구 | 2라운드에서 **두 사람 스스로 철회**. 미리 쓰는 깊이 + 묻기로 대신하고, 묻기 사용량을 본 뒤 다시 논의 |

## 13. 토론에서 새로 드러난 사실

1. **근거 언론사 표시가 지금도 어긋날 수 있다.** 원문 읽기는 같은 사건의 다른 보도에서 성공할 수 있다(`body.ts:17-21`). 그런데 성공한 본문의 글자만 남기고(`body.ts:67-72`) 어느 언론사였는지는 버린다. 요약 호출에 기사를 싣는 부분(`summarize.ts:30-43`)은 그 본문을 대표 기사 언론사의 글로 붙여 AI에게 준다. 저장도 대표 언론사·주소만 한다(`edition.ts:97-98`). 결과적으로 모델은 한겨레 본문을 연합뉴스 글로 알고 쓴다. 9장 1단계에서 고친다.
2. **질문 기능에 원문을 넘기면 저장된다.** `ask_threads.quote`·`context`와 `ask_messages`는 DB 표다. "본문은 저장하지 않는다" 원칙과 부딪치므로, 묻기에는 우리가 쓴 글만 넘긴다.
3. **폰 캐시가 "저장하지 않음"을 깰 수 있다.** 원문 응답에 `no-store`를 붙이고 서비스 워커 캐시에서 빼야 한다.
4. **1차 보고서의 줄 번호 오류**: `body.ts`(92줄)와 `ai.ts`(102줄)를 존재하지 않는 줄로 인용했다. 감시가 지적해 고쳤다(`body.ts:12-14`, `body.ts:71-73`, `ai.ts:45,54,102`). 파이프라인 담당의 1라운드 안에도 `select.ts:314`, `sources.ts:270-298` 같은 틀린 줄이 있어 읽는 사람 대변이 바로잡았다(실제 `select.ts:113`). 이 문서의 줄 번호는 진행자가 다시 확인했다.
