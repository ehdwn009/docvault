테마 대응 시료

테마를 따라가는 문서

이 문서로 무엇을 시험하는가. 색을 전부 CSS 변수로 뽑아 놓고, 뷰어가 문서 <html>에 남기는 data-theme 표식(light / dark / sepia)에 따라 팔레트를 통째로 갈아끼웁니다. 뷰어에서 테마를 바꿀 때 배경·글자·테두리·코드블록이 한 번에 따라 바뀌는지, 시스템이 다크 모드인데 뷰어에서 라이트를 고른 경우 라이트가 이기는지를 봅니다. 글자 크기는 전부 px이므로 배율 기능도 함께 시험 대상입니다.

1. 색을 변수로 뽑는다는 것

테마를 바꾼다는 건 결국 같은 자리에 다른 색을 넣는 일입니다. 문제는 그 "자리"가 문서 전체에 흩어져 있다는 점입니다. 배경색 한 가지가 본문·카드·표 머리·코드블록 등 수십 군데에 적혀 있으면, 테마마다 그 수십 군데를 전부 다시 적어야 합니다.

CSS 변수는 이 관계를 뒤집습니다. 색에 역할 이름을 붙여 한곳에 모아 두고, 실제 규칙들은 그 이름만 참조합니다. 테마가 바뀔 때 갈아끼우는 것은 이름표 뭉치 하나뿐입니다.

--bg · 바탕
--surface-2 · 면
--accent · 강조
--ok · 성공
--warn · 주의
--border · 경계

위 견본 상자는 변수를 그대로 칠한 것입니다. 테마를 바꾸면 여섯 칸의 색이 동시에 바뀌어야 합니다. 하나라도 그대로 남아 있다면 그 변수가 어딘가에서 하드코딩된 색으로 덮여 있다는 뜻입니다.

2. 우선순위 — 누가 이기는가

세 갈래의 선언

이 문서는 팔레트를 세 번 선언합니다.

  • 맨바닥 :root — 라이트 기본값. 아무 조건이 없으므로 항상 깔립니다.
  • @media (prefers-color-scheme: dark) — 운영체제가 다크 모드일 때. 단, 뷰어가 명시적으로 light나 sepia를 골랐다면 적용되면 안 되므로 :not([data-theme="light"]):not([data-theme="sepia"])로 막아 둡니다.
  • :root[data-theme="dark"] / [data-theme="sepia"] — 뷰어에서 사용자가 직접 고른 테마. 가장 뒤에 오고 선택자도 더 구체적이므로 언제나 이깁니다.
흔한 실수 다크 팔레트를 미디어 쿼리 안에만 정의하면, 시스템이 다크인 사용자가 뷰어에서 라이트를 골라도 다크가 남아 버립니다. 그래서 기본값은 반드시 조건 없는 :root에 두고, 미디어 쿼리 쪽은 예외 처리를 붙여야 합니다.

실제 동작 표

시스템 설정뷰어 테마적용 결과이유
라이트light라이트기본 :root만 적용
다크light라이트:not([data-theme="light"])가 미디어 쿼리를 차단
라이트dark다크[data-theme="dark"]가 직접 적용
다크dark다크두 경로가 같은 값이라 충돌 없음
아무거나sepia세피아[data-theme="sepia"]가 가장 구체적

3. 문서가 테마를 "따르는" 것과 "강요하는" 것

뷰어는 문서에 테마를 강요하지 않습니다. 남의 HTML을 격리된 틀 안에 그대로 띄우는 것이 원칙이고, 색을 억지로 덮어쓰면 원본이 의도한 디자인이 망가지기 때문입니다. 대신 표식만 남깁니다. 문서가 그 표식을 읽고 따라올지 말지는 문서의 자유입니다.

따르는 문서 (이 문서)

[data-theme] 선택자를 준비해 두었으므로, 뷰어에서 테마를 바꾸면 즉시 반응합니다. 뷰어의 주변 UI와 색이 어우러집니다.

따르지 않는 문서

표식을 무시하고 자기 색만 씁니다. 다크 테마 뷰어 안에 흰 종이 한 장이 덩그러니 떠 있는 모습이 되지만, 그게 원본의 의도라면 그대로 존중됩니다.

확인 포인트 뷰어 테마를 세 번 돌려 보세요. 이 문서의 배경·카드·코드블록·표 머리·견본 상자가 모두 함께 바뀌면 통과입니다. 하나만 어색하게 남는다면 그 규칙이 변수를 안 쓰고 있는 것입니다.

4. 코드로 보기

/* 역할 이름을 정하고 */
:root {
  --bg:   #ffffff;
  --text: #161c2b;
}

/* 규칙은 이름만 참조한다 */
body { background: var(--bg); color: var(--text); }

/* 테마마다 이름표 뭉치만 갈아끼운다 */
:root[data-theme="dark"] {
  --bg:   #10131c;
  --text: #e6eaf5;
}

규칙의 수가 아무리 늘어도 테마 추가 비용은 늘지 않습니다. 새 테마를 하나 더 만들고 싶다면 변수 뭉치 하나만 더 쓰면 됩니다. 이 문서가 세피아를 쉽게 추가할 수 있었던 이유입니다.

배율과 함께 시험하기

이 문서의 글자 크기는 전부 px입니다(34px, 24px, 16px, 13px ...). 따라서 뷰어 배율의 직접 대상입니다. 테마를 바꾼 상태에서 배율까지 올려 보고, 두 기능이 서로를 지우지 않는지 확인하세요. 색이 유지된 채 글자만 커져야 정상입니다.

5. 확인 항목 정리

  • light → dark → sepia 전환 시 모든 영역의 색이 동시에 바뀌는가
  • 시스템 다크 + 뷰어 라이트 조합에서 라이트가 이기는가
  • 테마를 바꿔도 글자 크기 배율 설정이 유지되는가
  • 코드블록·표·견본 상자 등 특수 영역에 하드코딩된 색이 남아 있지 않은가
  • 목차에 h1 1개, h2 5개, h3 4개가 잡히는가
