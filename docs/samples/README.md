# HTML 뷰어 테스트 시료

뷰어가 남의 HTML을 격리 iframe에 그대로 띄울 때, 두 가지 보정이 제대로 도는지 눈으로 확인하기 위한 샘플 문서 모음이다.

- **화면 맞춤** — 그림 `max-width` 가드 → 넘치는 것을 전부 화면 폭에 가두고(`box-sizing`+`max-width:100%`) 그러고도 제 안에서 넘치는 것만 가로 스크롤 상자로 → 그래도 넘치면 축소
- **글자 크기 배율** — 문서의 스타일 규칙에서 `font-size`의 **px 값만** 배율을 곱한 사본 시트를 맨 뒤에 덧붙임. `em`·`rem`·`%`와 SVG의 `font-size` **속성**은 건드리지 않음. 인라인 `style="font-size:…"`는 시트보다 세므로 따로 덧씌움

> **기준값(2026-08-18 실측, 폭 390px)**: 여덟 문서 모두 맞춤을 켜면 가로 넘침 **0**, 끄면 각각 599·0·0·369·1416·560·540·490px 넘침. 축소(마지막 단계)는 한 번도 발동하지 않는다. 이 값이 달라지면 뭔가 깨진 것이다.

여덟 문서는 서로 구조가 겹치지 않게 만들어져, 위 경로를 하나씩 나눠 밟는다. 외부 리소스는 8번의 CDN 링크 하나뿐이다(폐쇄망에서 실패하는 것이 정상).

## 시료 목록

| 파일 | 무슨 구조인가 | 무엇을 확인해야 하는가 |
|---|---|---|
| `01-고정폭-신문.html` | 래퍼가 `width:900px`로 못박힌 신문 판형. `column-count` 3단·2단 조판, 글자 크기 전부 px 하드코딩 | 고정폭 래퍼가 화면 폭 안으로 들어오는지(여백까지 포함해서 — 이 문서가 `box-sizing` 문제를 잡아냈다). 단 조판이 무너지지 않는지. 배율을 올릴 때 제목·본문·캡션이 빠짐없이 함께 커지는지 |
| `02-rem-반응형.html` | `html{font-size:16px}` 하나만 px. 나머지는 전부 rem·em. 중첩 em이 3~5겹 누적, `@media`로 루트 크기만 바뀜 | 배율이 **루트 하나만** 바꿔 문서 전체가 비율 유지한 채 움직이는지. 중첩 em의 단계별 비율이 배율과 무관하게 일정한지. 가로 스크롤이 아예 안 생기는지 |
| `03-다크-CSS변수.html` | 색을 전부 CSS 변수로. 맨바닥 `:root`(light) + `@media (prefers-color-scheme:dark)` + `[data-theme="dark"]` + `[data-theme="sepia"]` | 뷰어가 `<html>`에 남기는 `data-theme` 표식을 따라 팔레트가 한 번에 갈리는지. **시스템 다크 + 뷰어 라이트**에서 라이트가 이기는지. 테마 전환 후에도 배율 설정이 유지되는지 |
| `04-넓은-표.html` | 열 12·9·10개짜리 넓은 표 3개. 셀에 `width:120px` 등 고정폭, 일부 셀 `white-space:nowrap`. **스크롤 래퍼를 문서가 만들지 않음** | 화면 맞춤 **2단계(스크롤 상자)** 가 표마다 **독립적으로** 걸리는지. 표 때문에 본문 전체가 밀리지 않는지. `nowrap` 셀이 억지로 접히지 않는지 |
| `05-코드-터미널.html` | `white-space:pre` 코드 블록 8개. 어두운 터미널 블록, 줄 번호 블록, 등폭 문자 표 포함. 최장 줄 약 220자 | 코드 블록 각각이 독립 가로 스크롤 상자가 되는지. 줄 번호와 코드 줄이 스크롤 중 어긋나지 않는지. 등폭 표(`┌─┬─┐`)의 선이 배율 변경 후에도 맞는지 |
| `06-SVG-다이어그램.html` | 인라인 `<svg>` 5개(폭 760~900 고정 속성). 두 개에만 `max-width:100%` 가드. 라벨은 전부 `font-size="14"` **속성** | 가드 **없는** 세 그림을 화면 맞춤 1단계가 잡아 비율 유지한 채 줄이는지. 배율을 올려도 도해 안 라벨은 **변하지 않는지**(속성은 보존 대상). 같은 배율에서 본문 글자는 커지는지 |
| `07-인라인스타일.html` | `<style>` 태그 0개. 글자 크기·색·폭이 전부 요소의 `style="..."` 속성. 인라인 `width:680px` 상자와 260px 삼단 배치 포함 | 배율이 인라인 스타일에도 **통해야** 한다(시트 사본으로는 못 이기므로 뷰어가 따로 덧씌운다). 인라인 고정폭·삼단 배치가 화면 맞춤으로 처리되는지(이 문서가 "밀려난 요소" 검출 누락을 잡아냈다). 테마를 바꿔도 색이 안 변하는 것이 정상 |
| `08-동적생성.html` | 본문 대부분을 `setTimeout` 800ms 뒤 JS가 DOM에 추가(카드 8·열 10짜리 표·목록·헤딩 2). `<head>`에 실패할 CDN 스타일시트 링크 1개 + 자체 `<style>` | 나중에 나타난 넓은 표에도 **보정이 다시 도는지**(최초 계산만 하면 그대로 넘침). 나중에 생긴 내용에 배율이 적용되는지. CDN 로드 실패가 화면·배율 기능을 망가뜨리지 않는지. 목차가 나중 추가된 헤딩까지 잡는지 |

## 쓰는 법

1. 뷰어에 파일을 올리거나 열고, 창을 좁혔다 넓혔다 하며 **화면 맞춤**이 어느 단계에서 개입하는지 본다.
2. 같은 문서에서 **글자 크기 배율**을 최소·최대로 바꿔 보고, 위 표의 "무엇을 확인해야 하는가"와 대조한다.
3. 두 보정을 겹쳐서(축소된 상태에서 배율 변경, 배율을 바꾼 뒤 창 크기 변경) 서로 싸우지 않는지 본다.
4. 테마(light / dark / sepia)를 돌려 가며 3번 문서의 반응과 나머지 문서의 무반응을 비교한다.

각 문서 맨 위에는 "이 문서로 무엇을 시험하는가" 안내 상자가 있고, 맨 아래에는 확인 항목 목록이 있다. 목차 기능도 함께 시험하도록 모든 문서에 `h1`/`h2`/`h3`가 여러 개 들어 있다.

## 주의

- `08-동적생성.html`의 CDN 링크(`https://cdn.jsdelivr.net/npm/some-typography@1.4.2/dist/some.css`)는 **일부러 넣은 실패용**이다. 실존 여부와 무관하게 폐쇄망에서 실패해야 정상이며, 실패해도 문서는 멀쩡히 읽혀야 한다.
- 그 링크 하나를 빼면 여덟 문서 모두 외부 이미지·폰트·스크립트를 쓰지 않는다.
