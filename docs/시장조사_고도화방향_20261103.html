2.4이탈 요인 · 한국 시장 · 규제

이탈 요인 (반복 순)

  • 성능 — Notion은 Electron·서버 의존 성능 불만 1위. Obsidian iOS는 5천 노트에서 재시작 반복. 서버 인덱스·PWA 구조인 docvault는 이 모바일 문제를 구조적으로 피합니다.
  • 학습 곡선 — Obsidian 이탈자의 최다 행선지는 Notion(23.72%, 독자 투표 약 2,600명).
  • 종속·가격 정책 변경 — Evernote 사례. Notion은 Enterprise에만 LLM 무보존(ZDR) 약속.
  • AI 프라이버시 — Evernote는 2016년 "직원이 ML 학습용으로 노트 열람 가능" 정책을 며칠 만에 철회.

한국 시장 · 규제 (법률 자문 아님)

  • Notion — 한국은 미국 다음 시장. 2025년 한국 사용자 템플릿 복제 약 2,000만 회. 2026-05부터 Enterprise 한정 한국 데이터 레지던시.
  • 카카오톡 "나에게 보내기" — 사용자 4,823만 명의 사실상 캡처 도구이나 검색·분류 불가 불만 반복.
  • 통신판매업 신고 — 직전 연도 거래 50회 미만 또는 간이과세자면 면제. 단 PG가 신고번호 요구 가능.
  • 개인정보 처리방침 — 보호법 제30조 필수 항목. 문서 본문을 Claude API로 보내므로 "처리 위탁(미국)·국외 이전" 고지 필요 가능성 높음.

A-2사용자가 실제로 쓰는 것 vs 안 쓰는 것

매일 또는 자주 쓴다

  • 템플릿·속성 쿼리·데일리 노트 — 2025년 Obsidian 플러그인 다운로드: Templater 151만, Dataview 119만, Tasks 108만, Calendar 74만. 그래프 강화 플러그인은 TOP10에 없음.
  • 백링크 — "과거의 기록이 현재의 글쓰기에 자동으로 참여" (국내 UX 리서처 후기).
  • 로컬 그래프(1~2홉) — 그래프 비판자도 "어떤 규모에서도 쓸 만하다"고 인정.

안 쓰거나 유료 벽 뒤

  • 전체 그래프 — r/ObsidianMD 은어 "the hairball". 1.5만 노트 그래프 게시물 캡션 "YES this view is unusable". 국내 스터디 후기도 필터·폴더 한정 요구.
  • unlinked mentions·related content — Capacities가 Pro 이상에만 제공하는 "유료 가치" 기능.

A-3docvault에 넣는다면

링크를 DB 테이블로 물질화하는 것이 모든 셀프호스팅 구현의 공통 패턴이고, docvault는 이미 SQLite 중심이라 가장 자연스러운 길입니다.

  1. [[제목]] 자동완성(fuzzy) + 렌더링 + 백링크 패널(문맥 스니펫)
    저장 시 remark로 링크를 뽑아 file_links 테이블에 upsert하고, 뷰어 remark 파이프라인에 wiki-link 플러그인을 더합니다. 버전 복원도 저장 경로를 타므로 자동 갱신됩니다.
    난이도 중비용 0
  2. 제목 변경 전파 + 미존재 링크 클릭 시 생성
    영향받는 문서만 찾아 치환하고, 각 문서를 "하나의 편집"으로 스냅샷해 20버전 정책과 맞춥니다. 전체 스캔은 금지.
    난이도 중비용 0
  3. 템플릿 + 데일리 노트
    다운로드 1·4위 기능. 데일리 노트는 "다 던지기"보다 원자 노트 + 날짜 링크를 권장 UI로.
    난이도 하비용 0
  4. Unlinked mentions + "링크로 바꾸기"

C-2계속 쓰는 것 vs 한 번 써보는 것

계속 쓰는 기능은 "이미 하려던 일(읽기·찾기·쓰기)의 마찰을 줄이는 것"이고, 한 번 써보는 기능은 "새 소비 형식을 만드는 것"입니다.

계속 쓴다 · 조건부

  • 출처 인용 Q&A — r/notebooklm 핵심 가치 "소스 밖을 아는 척하지 않고 답마다 구절 링크".
  • 연관 노트 추천(수동적 회상) — Smart Connections 126만 다운로드, "passive recall에 강함".
  • 자동 태그·링크(조건부) — 모든 플러그인이 "기존 태그와 대조 → 미리보기 → 확인" 설계.
  • AI 플래시카드(조건부) — Brown 의대 2025: 시험 점수 차이 없음, 91%가 "시간 절약". 학습 효과가 아니라 시간 절약으로 포지셔닝.

한 번 써본다 · 과금 안 된다

  • 오디오 오버뷰 — "첫 주엔 목소리가 훌륭하다, 그 다음엔 늘 같은 두 사람". 통근 청취 상황이 있을 때만 유지.
  • 답변 품질 자체 — NotebookLM 무료가 95% 커버, Plus 구매자 후회. Notion은 AI를 USD 20 플랜 업셀 명분으로 씁니다.

피할 것

  • 2인 대화형 오디오 오버뷰를 먼저 만들기 — 구현 복잡도에 비해 유지 사용률이 낮습니다.
  • 승인 단계 없는 자율 에이전트("폴더 자동 정리") — Notion조차 계획 검토·승인 UX를 기본으로 둡니다.
  • 답변 품질로 과금 — 과금은 한도(질문 수·생성 수·색인 문서 수)와 BYOK 해제가 업계 패턴.
  • 사용자 문서를 LLM 제공사 학습에 쓰이는 무료 티어로 보내기 — Evernote 2016의 교훈.

방향 D캡처·수집·형식 확장

iPhone Safari는 PWA share_target을 지원하지 않으므로 iOS 단축어 + 메일 수신 + 서버 URL 추출을 먼저 깔고, PDF 하이라이트는 DB에 저장하며, 형식 확장은 "가져오기 시점에 Markdown으로 변환"으로 기존 뷰어·검색·버전을 재사용합니다.

D-2사용자가 실제로 쓰는 것 vs 안 쓰는 것

사용자는 "읽으려고"가 아니라 "저장하려고" 쓰며, 리텐션은 "한 번에 저장되고 나중에 검색으로 다시 찾히는가"에 달렸습니다.

쓴다

  • 1탭 저장(공유 시트·확장) — Pocket 사용자 대부분은 읽지 않고 저장했습니다. 카카오톡 "나에게 보내기"에 380개 쌓였지만 다시 본 건 손에 꼽는다는 후기.

불만 · 플랫폼 제약

  • 본문 추출 누락 — 이미지·첫 링크에서 잘림.
  • 네이버 블로그 iframe — 최상위 DOM만 읽으면 껍데기. 모바일 URL 치환 + se-module-text 파싱으로 우회.
  • 중복 저장, 로그인·페이월 뒤 미수집
  • Safari·iOS Safari share_target 미지원 — WebKit 입장 neutral(2019년 버그), Firefox 미구현. Chrome Android만 지원.

D-3docvault에 넣는다면

캡처 경로 보강 → PDF 하이라이트 → 이미지 OCR → Excalidraw·DOCX/HWPX 가져오기 → EPUB 순이 증거가 가리키는 순서입니다.

  1. 토큰 인증 캡처 엔드포인트(URL 또는 HTML 본문) + iOS 단축어 배포
    기존 PWA share-target 라우트를 같은 서비스 함수로. 카카오톡 → 공유 시트 → 단축어 → docvault 흐름을 온보딩에 문서화. Linkwarden·Obsidian 모바일 1.11.0 선례.
    난이도 하비용 0
  2. 서버 추출기: Defuddle + linkedom → Markdown
    사이트 규칙 테이블(네이버 모바일 URL 치환), URL 정규화 해시로 중복 감지, 실패 시 사용자 선택 텍스트 폴백, 추출 텍스트를 FTS·RAG 인덱스에 즉시 반영. 원본 보존은 기본 꺼짐 + 용량 쿼터.
    난이도 중비용 0 (linkedom 약 100 MB 실측)
  3. 사용자별 수신 메일 주소 → 같은 캡처 서비스
    뉴스레터 구독도 같은 파이프라인. 뉴스 브리핑의 RSS와 합류 가능.
    난이도 하Mailgun Free 100통/일 또는 SES USD 0.10/1,000통
  4. PDF 하이라이트(DB 저장) → Markdown 노트·학습 카드 추출
    pdf_highlights 테이블에 W3C 선택자 + 정규화 좌표 + 색 + 메모. 현 뷰어가 pdf.js면 react-pdf-highlighter 패턴, 교체 가능하면 EmbedPDF(MIT). PDF는 불변 원본으로 두어 20버전 정책과 정합.
    난이도 중상비용 0
  5. 이미지 업로드: HEIC → 서버 JPEG/WebP 변환, 썸네일, OCR 텍스트를 검색·Q&A에 포함
    Safari 17+만 HEIC 네이티브 표시. 손글씨·화이트보드는 멀티모달 LLM으로 "요약+텍스트화".
    난이도 중Upstage OCR USD 0.0015/쪽 · Google Vision USD 1.50/1,000쪽
  6. .excalidraw JSON을 텍스트 형식으로 추가 + Excalidraw 뷰어/에디터
    텍스트 저장 경로·버전 관리 재사용, SVG 내보내기를 Markdown에 삽입. MIT, 135k 스타.
    난이도 하비용 0
  7. DOCX(mammoth.js)·HWPX(python-hwpx/hwpforge) 가져오기 → Markdown/HTML + 원본 첨부
    양방향 편집(다시 DOCX로)은 보류. HWP5는 여전히 장벽.
    난이도 중비용 0
  8. EPUB 뷰어(foliate-js, iframe 샌드박스 + CSP 필수)
    리더 모드·이어읽기 연장. "deny by default" 원칙과 부합.
    난이도 중비용 0
  9. Telegram 봇 수신(서버 웹훅)
    Obsidian 플러그인의 "데스크톱 켜져 있어야 함" 한계 없음. 카카오톡 봇은 공식 수신 경로 불명.
    난이도 하비용 0

Claude에 PDF를 매번 통째로 넘기면 쪽당 1,500~3,000 텍스트 토큰 + 이미지 토큰이 들므로, 업로드 시 1회 추출(디지털 PDF는 pdftotext 무료, 스캔본만 OCR)로 비용을 고정합니다.

피할 것

  • tldraw — SDK 4.0(2025-09)부터 프로덕션에 라이선스 키 필수, 상업 가격 비공개, 서버 핑.
  • PDF.js로 주석을 PDF에 굽기 — 주석별 API가 없고 버전 폭증을 부릅니다.
  • Nutrient/PSPDFKit — 웹 전용 연 USD 10,000~15,000부터, 구매 중앙값 USD 31,000(제3자).
  • 손글씨 전용 캔버스 자체 구현 — GoodNotes가 네이티브로 수년간 다듬은 영역.
  • 기본 켜짐 전체 페이지 아카이브, Tesseract 단독 한국어 OCR, 카카오톡 봇 수신에 의존한 설계, 호출 없어도 유지비가 나가는 CLOVA OCR 플랜.

로드맵 제안

1단계는 외부 비용이 거의 0인 네 가지로 "제품처럼 보이는" 수준을 만들고, 2단계에서 음성과 PDF로 폭을 넓히며, 3단계는 사용 로그를 보고 고릅니다.

1단계

핵심 격차 메우기

  • 하이브리드 RAG + 인용 Q&A
  • [[위키링크]] + 백링크 + rename 전파
  • 캡처 엔드포인트 + iOS 단축어 + 서버 URL 추출
  • Markdown 일괄 내보내기 + AI 옵트인·전송 로그

"내 자료만 근거로 출처를 달아 답하고, 문서끼리 이어지고, iPhone에서 한 번에 저장되는" 시연 가능한 제품. 셀프호스팅 경쟁 체크리스트의 약점(이식성·AI 투명성) 해소.

선행 조건: 설계 문서(ERD의 file_links·chunks 테이블, API 명세의 캡처 ID) 먼저 갱신. 임베딩 공급자 선택(Voyage 무료 또는 OpenAI small). STT는 아직 불필요.

2단계

폭 넓히기

  • 음성 파일 가져오기 → STT 어댑터 → 전사 문서 + 용어집 + 요약·카드 초안
  • PDF 하이라이트(DB) → 노트·카드
  • 연관 문서 추천 + 로컬 그래프
  • 수신 메일 주소 + 프롬프트 캐싱·모델 라우팅

클로바노트 개인 사용자의 "유료로 못 늘리는 한도" 공백 공략, 학습 카드 루프 완성, AI 비용 구조 안정.

선행 조건: 결정 2(녹음을 외부 STT로 보내도 되는가)와 결정 3(정확도 vs 비용). PDF 뷰어 라이브러리 결정(pdf.js 유지 vs EmbedPDF).

3단계

사용 로그 보고 선택 (4개 이하)

  • 후보: unlinked mentions, 이미지 OCR, 자동 태그 제안, 읽어주기, Excalidraw, DOCX/HWPX, EPUB, 짧은 음성 메모

업로드되는 형식·질문 패턴·캡처 채널 실측값에 맞춰 고릅니다.

선행 조건: 1·2단계 배포 후 관리자 대시보드에 형식별 업로드 수·캡처 채널별 건수·AI 기능별 호출 수 지표 추가.

모든 단계는 프로젝트 규칙대로 설계 문서를 먼저 고치고, 표를 새로 만들면 ERD의 엔티티 블록과 관계 설명을 함께 갱신하며, 사용자에게 보이는 변경은 CHANGELOG.md에 기록합니다.

사용자가 정해야 할 것

아래 다섯 가지는 시장 자료로 답할 수 없고 소유자가 정해야 하며, 특히 2번과 3번은 2단계 착수 전에 필요합니다.

기존 기능 세 가지(내 자료 참고 · 공유 라우트 · 학습 카드 그래프)를 승격하는 것만으로 1단계가 성립하고, 음성은 "녹음 앱"이 아니라 "녹음을 문서로 바꾸는 곳"으로 정의할 때만 1인 운영 범위에 들어옵니다.

docvault가 서 있는 자리는 비어 있는 칸개인용 로컬 퍼스트(Obsidian)와 기업 위키(Notion·Outline) 사이에서 "가볍게 셀프호스팅되고, 관리자가 소수 계정을 발급하며, AI Q&A가 내장된 소그룹 문서함"을 하나의 제품으로 내놓은 곳은 없습니다. 가장 가까운 대안이 두 제품을 따로 운영하는 것이라는 사실 자체가 포지셔닝 문장이 됩니다.
먼저 할 일은 새 방향이 아니라 기존 기능의 승격"내 자료 참고"에 임베딩과 인용을 붙이고, 문서에 [[링크]]를 붙이고, 이미 있는 share-target 라우트를 iPhone에서도 닿게 하는 세 가지는 외부 비용이 거의 0이고 설계 상수와 백업 단위를 건드리지 않습니다.
음성은 하되 순서와 경계를 지킨다클로바노트가 개인 유료를 열지 않아 생긴 공백은 실재하지만, iOS 26 PWA의 녹음 버그와 1 GB VM의 한계 때문에 "녹음 파일을 문서로 바꿔 보관·검색·질문하는 곳"으로 정의해야 합니다.
다음 행동결정 2(외부 API 전송 정책)를 정한 뒤 1단계 네 가지의 설계 문서(ERD·API 명세)를 갱신하는 것입니다.
